# PRD · v0.17 · 保险账户(储蓄/理财型)· issue #6

> 关联 GitHub [issue #6](https://github.com/LuoDi-Nate/financial-management/issues/6)(用户 BetterQx)。新增**保险**账户类型,把**有现金价值的储蓄/理财型保险**(年金险 / 增额终身寿 / 万能险 / 分红险)纳入家庭资产大盘。**坚持原有账户理念**:保险账户 = 又一类「按周期手填当前价值」的资产账户,复用既有估值/净资产/配置链,**不引入预算引擎、不做逐笔、不替 LLM 算保单收益**。

## 1. 背景与动机

- issue #6:现有账户偏现金 / 股票等高流动性资产,而家庭里**保险**占了很大一块资金往来,资产大盘不完整。
- 保险的特殊性(issue 已点明,与我们之前调研一致):
  - **消费型保险**(车险 / 医疗险 / 定期寿等):纯支出,**无现金价值**,不构成资产。
  - **储蓄 / 理财型保险**(年金险、增额终身寿、万能险、分红险):有**现金价值(cash value)**,是一笔可累积、可退保变现的**长期资产**。
- 用户诉求:在账户类型里加「保险」分类,让储蓄型保险的**现金价值计入总资产**,并能登记保费 / 缴费周期等信息。

## 2. 我们之前对保险的调研结论(设计前提)

| 维度 | 结论 | 对本设计的含义 |
|---|---|---|
| 消费型(车/医疗/定期寿) | 纯支出、无现金价值 | **不建资产账户**(建了也没有余额可填,违背"账户=资产/负债容器") |
| 储蓄/理财型(年金/增额寿/万能/分红) | 有现金价值、长期资产 | **建资产账户**,现金价值 = 手填余额,计入净资产 |
| 现金价值怎么来 | 保单每年有「现金价值表」或退保价值,保险 App / 保单可查 | **用户手填**(和 WEALTH 理财 / PROPERTY 房产同一套手填估值,不自动) |
| 保单"演示收益 / 预定利率" | 保险公司演示利率不可信、且是复杂精算 | **不做收益预测 / IRR 演算**(承 [[feedback_llm_no_math]]:数学不交给 LLM,不可信数字不进系统) |
| 保费缴纳 | 是一笔从现金流出的支出;早期年份现金价值 < 已交保费 | **不做"未来预算引擎"**;保费流出由每期余额变化 + 现有净流入机制自然体现,保费只作登记项 |

## 3. 坚持原有账户理念(本设计的红线)

我们的账户模型是:**一个账户 = 一类资产 / 负债的容器,按周期(月/周)填一次「当前价值」快照,并入净资产;10 分钟/月,不逐笔、不做预算预测**。保险账户必须落进这套理念,而不是另起炉灶:

1. **保险账户 = 手填价值的资产账户**,和 `WEALTH`(理财) / `PROPERTY`(房产) / `METAL`(贵金属手填量)同类:每期填「现金价值」,估值链、FX 折算、净资产、资产配置、报表全部**复用现有**,不新增估值范式。
2. **不引入预算 / 现金流预测引擎**。issue 里「自动生成未来的流出预算」超出我们模型 —— 我们不做前瞻预算。保费只作**登记信息**;真实流出在你每期把现金账户填低时被现有「净流入 / 流出」自然捕获。
3. **消费型保险不建账户**(无现金价值)。本版聚焦"补全资产拼图"这一核心诉求;消费型的保费到期提醒列入非目标(见 §6)。
4. **不替 LLM / 系统算保单收益**(承 [[feedback_llm_no_math]] + [[feedback_decision_weight_honesty]]:不可信数字不进系统)。
5. **面向用户命名友好**(承 [[feedback_user_friendly_naming]] + [[feedback_no_emoji]]):用「现金价值 / 保单 / 被保人 / 缴费」等家庭成员看得懂的词,不裸露枚举 code;图标一律 inline SVG。

## 4. 功能需求(FR · 用户视角)

### FR-17-1 · 建账户向导新增「保险」类型
- 「账户类型」里新增**保险**(第 9 类,`INSURANCE`),与现有 8 类并列。
- 选「保险」后,选**保险子类型**(下拉):`年金险 / 增额终身寿 / 万能险 / 分红险 / 投连险 / 其他储蓄型`。子类型是**展示 + 分组**用途,不改变估值逻辑。
- 提供 2–3 个**内置模板**(如「年金险 · 现金价值」「增额终身寿」),向导式一键建好,和现有 13 个模板同一体验。
- 建账户时对**消费型保险**给一句友好提示:「车险 / 医疗险 / 定期寿等**消费型保险是纯支出、没有现金价值**,不建议建成资产账户;这里请建**有现金价值的储蓄 / 理财型保险**。」

### FR-17-2 · 现金价值 = 每期手填余额,计入总资产
- 保险账户每期在「填报」里填**现金价值**(当前退保 / 账户价值),口径 = 手填余额,和 WEALTH/PROPERTY 完全一致。
- 该现金价值**计入家庭总资产 / 净资产 / 资产配置 / 报表**(与其它资产账户同源)。
- 支持币种 + FX 折算(复用现有)。**比值类指标币种无关**不受影响(承 [[feedback_currency_invariance]])。

### FR-17-3 · 保单登记字段(可选 · 纯展示,不做引擎)
账户详情可选登记(都可留空):
- **承保公司**、**保单号**
- **投保人 / 被保人**(可关联家庭成员或自填)
- **保额**(身故 / 满期保额)
- **保费 + 缴费周期**(如 12,000 元 / 年;周期:趸交 / 年缴 / 月缴)、**已缴期数 / 总期数**
- **生效日 / 满期(领取)日**
> 这些字段只在**详情页登记与展示**,用于"这张保单是什么"。**不生成预算、不预测、不参与净资产计算**(净资产只认现金价值)。

### FR-17-4 · 资产大盘把「保险」作为独立类目
- 资产配置(环形图 / 图例)、报表账户表里,**保险作为独立类目**呈现(不混进 WEALTH),让用户一眼看到"保险占家庭资产多少"。
- 中文类目名「保险」;数据标签(金额 / 占比)按既有规范直接浮在图上(承 [[feedback_chart_datalabels]])。

### FR-17-5 · 保费作为可选现金流备注(承接现有,不新建)
- 缴保费时,用户可像现有那样在填报里记一笔**支出 / 转账**(现金 → 保险,或纯支出),复用现有现金流。**系统不自动生成**。
- 早期年份"已交保费 > 现金价值"是正常的(保障成本),详情页可展示「已缴保费 vs 当前现金价值」两个**已登记数字的并列**(不算 IRR、不判好坏)。

### FR-17-6 · 加枚举全链扫(工程护栏)
- 新增 `INSURANCE` 账户类型 + `InsuranceSubType` 子类:**必须全链扫**模板串条件、写死计数分母、面向用户裸露 code(承 [[feedback_enum_add_sweep]]:v0.14 加 METAL 连踩三处上线才发现)。落 qa 守护网住整类。

## 5. 用户故事

- 「我买了份增额终身寿,现金价值 8 万,想让它进家庭总资产」→ 建保险账户(子类型=增额终身寿)→ 每期填现金价值 8 万 → 总资产 +8 万,资产配置里「保险」类目出现。
- 「我想记下这张保单每年缴 1.2 万、缴 10 年、被保人是孩子」→ 详情页登记保费/周期/被保人 → 展示,不影响净资产。
- 「车险要不要建?」→ 向导提示:消费型不建账户。

## 6. 非目标(明确不做 · 坚持理念)

1. **消费型保险不建资产账户**(车险 / 医疗 / 定期寿):无现金价值 = 纯支出。
2. **不做保费"未来流出预算 / 现金流预测"引擎**(issue 提到)—— 违背"快照非预算"理念;保费只作登记 + 现有现金流承载。
3. **不做保单收益预测 / IRR / 预定利率演算**(不可信 + LLM 禁数学)。
4. **不做消费型保险的保费到期提醒**(本版聚焦资产;若要,列 backlog,复用现有报表提醒机制,另开版本)。
5. 不接保险公司 API 自动拉现金价值(无稳定公开接口;手填,和其它手填账户一致)。
