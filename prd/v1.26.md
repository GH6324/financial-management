## 0 · 这一版在解决什么

### 0.1 背景与现状

「券商自动同步」从 v0.15 起支持**富途**与**老虎**两家,规矩写在 `prd/v0.15.md:5`:突破原来「不做券商 API 直连」的非目标,**但严格限定为只读(拉持仓 + 现金),永不下单**。

盈透(Interactive Brokers,下称 IBKR)不在其中。IBKR 账户的用户今天只能每月手抄持仓和各币种现金 —— 多币种、多市场,正是最费时间、最容易抄错的那一类账户。

**现有机制能直接复用的部分**(逐个读过代码):

| 环节 | 现状 | 在哪 |
|---|---|---|
| 只读客户端接口 | 只有读方法,没有任何下单 / 改单 / 解锁 | `service/broker/BrokerClient.java:14` |
| 同步与对账 | 只动 `sync_source` 标记的持仓,不碰手填;失败写回卡片 | `service/broker/BrokerSyncService.java:51` |
| 定时同步 | 工作日 16:45,管理页可改 | `DynamicScheduleConfig.java:63` / `:164` |
| 关联页 | 选券商 → 两步确认 → 替换接管 → 首次同步 | `templates/broker/link.html` |
| 凭据配置 | 管理 → 数据源接入 → 券商同步(老虎就在这里) | `templates/admin/integrations.html:122` |

**三处加券商就会漏的地方**(按「加枚举值要扫一遍」的纪律先查了):

- `templates/stock/holdings.html:57` 写死 `vendor == 'FUTU' ? '富途 Futu' : '老虎 Tiger'` —— 加第三家,IBKR 会被显示成「老虎」。
- `domain/ledger/LedgerSource.java:80` 的 `ofBroker` 带 `default -> UNKNOWN` —— IBKR 同步引起的估值变动会被记成「来源不明」,账户时间线上看不出是券商同步的。
- 数据库 `broker_link.vendor` 有 `CHECK (vendor IN ('FUTU','TIGER'))`(`V39`)—— 不改约束,IBKR 的关联根本存不进去。

### 0.2 服务谁

在 IBKR 开户的自建用户。提交者原话「目前大多数人应该某种原因都得用 ib 这种券商来进行交易了」—— 对大陆用户,IBKR 往往是唯一能买港美股的券商,而且常常是家里**资产最多、币种最杂**的那个账户。

### 0.3 主推动力

**IBKR 账户像富途、老虎一样:配一次,之后每月不用手抄。** 只读、只拉持仓和现金。

### 0.4 本版新引入的名词

| 名词 | 是什么 |
|---|---|
| **Flex 报表**(Flex Query) | IBKR 后台里用户自己定义的一份报表(选哪些栏目、什么格式),每份有一个**查询号**(Query ID) |
| **报表口令**(Flex Web Service Token) | IBKR 发的一串口令,**只能用来取 Flex 报表**。最长一年有效,重新生成会让旧的立即失效 |

用户可见文案里统一叫「报表口令」「查询号」,不出现 token / query id。

## 1 · 调研

**这一节是必须的**:外部平台接入。IBKR 与富途(常驻网关)、老虎(开发者 API + RSA 私钥)都不一样,它**没有面向个人的实时 API 需要常驻进程**,取数走「Flex Web Service」:用口令发一个请求,拿到一个回执号,稍等片刻再用回执号取报表。

### 1.1 接口事实(官方文档 + 我们从 beta 实测)

| 事实 | 来源 | 实测 |
|---|---|---|
| 两步取数:`SendRequest?t=口令&q=查询号&v=3` 返回回执号;`GetStatement?t=口令&q=回执号&v=3` 返回报表 XML | IBKR 文档 | 端点可达:beta 访问 `ndcdyn.interactivebrokers.com` **0.6 秒** |
| **失败也是 HTTP 200**,正文里 `<Status>Fail</Status>` + 错误码 | IBKR 文档 | ✅ 用假口令实测:HTTP 200,`ErrorCode 1015 · Token is invalid.` |
| **必须带 User-Agent 头** | IBKR 文档「requires the User-Agent HTTP header」 | ✅ 不带 → **HTTP 403 Access Denied** |
| 报表还没生成好时返回 `1019 · Statement generation in progress`,要等一会儿再取 | IBKR 文档错误码表 | 待真口令实测 |
| 限流:**每个口令每秒 1 次、每分钟 10 次**(超了返回 1018) | IBKR 文档错误码 1018 | — |
| 口令默认 **6 小时**过期,可选最长 **1 年**;可选绑定一个 IP;**重新生成会让旧口令立即失效** | IBKR 文档 + 第三方接入指南 | — |
| 口令过期返回 `1012 · Token has expired.` | IBKR 文档 | — |
| 报表是**日终数据**(上一个交易日收盘后生成),不是实时 | IBKR 文档 / 业界做法 | — |
| 持仓在 `OpenPositions/OpenPosition`:`symbol` `assetCategory`(STK / OPT / FUT / BOND …)`position`(股数,空头为负)`markPrice` `costBasisPrice` `currency` `listingExchange` | 开源解析库 + IBKR 报表参考 | 待真口令实测 |
| 现金在 `CashReport/CashReportCurrency`:每币种一行 `endingCash`,另有一行 `currency="BASE_SUMMARY"` 是**折成基础币种的合计** —— 不跳过就会把现金算两遍 | 开源解析库 | 待真口令实测 |
| 一个口令可以覆盖多个账户;报表里每个账户一个 `FlexStatement` | IBKR 文档 | 待真口令实测 |

### 1.2 别人怎么做

- **Portfolio Performance**(开源记账软件)、**TradesViz** 都用同一套 Flex Web Service 做 IBKR 自动导入;TradesViz 的接入说明专门提醒「请选 1 年有效期,否则要频繁重新连接」。
- 一个开源个人理财项目踩过的坑:**口令一年一到期,到期后每周的持仓快照静默停更**,他们的修法是把到期时间存下来,提前 5 / 2 / 1 天提醒。本 PRD 的 FR-756 就是照这个坑设计的。

### 1.3 调研留下的未知(TDD §零 的「待实测」)

- **prod 和大陆 Docker 用户能不能连上 IBKR**:beta 能连,prod 与大陆家庭宽带没测过(prod 操作只在发版流程内)。页面上的「测试连接」就是为这个留的,连不上要说人话。
- 真实报表的字段形状:需要一个真实 IBKR 账户的口令实测一次(维护者或提交者提供,只在 beta 测,不落库)。

## 4 · 不做什么

**非目标**:

- **不导入逐笔交易**。issue 里提到「交易数据」,但本项目颗粒度停在「账户 + 持仓」的月度快照(`AGENTS.md` 定位硬约束)。持仓里已经带了成本价,账户级收益照常算。回复里问了提交者要交易数据做什么用 —— 如果是「看成本 / 算收益」,现有能力已覆盖。
- **不同步期权 / 期货 / 债券 / 差价合约**。与富途、老虎一致(`BrokerTicker.isEquity`),本项目的持仓模型没有这些品种。
- **不做实时**。Flex 报表是日终数据;定时同步在工作日 16:45,月度快照完全够用。
- **不下单、不改单、不转账** —— 报表口令本身就做不到,不是靠我们自觉。
- **不做 IBKR 的其它 API**(Client Portal Web API / TWS API):都需要常驻登录会话或网关,和「配一次就不管」的目标相反。

**撞「刻意不做」清单?** 表面上撞了「券商 API 直连」—— 但那一条在 v0.15 已经被**只读**的例外打开过(`prd/v0.15.md:5`),富途、老虎都在这个例外里。IBKR 的报表口令比老虎的 RSA 私钥**更安全**:后者是能交易的密钥,前者只能取报表。**顺带要修的文档**:`AGENTS.md:19` 的清单一直没补这个例外,读起来像连只读同步也不做;本版把它改成「券商 API 直连**下单**」并注明只读例外。

## 6 · 存量影响

| 维度 | 这一版的影响 |
|---|---|
| **schema** | `broker_link.vendor` 的 CHECK 约束放宽到含 `'IBKR'`(`V39` 原约束只有 FUTU / TIGER)。列宽 `VARCHAR(8)` 够用,旧行不动 |

### 核心功能影响排查

**触发条件**:加了新的写入通道?—— **没有新通道,是现有通道多一个来源**。IBKR 同步走的就是 `BrokerSyncService.sync` → 对账 → 估值刷新这一条路,在 `prd/v1.23.md` §4 的矩阵里已经登记为 U17(手动同步)/ S4(定时同步),判据「**事件时点**」,属于 E 列(估值 / 股价 / 券商自动刷新)。本版不改这条路的任何语义,只是多一个 `BrokerClient` 实现。

**确定不受影响的边界**:没有关联 IBKR 的账户;富途、老虎的同步(共用同一个对账,但只动 `sync_source='IBKR'` 的行);填报、账期、报表、体检的口径。

## 8 · 隐私与数据红线

不涉及 LLM。涉及**我们主动调用的外部接口**:

- **只从本服务器发往 IBKR**,不经任何第三方;报表 XML 只在内存里解析,**不落盘、不进日志**(日志只记「几个账户 · 几笔持仓 · 几个币种」这类计数)。
- 报表口令按密钥处理:存在家庭配置里(与老虎私钥、大模型密钥同一种存法),页面不回显,审计日志只记「已配 / 未配」不记值。**注意**:现有管理页和图文教程写着「凭据加密保存」,实际这几类密钥在数据库里是明文 —— 这是 v0.15 起就有的说法与实现不符,单独报给维护者,本版没有改它,IBKR 的文案里不写「加密」。
- 口令**本身只能取报表**,即使泄露也不能交易;但报表里有账户号和全部持仓,仍按高敏感处理。页面上建议用户在 IBKR 后台把口令**绑定到本服务器的 IP**。
- 账号在页面上一律打码(`U•••4521`)。

## 9 · 失败模式(pre-mortem)

1. **口令一年一到期,到期后静默停更。** 这是别人实际踩过的坑。账户余额停在一年前某天,页面上看起来一切正常。
   **怎么发现**:FR-756 到期提醒 + FR-757 过期后卡片标红(沿用 v1.17.3「失败要落库、卡片切红」的机制);护栏守「1012 必须变成用户看得懂的一句话,不能被兜底文案盖住」。
2. **失败被当成数据读。** IBKR 的失败是 HTTP 200 + XML 里写 Fail,只看状态码会把一段错误 XML 当报表解析 —— 结果是「0 笔持仓」,对账把所有同步来的持仓**全部归档**,账户余额掉成 0。
   **怎么发现**:单测守「Status=Fail 必须抛错、不许进对账」;另加一道闸:**报表里一个账户都没解析出来时拒绝对账**(空报表不等于「全卖光了」)。
3. **现金算两遍。** `CashReport` 里除了每个币种,还有一行 `BASE_SUMMARY`(折成基础币种的合计)。不跳过它,现金就翻倍。
   **怎么发现**:单测用带 BASE_SUMMARY 的样例报表断言现金只算一次;beta 上拿真实报表对一次 IBKR 后台的现金数。
4. **多账户撞限流。** 一个口令关联三个账房账户,一轮同步取三次报表 × 每次「发请求 + 等 + 取」,很容易超过「每分钟 10 次」。
   **怎么发现**:FR-758 一轮只取一次;单测数请求次数。
