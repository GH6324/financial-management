## 0 · 这一版在解决什么

两件事看起来无关,其实是同一个毛病的两面:**系统知道的东西没告诉用户**。

### 0.1 券商同步坏了,页面上看不出来

v1.17.3 那次事故:生产上富途 OpenD 因为我引入的版本判据 bug 起不来,同步**断了两天**。这两天里:

- 券商接入页显示的是「上次同步:8-17 09:12 · 成功」—— 一条**两天前的成功消息**,看起来像刚同步过
- 账户列表页什么都没有
- 账户余额停在两天前,但页面上没有任何「这个数字可能过期了」的信号

失败路径当时只有一行 `log.warn`,`broker_link` 表压根没被写过。所以这不是「缺一个提醒」,是**一条过时的成功消息在冒充当前状态** —— 比没有消息更坏。

### 0.2 流水时间线分不清数据是谁写的

账户详情页的流水时间线把这些混在一起:

| 时间线上显示 | 实际可能是 |
|---|---|
| `= 校准 月末校准` | 用户在填报页敲的数 / 开账时系统延续上期余额 / 系统估值回写 / 接受贷款趋势预测 / 由一笔收支派生 |
| `△ 估值 估值变动 · 自动(定时)` | 定时拉股价 / 定时拉金价 / 定时拉币价 / 富途同步持仓 / 老虎同步持仓 / AI 截图导入 |
| `+ 收入 …` | 用户填的 / 系统联动派生的(股票现金行调整) |

`kind` 说的是「这是什么性质的变动」,说不清「它怎么进到系统里的」。已有的 `trigger_kind`(CRON / MANUAL / HOLDING_CHANGE / IMPORT)也只说「什么动作触发」—— 同一个 CRON 可能是股价接口也可能是金价接口。

结果:用户看到一笔估值变动,分不出是定时拉价、还是富途同步、还是自己截图导入的;而 0.1 那种「同步其实早就断了」的情况,时间线上也一样看不出来。

## 1 · FR

### FR-410 · 券商同步失败必须写进状态,不能只写日志

同步任一环节抛异常时,把**人话失败原因 + 时间**写进 `broker_link.last_status`,并且**不动 `last_synced_at`** —— 那一列的语义是「上次成功同步」,失败时改它会把失败伪装成成功。

失败原因要是用户能自己判断下一步的措辞,不是异常类名:

| 实际异常 | 写给用户的 |
|---|---|
| 连不上网关端口 | `同步失败 · 连不上 OpenD 网关`(08-19 11:06) |
| 凭据缺项 | `同步失败 · 券商连接未配置完整` |
| 读超时 | `同步失败 · 网关无响应(超时)` |
| 网关未登录 | `同步失败 · 网关未登录` |

### FR-411 · 失败提醒出现在账户列表页(维护者定:方案 B)

我给过三个位置,维护者选了 B:

| | 方案 | 为什么没选 |
|---|---|---|
| A | 首页横幅 | 首页是「10 分钟月度」的入口,横幅会和月度待办抢位置 |
| **B** | **账户列表页标记那个账户** | **选定** —— 失败是**某个账户**的属性,标在账户身上位置最对;点进去就是那个账户的券商页 |
| C | A + B 都做 | 维护者只要 B |

具体:`/accounts` 上那个账户的「券商托管」徽记旁边多一枚**红色可点标记**,点进 `/accounts/{id}/broker`,`title` 上挂完整失败原因。

> 为什么二级页不够:失败以前只在券商接入页可见,而那页没人天天点 —— 生产上断两天没人发现,就是这个原因。

### FR-412 · 每笔流水变动带来源标签

时间线每一行显示「这笔是谁写进来的」。全部可能的来源(草拟后定稿 10 个):

| tag | 显示 | 分组 / 配色 | 什么时候写 |
|---|---|---|---|
| `MANUAL` | 手动填报 | manual · 中性 | 填报页敲余额 / 登记收支 / 登记划转 / 填股数收入 |
| `SYNC_STOCK_API` | 自动 · 股价 | auto · 黄铜 | 定时拉股价后估值(A股/美股/港股) |
| `SYNC_METAL_API` | 自动 · 金价 | auto · 黄铜 | 定时拉贵金属价后估值 |
| `SYNC_CRYPTO_API` | 自动 · 币价 | auto · 黄铜 | 定时拉加密货币价后估值 |
| `SYNC_BROKER_FUTU` | 自动 · 富途 | broker · 石板蓝 | 富途 OpenD 同步持仓引起的变动 |
| `SYNC_BROKER_TIGER` | 自动 · 老虎 | broker · 石板蓝 | 老虎证券同步持仓引起的变动 |
| `IMPORT_SCREENSHOT` | 截图导入 | import · 森绿 | AI 解析持仓截图后引起的变动 |
| `CARRIED_FORWARD` | 开账延续 | system · 中性深 | 开账时系统代填上期末余额(没有人确认过这个数) |
| `SYSTEM_ADJUST` | 系统联动 | system · 中性深 | 股票现金行调整、接受贷款趋势预测等系统派生的行 |
| `UNKNOWN` | 来源未记录 | unknown · 虚线最淡 | v1.18 之前的历史数据 |

标签文案不许出现 `api` / `sync` / `cron` 这类技术词(既有原则:面向用户的命名避免技术词)—— 有单测钉住。

### FR-413 · 历史数据一律 UNKNOWN,不假装知道

维护者裁定:**回填 `UNKNOWN`**。

为什么不回填成 `MANUAL`:那等于假装我们知道。历史行里确实有一部分是自动同步来的,但 `cash_flow` / `transfer` / `period_snapshot` 上没有任何依据可推断,写 `MANUAL` 会让统计得出「过去全是手填」的错误结论。`UNKNOWN` 是诚实的:来源当时没记。

`UNKNOWN` 在语义上**不等于** `MANUAL`,也不算「自动」—— 有单测钉住这条边界。

### FR-414 · UNKNOWN 不能刷屏

历史行占绝大多数(beta 实测:5164 行全是 UNKNOWN)。所以 `UNKNOWN` 这一枚必须是**最不抢视线**的样式:虚线边 + 透明底 + 最淡的字,鼠标悬停才解释「这一笔早于 v1.18,当时还没有记录来源」。

## 2 · 不做什么

- **不按来源做筛选器**:时间线已经有类型 / 时间范围两个筛选,再加一个会把这页做成查询工具 —— 与「10 分钟月度」的定位冲突。维护者没要。
- **不回填历史**(见 FR-413)。
- **不做失败告警推送**(微信 / 邮件):这一版只解决「页面上看不出来」。推送是另一个题目,涉及节奏与免打扰,不顺带做。
- **不动 `trigger_kind`**:它和来源是两个维度,都保留。

## 3 · v1.18.6 追加 · 对账页是「提示」,不是「判决书」

### FR-415 · 每条疑似都要给出「到期末是否还缺着」

**起因**:我拿 v1.18.2 那个扫描器的输出,断言维护者的某个账户「多算了 12.5w、要扣掉」。
维护者回:「这个账户和我真实持仓是对得上的,你为什么判断我要扣 12.5w?」—— **他是对的,我错了**。

判据只看**某一个瞬间**(某次估值的 Δ 恰好抵消了刚进出的钱),看不出「后来是不是已经被纠正了」。
那一格的真相是:用户转账后立刻又重导了一次持仓截图(导入如实还原了转账前的持仓、于是相消),
而 8 天后的又一次导入已经把账做平。**照着报告去补,就是凭空删掉 12.5 万。**

所以每条疑似必须同时给出**整期视角**:

- `本期余额变化`(期末 − 期初)与 `隐含损益`(余额变化 − 净流水)摆在同一行
- 判定分两级:
  - **期末仍对不上** —— 这一期的隐含损益正好还背着这个缺口,钱到期末还没回来(真要动手)
  - **需人工核对** —— 期末余额后来被改动过,可能已经纠正,先去持仓页核对再决定

### FR-416 · 页面不许写成「照此补回」

对账页的定位是**把可疑的地方指出来给人看,不是替人做决定**。
文案一律「疑似 · 请核对」,并明说判据的局限(只看瞬间、看不见后续纠正)。
两个视角都可能出错 —— 整期视角的盲区是「当期真实涨跌恰好等于缺口」,概率极低但不为零。

### FR-417 · 补回之后,同一条痕迹自动降级

**不做**人手打的「已处理」按钮:那个标记会和数据分家(补过之后又被抹一次,标记还挂着「已处理」),
而「同一件事两份判据」正是这一整个 bug 家族的形状。
钱一旦补回,期末余额跟上,残留自然远离 0 —— 这条痕迹**自己就降级了**,不需要谁去点。

### FR-418 · 算不出来就说算不出来

账户建仓的第一期查不到期初,隐含损益**算不出来**。
那就显示 `—`,不许拿 0 冒充「算过了」—— 页面上看不出一个数是算出来的还是编出来的,
而这一页恰恰是用来做取舍决定的。
