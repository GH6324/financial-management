# PRD · v1.3 · 旭日下钻 · 可选分析指标

> **状态**:已实现 · beta 待验收(2026-07-22)· 交互 preview `preview/v1.3/sunburst-metrics.html`
> **一句话**:让旭日像交叉表一样,可以分析任意指标(不止「金额」)—— 金额 / 本期收益额 / 累计收益额 / 累计收益率,按任意维度下钻,直接呈现在旭日上。

## 0 · 背景与短板

资产透视的旭日下钻很有用,但有个大短板:**只能看「总金额」**。而右侧交叉透视表早就能按多指标(收益额 / 收益率)分析,旭日却没接上 —— 用户想「哪类资产这个月赚得多 / 亏得多」「哪块累计收益率最高」时,旭日帮不上。

本质:旭日与交叉表共用同一个后端(`POST /lens/query` + `PivotEngine`),PivotEngine **早已会算全部 5 个指标**,只是旭日的前端**只请求了 `value`(金额)**。补齐它 = 让旭日成为「可选指标」的分析器。

## 1 · FR(用户视角)

- **FR-1 · 分析指标选择器**:旭日卡头部加「分析指标」选择器,可选 **金额 / 本期收益额 / 累计收益额 / 累计收益率**;切换即重绘旭日 + 中心圆 + 切片排行。
- **FR-2 · 点中心圆换指标**:点旭日**中心圆** = 弹出指标菜单(也视为「想换个指标分析」)。
- **FR-3 · 任意维度下钻**:指标与维度正交 —— 任一指标都能按当前内/外环维度下钻、面包屑回退(不变)。
- **FR-4 · 诚实呈现**:金额类按弧长表达;比率类(收益率)不可按角度分 → 弧长仍=市值、指标画成颜色热力。见 §3。
- **FR-5 · 诚实降级**:行业 / 地域(持仓级)维度下,账户级收益(本期收益额 / 累计收益率)不可精确归因 → 对应指标**灰置 + 提示**;累计收益额改用持有口径(市值−成本)仍可看(承 PivotEngine 既有规则,绝不假分摊)。
- **FR-6 · 切片排行跟随**:右侧「切片排行」按当前所选指标排序 / 着色。

## 2 · 交互

- 指标选择器:旭日卡头一排 pills(金额高亮 = 默认)。
- 中心圆:平时显示当前指标的总计(合计 ¥X / 净收益 ±¥X / 整体 +X.X%)+「▾ 点我换指标」;点击弹出指标菜单浮层(浮在中心)。
- 切内/外环维度不变;切到持仓级维度且当前指标不可归因 → 自动回退到「累计收益额」并提示。

## 3 · 指标 × 旭日呈现矩阵(核心设计)

旭日本质是**部分-整体(可加)**图。可加金额类天然合适;**比率类不可加**(父级收益率 ≠ 子级之和),不能按角度分 → 用颜色表达。

| 指标 | 可加 | 弧长 | 颜色 | 中心圆 | 行业/地域降级 |
|---|---|---|---|---|---|
| **金额**(默认) | 是 | = 金额 | 维值配色(现状) | 合计 ¥X | 无影响 |
| **本期收益额** | 是(±) | = \|收益额\| | 绿赚 / 赭亏(深浅按幅度) | 本期净收益 ±¥X | 不可归因 → 灰置 |
| **累计收益额** | 是(±) | = \|收益额\| | 绿赚 / 赭亏 | 累计净收益 ±¥X | 持有口径仍可 |
| **累计收益率** | **否(比率)** | **= 市值**(不能按比率分角) | **颜色 = 收益率热力**(绿高 → 赭负) | 整体 +X.X% | 不可归因 → 灰置 |

**两种渲染模式**:
- **可加金额类**(金额 / 收益额):弧长 = 该指标本身;收益额取 \|值\|、正负用颜色(绿/赭)。父级 = 子级之和,层级自洽。
- **不可加比率类**(收益率):弧长仍 = 市值,把收益率画成**颜色热力**。一眼看出「这块又大又赚(深绿)/ 又大又亏(深赭)」。诚实,不假装能按比率分角。
- 占比(share)不单列:金额模式的弧角本身就是占比。

## 4 · 决策与备选(推荐已选,待拍板)

| 决策 | 备选 | 选定 | 理由 |
|---|---|---|---|
| 指标集 | 4 指标 / 也放占比 | **金额+本期收益额+累计收益额+累计收益率** | 占比=金额弧角,不重复;这 4 个交叉表已支持 |
| 收益率呈现 | 弧长=市值+色热力 / 收益率不进旭日 | **弧长=市值,色=收益率热力** | 保留旭日价值(还能看结构),又诚实表达比率;比"禁用"信息量大 |
| 中心圆点击 | 弹指标菜单 / 盲切下一个 | **弹指标菜单** | 明确、可选目标;盲切易误触 |
| 持仓级降级 | 灰置+提示 / 假分摊 / 自动回退 | **灰置+提示 + 自动回退到累计收益额** | 承 PivotEngine 诚实降级;绝不假分摊 |
| 切片排行 | 跟随指标 / 恒按金额 | **跟随所选指标** | 与旭日一致,信息连贯 |

## 5 · 工程量(为什么这是"高价值低成本")

- **后端 ~零改动**:`/lens/query` 是唯一分析端点,`PivotEngine` 已算全部 5 指标。旭日现用 `rows=[内,外] measures=[value]`;改为 `rows=[内] cols=[外] measures=[所选指标]` → 用 `result.rowTotals` 拿**父级(内环)正确聚合**、`cells` 拿子级 —— 比率类的父级聚合由 PivotEngine 正确计算(不是前端求和,那对比率是错的)。
- **前端**(`lens.js` + `lens/_section.html`):指标选择器 + 中心圆点击浮层 + 两种渲染模式(弧长/颜色/标签/中心圆)+ 降级灰置 + 排行跟随。旭日引线标签(renderLeaders)复用,按指标改标签内容。
- **一致性**:交叉表 / AI 洞察已用这些指标,概念统一。

## 6 · 非目标

- 不新增指标口径(沿用 PivotEngine 既有 5 个;要加新指标仍只在 `LensRegistry` 登记一处)。
- 不做收益率的"假分摊到持仓"(诚实降级铁律)。
- 不改交叉表 / 明细 / 看板(它们已支持多指标)。

## 7 · 落地面(评审通过后进 tech-design + 编码)

`lens.js`(renderSunburst 改 query spec + 两种渲染模式 + 中心圆浮层 + renderRank 跟随 + renderLeaders 标签)· `lens/_section.html`(指标选择器 + 中心圆可点)· 看板 spec 存所选 sunMetric(自定义看板记住指标)· qa 守护(断言旭日 query 带 measures、比率类弧长=市值、降级灰置)· e2e(切指标后旭日数据随之变、持仓级维度灰置)。
