# v1.16 · 「本期填报完成」只留一个定义

> 状态:**方向已定 · 实现中**(2026-08-17 · 维护者在三个方向里选了 **B:以「有数字」为准**)
> 目标版本:`app.version = 1.16.0`(已 bump)
> 来源:[GitHub issue #15](https://github.com/LuoDi-Nate/financial-management/issues/15)「填报按钮旁边的数字,和预期不一致」
> 前置:v0.1 的 `snapshot_todo` 骨架 · v0.11.2 的开账自动延续 · v0.17.x 的贷款趋势提示条

---

## 0 · 这一版在解决什么

一个账户、已经填完、没有收支,填报 tab 右边却挂着一个红色的 `·1`。

复现路径查下来,原因不是算错,是**「完成」这个词在系统里同时有三个定义,而且互不联动**:

| 谁在用 | 它认为「完成」是 | 于是 |
|---|---|---|
| 填报页每行的 ✓ | 这个账户**有数字** | 开账时系统延续的余额也算 ✓ |
| tab 徽标 / 自动关账 | 这个账户**被人确认过**(`snapshot_todo.status='DONE'`) | 只有真提交过才清零 |
| 「我已记账完毕」按钮 | 这个**成员**声明自己弄完了 | 不影响上面两个 |

页面用第一种、徽标用第二种,所以页面说「都填好了」、徽标说「还有 1 个」。**两边都按自己的代码正确执行,合起来是错的。**

连带的第二个症状:自动关账的条件是「全员提交 **且** 未填数=0」,后半条永远不满足,
于是账期迟迟不关,而页面**不告诉你为什么没关** —— 用户只看到那个 1。

### 为什么选 B(维护者定)

摆在桌面上的是三个方向,差别不在实现难度,在**「按下开账那一刻,系统替你填的那个数,算不算数」**:

| | 口径 | 代价 |
|---|---|---|
| A | 徽标改成数「没有数字的账户」(改读取侧) | 徽标对了,但 `snapshot_todo.status` 这张表从此没人信,自动关账还得再挑一个口径 |
| **B(选定)** | **开账代填即视为完成**,三处口径统一到「有数字」 | 「有数字」和「人看过」这个区分被收窄,只在需要的地方(贷款)单独保留 |
| C | 页面 ✓ 改成只认人工确认(倒过来对齐) | 每期开账后所有账户重新变回「未填」,与「10 分钟月度」的产品硬约束正面冲突 |

C 违背产品定位 —— 这个 app 的核心承诺就是**大多数账户月月不动、系统替你延续、你只改动了的那几个**;
把它们统统打回「未填」等于每月凭空造出十几个待办。A 是把矛盾藏起来而不是解决。
**B 是唯一让三处口径真正合一的选择。**

## 1 · FR 清单

### FR-390 · 开账代填的账户,一开始就算「已填」

**要求**:`PeriodOpener` 在开账时把上期末余额延续成本期快照的同时,把这一行 `snapshot_todo` 一并标成 `DONE`。

**边界**(必须逐条成立):

| 情形 | 期望 |
|---|---|
| 账户有历史余额 → 系统延续 | todo = `DONE`,徽标不计它 |
| 账户**没有**历史(首期 / 新建账户的第一期) | todo 保持 `PENDING`,徽标计它 —— 这时候确实没数字,该催 |
| 同一账期重复开账(幂等重跑) | 已存在的 todo 一律不动,不覆盖任何人工状态 |
| 用户后来手动改了余额 | 走原有提交路径,`DONE` + 记名到人,与今天一致 |

**连带效果(是要的,不是副作用)**:自动关账的两个条件里,「未填数=0」在正常家庭会在开账瞬间就满足,
于是**账期能否自动关账,回到只看「全员是否点了『我已记账完毕』」** —— 那本来就是人给出的那句「我弄完了」。

### FR-391 · 已经在飞的账期要一起对上

**要求**:升级后**不必等到下个月开账**才看到正确的数字。当前仍 `OPEN` 的账期里,
凡是「已经有本期快照、todo 却还是 `PENDING`」的行,一次性对齐成 `DONE`。

**红线**:

- **只动 `OPEN` 的账期**。已关账的历史一行不改 —— 关账那一刻的事实就该保持原样(v1.10 的封板承诺)。
- **只改状态,不碰任何金额**。这次对齐不写、不改、不删任何一条 `period_snapshot` / `cash_flow` / `transfer`。
- 回填后徽标应当立刻归零(前提是这些账户确实都有数字)。

### FR-392 · 贷款那条趋势提示不能被顺手关掉

v0.17.x 立过一条规矩:贷款**不静默外推**,系统算出的「按上两期趋势,这个月大概是 X」必须以
填报页行内提示条的形式让用户**显式**选「接受 / 保持上月」。

这条提示条今天的出现条件里有一条是「这行 todo 还没 DONE」。FR-390 一改,
**所有贷款账户在开账瞬间就 DONE,提示条会当场消失** —— 一个用户可感知的能力被这次口径统一顺手删掉。

**要求**:提示条的出现条件改为看「**有没有人确认过**」,而不是看 todo 的状态。
系统代填出来的 `DONE` 不算「人确认过」;用户点了「接受」或「保持上月」之后才算,之后提示条才消失。

也就是说:**「有数字」和「人看过」这个区分不是被删掉了,是被收窄到唯一真正需要它的地方。**

## 2 · 不做什么

- **不改填报页每行的 ✓ 判定**。它本来就是对的,这一版是让另外两处向它靠。
- **不给徽标加第二个数字**(比如「已填 8 · 待确认 3」)。那是把三个定义变成四个,
  而 issue #15 的抱怨恰恰是「数字之间对不上」。
- **不动「我已记账完毕」的语义**。它声明的是**人**的状态,不是账户的状态,这两件事本来就该分开。
- **不做账期未关账原因的解释性提示**。它确实缺(见 §0),但那是独立的一条改进,
  而且 FR-390 落地后「因为还有账户没填所以关不掉」这个情形本身就基本不出现了。

## 3 · 验收

1. 单账户家庭、开账后什么都不做 → 填报 tab 无徽标,填报页该账户显示 ✓。
2. 全员点「我已记账完毕」→ 账期自动关账(不再卡在「还有 1 个未填」)。
3. 首期 / 无历史账户 → 徽标照常提示,不被误清。
4. 贷款账户开账后 → 趋势提示条**照常出现**;点「保持上月」后消失,再刷新不复现。
5. 升级到本版后,当前在飞账期的徽标立刻归零(FR-391),已关账月份的报表数字一分不变。
