# PRD · v1.2 · 月度归因复盘 + 再平衡执行闭环 + 性能底盘

> **一句话**:每月关账后自动回答「这个月钱为什么变了、怪谁」(A 归因复盘);
> AI 调仓建议从"一段话"升级为**可跟踪核销的再平衡计划**(D 执行闭环 · 只在自家账户间调结构,不荐任何产品);
> 同时把 dashboard 首屏 TTFB 从 ~1.2s 压下来(F 性能底盘)。
> 状态:**已实现(2026-07-20)· beta 待验收**。实现修订:①归因维度不含「行业」(持仓账户账户级行业恒空,账户级归因下全落未分类会误导;行业收益看 v1.1 透视持有口径);②瀑布主链用账户级 pnlBase 保证严格闭合,汇率重估以合计脚注呈现于贡献榜(不入主链防重复计入)。

## 0. 方向盘点(产品经理视角 · 为什么是它)

回顾使命:每月 10 分钟 → 一张全局图 → **算得清真实收益、分得清人赚的和钱赚的** → AI 只解读不荐产品。
v1.1 完成了「**看清结构**」(资产透视:钱现在长什么样);结构之后用户的下一个自然问题是「**看清变化**」(钱这个月为什么变成这样)。候选方向盘点:

| 方向 | 用户价值 | 与使命契合 | 工程成本 | 判断 |
|---|---|---|---|---|
| **A. 月度归因复盘**(本 PRD) | 每月必看:涨跌到底怪谁 · 「钱赚的」拆到账户/资产类型/汇率 | ★★★ 使命第二支柱的纵深;与"每月 10 分钟"节奏天然绑定,是每月回访的理由 | 中(底座全现成:账户级本期损益 + lens 维度标签 + AI 信号框架) | **选定** |
| B. 情景压力测试(股市 -30% 会怎样) | 教育意义强,但一年看两次 | ★★ 偏"预测"边缘,须小心红线 | 中 | 留 v1.3+ |
| C. 收益维度透视深化 | 各维度收益率对比 | ★★ XIRR 跨账户聚合=假精确,已定性不做;持有口径已在 v1.1 落地 | 低 | 边际小,不立项 |
| D. 再平衡执行闭环 | 建议→划转计划→跟踪 | ★★(2026-07-20 用户拍板**做**;红线解法见 §6:闭环建在站内划转记账上,只调结构不荐产品) | 中 | **本版做** |
| E. 年度报告(story 式年终总结) | 强但季节性 | ★★ | 低-中 | 做完 A 后顺产(A 的归因引擎按年聚合即是年报骨架) |
| F. dashboard TTFB 1.2s 拆分 | 工程质量 | — | 中 | **本版做**(2026-07-20 拍板 · §7 NFR) |

**拍板依据**:v1.1 PRD 非目标已明确「变化归因留 v1.2」;A 是三支柱中「收益统计计算」的最后一块大拼图,且直接消费 v1.1 打标资产——打标越全归因越好看,两个版本互相成就。

## 1. 用户故事(真实的每月一问)

- 「这个月净资产 -3 万,**是我花多了还是市场亏的?**」→ 人赚 +6 万、钱赚 -9.2 万:是市场。
- 「钱赚 -9.2 万,**亏在哪?**」→ 富途账户 -8.6 万(贡献 93%)、A 股 -1.1 万,余额宝 +0.3 万在苦苦支撑。
- 「按资产类型看呢?」→ 股票股权 -9.7 万、货币基金/存款 +0.4 万、房产 0(本月未重估)。
- 「美元跌了对我有影响吗?」→ 汇率重估 -0.8 万(USD 资产折本位币缩水),不是标的本身亏。
- 「AI 怎么看?」→ 「· 本月拖累主要来自富途账户的美股持仓(-8.6 万,占钱赚亏损 93%)…… · 值得做的一件事:……」

## 2. 功能需求(FR)

### FR-1 · 归因引擎(工程算数,恒等式闭合)
- **恒等式**:`ΔNW = 人赚(收入 − 支出) + 钱赚(投资损益) + 开账基线(新纳入存量) + 汇率重估`。
  - 汇率重估从「钱赚」中**拆出**:标的原币涨跌 ≠ 汇率折算涨跌,混在一起会误导(美股涨了但美元跌,用户该知道是两回事)。
  - 每一层可再下钻:**钱赚 → 按账户**(必有,精确)→ 按 lens 维度可切(资产类型 / 行业 / 成员 / 平台 / 币种,复用 v1.1 标签)。
  - 口径诚实:算不平的差额显示「未归因」,不吞不摊(承 v1.1 归因降级原则)。
- 数据源全现成:factview 账户级 `latestPnl` / 期间收支 / 开账基线已有;lens 标签就地可用。**不新增落库**,实时算 + 短缓存。

### FR-2 · 复盘视图(dashboard「本期怎么变的」卡原地升级)
- **瀑布图**(主视图):期初净资产 → +人赚 → −支出细分?(不,人赚一根) → ±钱赚各块(TopN 账户/或当前维度切片)→ ±汇率 → 期末。晚清账册配色,正绿负赭。
- **贡献榜**:两列「赚得最多 / 亏得最多」TopN 账户(金额 + 占钱赚比重),点击直达账户详情。
- **维度切换**:chips(账户 / 资产类型 / 行业 / 成员 / 平台 / 币种)——瀑布与贡献榜联动重切。
- 现有三段拆解条(人赚/钱赚/开账基线)保留为总览层,下方展开归因区;移动一等公民(瀑布横滑或改横条)。

### FR-3 · AI 月度复盘(信号驱动 · 复用 v1.1.x 洞察框架)
- 工程先判信号:最大拖累块(占钱赚亏损 ≥50%)、汇率吃掉超 X%、连续 N 月同一账户拖累、人赚为负(入不敷出)、钱赚回撤但未分类占比高(看不清)。
- LLM 只解读 + 一条最优先行动;真名脱敏;follow 管理页主选 vendor;按期缓存(账期关账后结果不变,可长缓存)。

### FR-4 · 跨期视角(小切口)
- 近 12 期「钱赚」堆叠柱(按当前维度着色)——一眼看出哪类资产长期在贡献/拖累。
- 任意两期对比 v1.3 再说(本版只做 单期归因 + 12 期趋势)。

### FR-5 · 入口与月报融合
- dashboard「本期怎么变的」卡内原地展开(不新开 tab,承 v1.1 教训);
- 报表页月报(已有)引用同一归因结果,AI 复盘文本并入月报 AI 洞察区,不做两套。

## 3. 非目标(明确不做)
1. 不做持仓级归因(账户级已足够回答"怪谁";持仓级在行业维持有口径下已有近似)。
2. 不做跨账户 XIRR 聚合、不做任何"如果当初"式反事实(假精确)。
3. 不做预测 / 情景模拟(留 v1.3 议题)。
4. 不新增 DB 表(纯派生计算;若 AI 复盘缓存需要落库,只加一张轻量缓存表,评审时定)。

## 6. 主题 D · 再平衡执行闭环(FR-6~9)

**红线解法(为什么现在可以做)**:此前判"不做"的两个障碍——①贴近荐产品:解法是计划条目**只到自家账户/资产类型层**(「从 华泰-A股 调 ¥50,000 到 招行-稳健理财」),永不出现具体产品/标的;②执行在外部闭环断:解法是**闭环建在记账动作上**——用户在券商/银行实际操作后,回填报页做站内划转,系统自动与计划核销。执行的"真值"就是账本,和本产品哲学一致(余额驱动)。

### FR-6 · 建议 → 计划(一键采纳)
- 现有 AI 调仓建议(v0.4 `rebalance advise`,已输出「从 X 调 ¥N 到 Y」结构化步骤)增加**「采纳为计划」**:勾选若干条 → 生成本期再平衡计划(可改金额/删条目)。
- 手动加条目:不依赖 AI,用户可自建「从账户A → 账户B ¥N + 备注」。
- 计划落库(轻表 rebalance_plan + item);一个账期至多一个活动计划(避免多计划打架)。

### FR-7 · 划转自动核销
- 填报页发生**账户间划转**时,若命中计划条目(同 from/to 账户 · 金额 ≥ 条目 80% 视为达成,可配),自动标记该条目「已执行」并回链划转流水;
- 不强约束:划转不必先有计划;计划条目也可手动勾「已在外部完成」(信任用户,但标注「未经划转核销」)。

### FR-8 · 计划进度视图
- 体检页(AI 调仓建议区)+ dashboard 洞察条:活动计划进度(3/5 条 · 已调 ¥N / 目标 ¥M);逾期账期自动关闭并归档(可回看)。
- 完成后下一次 AI 诊断把「计划执行率」作为输入信号(执行了建议 → 复查配置是否改善,形成闭环叙事)。

### FR-9 · 边界(铁律)
- 永不推荐具体产品/标的/时点;计划条目仅账户与金额;
- LLM 只解读计划进度,不生成新的买卖指令;
- 划转核销纯本地规则匹配,不涉 LLM。

## 7. 主题 F · 性能底盘(NFR)

- **目标**:dashboard 首屏(未含懒加载区)服务端耗时 P50 ≤ 400ms、P95 ≤ 800ms(现状 populateModel ~1.2s 串行全算)。
- **手段(TDD 定案)**:①populateModel 拆分——首屏 KPI 必算,趋势/分布/洞察改 HTMX 懒加载片段或并行化;②FactSlice 装配复用(一次 load 多消费,消灭重复 load);③归因/透视共用同一份头寸缓存(v1.1.1 SWR 已有,归因接入);④慢点埋点日志(阶段耗时打印,防回归)。
- **验收**:beta 实测 curl TTFB 前后对比入 qa-cases;不改变任何数值口径。
