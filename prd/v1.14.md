## 0 · 这一版在解决什么

issue #11 提的是「AI 截图导入资产,支持拖拽图片上传,可以只在 PC 端」。

查下来发现**比一条新功能更值得做** —— 现在那个上传区**已经长得像拖拽区了,但它不接拖拽**。

`templates/holdingimport/import.html:63`:

```html
<div id="dropZone" class="border-2 border-dashed border-rule ..." onclick="…click()">
```

- 元素 id 就叫 **`dropZone`**
- 视觉是 **2px 虚线框** —— 这在网页上几乎是「往这儿拖」的通用符号
- 但全仓库**搜不到任何 `dragover` / `drop` / `paste` 监听**(已确认)

于是 PC 上真把图片拖上去,浏览器走的是默认行为:**直接导航到那个图片文件,整个页面没了**。已经选好的图、正在进行的这次导入,全丢。

**所以这不只是「少了个便利功能」,是一个会让人丢东西的错误暗示。** 这一版把这个暗示兑现掉。

## 1 · FR 清单

### FR-370 · 拖拽到上传区即上传(PC)

把图片文件拖到 `#dropZone` 上松手 → 与「点击选择文件」**走完全相同的后续路径**:前端压缩(长边 2000 / JPEG 0.82)→ 逐张 POST `/entry/import/{id}/upload` → 缩略图 → 张数与预估花费更新。

**要求**:压缩、计价、并发上传计数、`scanBtn` 的启用条件,**一行都不复制** —— 现在这些逻辑写在 `fi.addEventListener('change', …)` 的回调里,要先抽成一个 `handleFiles(fileList)`,两个入口共用。两条路径出现行为差异是这类改动最典型的翻车方式。

**验收**:拖 3 张图 → 与「点击选 3 张」结果逐项一致(缩略图 3 个、`本次 3 张`、预估金额相同、`开始识别` 变可用)。

### FR-371 · 拖到区域外不许再把页面弄没

这是上面说的**真正的坑**,而且**它独立于拖拽功能本身存在** —— 即便用户不知道能拖,手滑拖歪一次也会丢掉当前页面。

**要求**:在 `window` 上拦掉 `dragover` / `drop` 的默认行为,拖到页面任何位置松手都**不导航**;只有落在拖拽区内才触发上传,落在别处静默忽略。

**验收**:把图片拖到页面页脚松手 → 页面纹丝不动,已上传的缩略图还在。

### FR-372 · 拖拽过程中的视觉反馈

进入拖拽区 → 边框与底色变化(用现有 `--brass-deep` / `--card-soft`,不引新色);离开或松手 → 复原。

**要求**:用 `dragenter` / `dragleave` 计数配对,不要只监听 `dragover`,否则拖过子元素时高亮会闪。文案在拖拽态下改成明确的「松手即上传」。

**不要 emoji**,需要图形用项目自带的 Feather-style inline SVG(memory `feedback_no_emoji`)。

### FR-373 · 非图片文件给出明确拒绝

拖进 PDF / Excel / 文件夹 → 不静默丢弃,在区域下方给一行提示说明只收图片(`image/*`),并列出被忽略的文件名。

**理由**:「截图导入」的用户完全可能拖一个对账单 PDF 进来。静默失败会让人以为系统坏了。

### FR-374 · 移动端不受影响

issue 里明说「可以只在 PC 端」。移动端**不加任何拖拽相关的提示文案**(手机上没有拖文件这个概念,加了只是噪音),但 FR-371 的兜底是全局的、无害的,照常生效。

**验收**:移动端截图导入页面**用户看得见的内容**从上到下与升级前逐字一致(提示文案由 JS 按指针能力注入,手机上那个元素渲染出来是空的;字符串本身仍在页内脚本里,这不影响用户看到什么)。

### FR-375 · Ctrl+V 粘贴截图即上传(PC)· 作者拍板加

在截图导入页任意位置按 Ctrl+V,若剪贴板里有图片 → 与拖拽、点选**走完全相同的后续路径**(同一个 `handleFiles`)。

**为什么值得加**:PC 上截图的真实动作链是「截图工具 → 图已经在剪贴板里」。拖拽还得先把图**存成文件**再拖,粘贴少这一步 —— 对「10 分钟录完一个月」这个硬约束来说,这是这一版里最省事的那条路径。

**要求**:
- 光标在输入框 / 文本域里时**不拦截**。这一页下方的比对表格有数值输入框,用户在那里粘数字不能被上传逻辑吃掉。
- 只认剪贴板里 `image/*` 的项;剪贴板里只有文字 → 什么都不做,正常粘贴。
- 粘贴上传的图沿用同一套压缩、计价、缩略图、`scanBtn` 启用条件。

**验收**:截图工具截完图直接 Ctrl+V → 缩略图出现、张数 +1、预估金额同步;在比对表格的数值框里 Ctrl+V 数字 → 正常粘贴,不触发上传。

## 2 · 非目标

- **不改**上传后的任何环节(识别、比对、确认入账)。这一版只动「文件怎么进来」。
- **不做**上传进度条 / 断点续传。单张压缩后约 300KB,没有这个必要。
- **不改**后端。`/entry/import/{id}/upload` 端点、`max-file-size: 12MB` 全部不动 —— 拖拽和点选送到后端的是**同一个 FormData**。
- **不做**整页任意位置拖放(drop anywhere)。上传区是明确的落点,整页接收会和「已上传截图画廊」的点击放大冲突。

## 3 · 作者已拍板(2026-08-15)

| 问题 | 拍板 |
|---|---|
| 要不要顺带支持 Ctrl+V 粘贴 | **加** → 已落成 FR-375 |

**扩范围的后果**(说清楚,免得后面才发现):

- issue #11 原文只说了拖拽,**发版说明与回给提交者的话里要把粘贴也写上** —— 他提的需求被超额满足了,得让他知道能这么用,否则等于没做。
- 粘贴是**全页面级**监听,所以引入了一条拖拽没有的风险:抢掉页内输入框的正常粘贴。FR-375 把「不拦截输入框」写成了硬要求,验收里单独有一条。
- 拖拽和粘贴共用 `handleFiles`,所以增量确实只有监听那一段;但共用也意味着**三条入口一起翻车**,tech-design 为此加了一条「上传单一路径」的护栏。

## 4 · 验收(整版)

1. PC:拖拽 / 点选两条路径结果逐项一致(FR-370)。
2. PC:拖到区域外页面不跳走(FR-371)。
3. PC:拖非图片文件有明确提示(FR-373)。
4. PC:Ctrl+V 粘贴截图即上传;在页内数值输入框里 Ctrl+V **不被拦截**(FR-375)。
5. 移动端页面逐字未变(FR-374)。
6. `scripts/qa-run.sh` 全绿,并**新增护栏**:
   - `v114-DROPZONE-HAS-DROP-HANDLER` —— `import.html` 里出现 `id="dropZone"` 就必须同时出现 `drop` 监听,钉住「长得像拖拽区就必须真的能拖」,防止以后重构又把监听弄丢。
   - `v114-UPLOAD-SINGLE-PATH` —— 三条入口都必须调 `handleFiles`,钉住 FR-370 的「一行都不复制」。
7. PC + 移动双端截图 + UED 复看(拖拽态的高亮不能糊成一片)。
