# PRD · v1.5 · 基金持仓穿透(真实行业 / 资产分布)

> 承 v1.4「持仓截图智能解析」——已把大账户拆成一支支真实基金。本迭代再进一步:**穿透每支公募基金的底层,拿到真实的「股 / 债 / 现金」拆分和「申万行业」构成**,让旭日 / 透视 / 体检的分布从"按基金名猜一个标签"升级为"真实持仓分布"。
>
> Spike 已用 **prod 真实持仓**验证(2026-07-24),结论与设计见 §6。

## 0 · 背景与短板

- 现状:v1.4 后每支基金由 `LensAiTagService` 按**名字**让 LLM 猜**一个**行业标签(如"兴全合润"→混合)。
- 短板:
  - 一支混合 / 指数基金内部横跨几十个行业 + 含债券 / 现金,单标签既**粗**又常**错**;旭日「行业」维度其实是"猜的"。
  - 用户诉求(原话):"A 基金 30% 在家电、40% 在消费、30% 是现金 → 就能更细化我们的投资分布"。要的是**真实的金额行业分布**,不是一个标签。

## 1 · FR(用户视角)

- **FR-1 · 导入即认代码(人在环核对)**:AI 截图导入确认页,系统对每支识别到的持仓**自动匹配公募基金代码**并展示(基金全名 + 6 位代码 + 类型)。用户一眼核对 / 一键纠正 / 标"非公募(不穿透)";低置信自动标疑 ⚑。份额 A/C/E 归并到同一底层(穿透结果一致)。
- **FR-2 · 后台穿透**:确认后台自动拉取该基金:①**资产配置**(股 / 债 / 现金 占净值比,季度)②**前十大重仓股 → 申万一级行业**。落**全局共享缓存**(所有家庭共用,按基金代码+报告期)。
- **FR-3 · 真实分布进分析**:旭日 / 交叉透视 / 体检的「行业」维度改用**穿透后真实分布**——某支基金 ¥X:股票部分按前十大申万行业摊、覆盖不到的股票部分记「其他持仓」、债 / 现金部分按资产配置摊进「固收 / 现金」桶。多支基金加总 = 家庭真实行业 / 资产分布。
- **FR-4 · 穿不透诚实标注**:银行 / 券商理财、投顾组合(帮你投)、私募等**无公募代码**的,明确标「未穿透」,保持账户级粗粒度(资产类别),**绝不假分摊**(承 PivotEngine 诚实降级哲学)。
- **FR-5 · 覆盖度透明**:穿透卡 / tooltip 如实标注"前十大覆盖该基金股票仓位的 X%,剩余记其他持仓";联接 / QDII / 指数基金覆盖有限时明示,不假装 100% 穿透。
- **FR-6 · 可运营**:管理页配穿透数据源开关、刷新节奏(季度)、失败重试;一键"重新穿透某基金"。承 [[feedback_admin_runtime_config]]。
- **FR-7 · 隐私**:穿透只拿**公开基金代码**去查公开数据,**用户持仓金额 / 家庭身份永不出服务器**;共享缓存不含任何家庭数据。
- **FR-8 · 实体模型加「持仓方向」层(与打标融合)**:现在一个子账户(持仓)唯一对应一套标签;新增 `账户 → 持仓 → 持仓方向`。一支基金 = 多个持仓方向(如 兴全合润 = 食品饮料 18% / 家电 9% / … / 债 5% / 现金 5%)。**无穿透的持仓 = 隐式 1 条 100% 方向**(回落现有单标签,老数据零迁移);穿透基金 = N 条方向(各带 资产类型 + 行业 + 权重)。旭日 / 多维分析**复用同一份持仓方向结果**,口径统一。
- **FR-9 · 打标页(/lens/tags)迭代**:①树从「账户 → 持仓」扩为「账户 → 持仓 → 持仓方向」,穿透基金的持仓子行可展开看方向明细;②持仓子行加「**发起穿透拉取**」入口(不必只从截图导入,已有持仓也能在这直接拉);③兼容——未穿透持仓仍是单行单标签,手标不受影响;穿透方向可手工微调(标 MANUAL,重拉不覆盖)。
- **FR-10 · 行业维值扩容(对齐申万一级)**:现有 `IndustryTag` 20 个偏粗(家电 / 白酒糊在「消费食饮 / 制造军工」),达不到"30% 家电"诉求。**扩容对齐申万一级**(补 家用电器 / 食品饮料 / 电子 / 电力设备 / 机械设备 / 有色金属 / 基础化工 / 医药生物 / 银行 / 非银金融 / 汽车 / 计算机 / 传媒 / 通信 / 国防军工 / 公用事业 / 交通运输 / 建筑 / 农林牧渔 / 煤炭 / 石油石化 / 环保 / 美容护理 / 社会服务 / 商贸零售 等);东财细行业(f127:白酒Ⅱ / 白色家电…)→ 映射到扩容后维值。承 [[feedback_enum_add_sweep]] 全量扫模板/计数/裸露 code。

## 2 · 交互流程(见 preview/v1.5)

1. 截图导入 → 识别到基金列表(v1.4 已有)→ **确认页每行多一枚「代码」**:自动匹配的基金全名+代码(可改 / 可标非公募)。
2. 确认落库 → 后台穿透 job:解析代码→拉资产配置+前十大→申万→写共享缓存→重算该家庭 lens 穿透分布。
3. 旭日切「行业」维度:看到的是**真实穿透分布**(家电 / 消费 / 半导体 … + 固收 + 现金 + 其他持仓 + 未穿透),不再是单标签。hover 某基金可看它自己的穿透饼。
4. 未穿透的理财 / 投顾:单独归「未穿透」块,点开提示原因(无公募代码 / 理财不披露底层)。

## 3 · 核心设计:三层穿透管线(诚实降级)

- **L1 · 股 / 债 / 现金拆分**(全覆盖、可靠):`pingzhongdata/{code}.js` 的 `Data_assetAllocation`(股票 / 债券 / 现金 占净比,按季度)。→ 每支公募先准确拆成 股 / 债 / 现金 三桶。**固收为主的组合最大增益在这层**。
- **L2 · 细行业穿透**(权益部分):前十大重仓股(带股票代码)→ **申万一级行业**映射(家电 / 食品饮料 / 半导体…)。股票仓位里前十大覆盖不到的部分 → 「其他持仓」。
- **L3 · 未穿透**:无代码 / 无季报 / 理财 / 投顾 → 保持账户级资产类别,标「未穿透」。
- **归一化匹配**(名→码):剥份额后缀(A/B/C/E)+ 括号((LOF)/(QDII-LOF))+ 公司别名(交银施罗德→交银)后匹配东财全量名↔码表;命中多个按类型择优;**份额不同底层同**→归并。低置信 / 多候选交给 FR-1 人工核对。
- **共享缓存**:`fund_penetration`(代码→报告期→资产配置+行业权重),季度刷新;查一次全体家庭复用;**金额不参与**,隐私天然干净。

## 4 · 决策与备选(★ = 已拍板)

- **★ 穿透粒度**:L1(股债现金)+ L2(前十大→申万细行业)。备选:仅 L1 / 仅证监会门类(制造业级)。选 L2 因用户明确要"家电 / 消费"级;门类太粗达不到诉求。
- **★ 名→码解析**:导入确认时**人工核对**。备选:全自动只标低置信。选人工核对因 spike 实测有份额错配(A/C)+ 误匹配(月月宝→天弘月月宝)风险,错配会让行业全错;复用 v1.4 确认流成本低。
- **数据源**:东财天天基金 F10 / pingzhongdata(免费、境内直连、spike 已验证)。备选:Tushare(需积分、只给个股持仓要自己映射)/ 巨潮季报 PDF(权威但解析重、滞后)。选东财为主,Tushare 可做交叉校验(待 TDD 权衡)。
- **调用方式**:Java 直连东财 HTTP(`RestTemplate`),不引 Python / AKShare 服务(部署轻)。承 [[feedback_resttemplate_signed_url]] 调用纪律。
- **行业分类标准**:申万一级(与现有 `IndustryTag` 白名单对齐 / 扩充);证监会门类仅作 L2 拿不到时的兜底。
- **穿透计算**:全在 Java 工程算(加权分摊),LLM 不碰数学。承 [[feedback_llm_no_math]]。
- **覆盖度呈现**:如实标"前十大覆盖 X%"+「其他持仓」桶。备选:把前十大归一化到 100%(假装全穿透)——**否决**,是假分摊。

## 5 · 非目标

- **理财 / 券商收益凭证 / 投顾组合穿透**:无干净 API(中国理财网数据不全、定期报告 PDF only、资管产品黑箱),spike 实测约 19 个穿不透 → 本迭代不做,标「未穿透」。
- 实时穿透(季报滞后 ~季末 15 天,月度快照产品可接受)。
- 私募 / QDII 底层逐股穿透(披露有限)。
- 超出前十大的精确逐股归因(季报只到前十大;半年报 / 年报全量留将来)。

## 6 · 技术可行性(Spike 已验证 · prod 真实持仓 · 2026-07-24)

- 东财接口境内可达:名↔码表(3.1MB)/ F10 行业配置 / `pingzhongdata` 资产配置 全通(http 200)。
- **资产配置可靠**:例 兴全合润 163406 = 股 91.7% / 债 5.1% / 现金 4.6%(2026-06-30),按季度全覆盖。
- **细行业靠前十大→申万**:F10「行业配置」是证监会门类(制造业级,太粗);且联接 / 指数基金直接持股行业几乎空(钱在 ETF 里)→ 细行业必须走前十大重仓股→申万。
- **名→码是瓶颈**:基础匹配 13/37;剥后缀调优后 ~15/18 公募可命中,但有份额错配 + 误匹配风险 → 故 FR-1 人工核对。
- **组合现实**:prod 组合绝大多数是固收 / 现金(债基 + 券商 / 银行理财 + 现金),真正股基 ~5 支(交银互联网 QDII、沪深300联接、兴全合润、天弘 A50、中欧价值智选)→ 细行业穿透精细化权益那块,固收为主组合最大增益在 L1 股债现金拆分。

## 7 · 数据模型(增量)· 核心是「持仓方向」层

- **新表 `holding_allocation`(持仓方向 · 融合打标与穿透的落点)**:`id, holding_id, weight_bp(万分比·同持仓合计10000), asset_class, industry, kind(STOCK/BOND/CASH/OTHER), source(PENETRATED/MANUAL/DEFAULT), report_period`。
  - 穿透基金 → N 条 PENETRATED 方向;手工微调 → MANUAL(重拉不覆盖 MANUAL);无穿透持仓 → **无方向行,lens 回落隐式 1 条 100%**(用持仓现有单标签),老数据零迁移。
- **新表 `fund_penetration_cache`(全局共享,无 family_id)**:`fund_code, report_period, alloc_json(股/债/现金 + 行业权重 + 覆盖度), fetched_at`。穿透结果**按基金代码全体家庭复用**,金额不入表(隐私)。`拉取` = 从缓存(缺则实时抓东财)物化成该持仓的 `holding_allocation` PENETRATED 行。
- `stock_holding` 增:`fund_code`(穿透键·可空)、`penetrate_state`(PENDING / RESOLVED / MANUAL / UNPENETRATED)。
- **Lens 融合(改 `LensQueryService.assemble`)**:每持仓——有 `holding_allocation` 行 → 按 `weight_bp` 拆成**多个 Position**(valueBase×权重,assetClass/industry 取方向值);无 → 保持现在的 1 个 Position(回落单标签)。`Position` 结构不变,引擎/注册表/旭日/透视**全下游零改动**,自然聚合出真实分布。
- **行业维值**:`IndustryTag` 扩容对齐申万一级(§FR-10);东财细行业→维值映射表(代码内)。
- 兼容自检见 §8。

## 8 · 向后兼容 + 隐私

- 现有 `industry_tag`(v1.4 单标签)保留为**穿透拿不到时的回落**;老持仓零回溯,不动历史快照。承 [[feedback_prod_backward_compat]]。
- 穿透是**增强**非核心:接口挂 / 限流 / 无季报 → 静默降级到 L1 或单标签,不阻断。
- 隐私:共享缓存只按公开代码,金额 / 家庭永不外泄;查东财只暴露"哪些公募基金被查"(公开标识),不含持仓额。

## 9 · 成本

- 免费(东财公开接口)。共享缓存 → 每基金每季度查一次,全体复用;调用量极小。
