# PRD · v1.2.2 · 全局字号调节(无障碍)

> **状态**:方案 + preview 待评审(2026-07-21)· 源自 GitHub issue #7「字体字号问题」
> **一句话**:让用户一键把全站文字放大到看着舒服的档位——覆盖我们所有组件类型,不崩排版、不糊图表。

## 0 · 背景与目标

外部试用者反馈:网页端 Demo「字体和字号略小,眼睛看的好难受」,希望有**字号调节开关**。owner 已确认要做(issue #7:「可以, ongoing」)。

这是**无障碍(a11y)诉求**,不是花活。家庭成员里有长辈 / 视力一般的人,阅读舒适度直接决定「每月 10 分钟」愿不愿意打开。因此:

- **G1**:提供全站生效的字号档位切换,默认「标准」(现状),可上调到「大 / 特大」。
- **G2**:放大必须**覆盖所有组件类型**——正文、KPI 数字、段标、pills、小注脚注、表格流水、按钮、表单、图表标签、旭日引线。任何一处"没跟上"都会露馅、显得半成品。
- **G3**:放大后**排版不崩**(不溢出、不错位、不字大框小)、**图表不糊**(不用 zoom 拉伸 canvas)。
- **G4**:选择**跨会话记住**(无障碍偏好不该每次重设)。

## 1 · 为什么是"大活"(现状盘点)

全站排版是「晚清账册」高密度体系,字号来源三类,**根字号放大只能推动其中一类**:

| 来源 | 规模 | 改根字号会缩放? |
|---|---|---|
| Tailwind 语义类 `text-sm/base/xl…` + rem 间距 `p-4/gap-2` | ~840 处 | ✅ 会(rem) |
| **写死 `text-[10px]/[11px]/[9px]…`** | **820 处 · 57 模板 · 仅 6 个离散尺寸(8/9/10/11/12/13px)** | ❌ 不会(绝对 px) |
| `style.css` 组件类绝对 px(`.kpi-value` 30px、`.eyebrow` 10.5px、`.pill`、`.btn-paper` 12px…) | 单文件十几类 | ❌ 不会 |
| 图表 JS 写死 fontSize(ECharts/Chart.js) | ~10 个模板 | ❌ 不会(canvas) |

**天真做法(只改根字号)会崩**:大标题涨、10px 小注纹丝不动、比例全乱。preview 里勾「天真对比」可亲眼看到。真正的工作量在**把后三类也纳入同一个缩放因子**。

## 2 · FR(用户视角)

- **FR-1 · 三档切换**:顶栏「Aa」控件,弹出 `标准 / 大 / 特大` 三档,单击即全站生效(无刷新)。
- **FR-2 · 全覆盖**:切档后正文、KPI、段标、pills、小注、表格、按钮、表单、**图表标签**一并同比放大(见 §3 矩阵)。
- **FR-3 · 不崩**:特大档下各页不溢出、不错位;移动端一等公民(移动端更是放大主场景)。
- **FR-4 · 记住**:选择按设备记住(localStorage),下次进来即生效,进入无闪烁(FOUC 防闪)。
- **FR-5 · 表单不触发 iOS 缩放**:输入框放大同时不低于 16px 地板(既有 iOS 聚焦放大坑)。

## 3 · UED 叠加矩阵(组件 × 缩放)

| 组件类型 | 现状 | 缩放机制 | 叠加坑 / 边界 | 处置 |
|---|---|---|---|---|
| 正文/描述/表名 `text-sm·base` | rem | 根字号自动 | — | 零改动直接受益(issue 主诉核心) |
| 大标题 `font-display 3xl~5xl` | rem | 根字号自动 | 特大档可能撑行 | 验证换行不溢出 |
| rem 间距 `p-4/gap-2` | rem | 根字号自动 | — | 容器随字呼吸,密度不挤 |
| 写死小字 `text-[10/11/9px]` ×820 | 绝对px | **层2 · 6 类 `!important` 重定义** | Play CDN 生成绝对 px,须同级后写压制 | `!important`(仓库已验证手法:lens-select 16px) |
| 组件类 `.kpi-value/.pill/.eyebrow/.btn` | 绝对px | **层3 · style.css 集中 `calc`** | 单文件十几类 | `base × var(--fs-scale)` |
| 图表轴/图例/数据标签 ×~10 页 | JS px | **层4 · JS 乘 scale + 重绘** | CSS 够不到 canvas;切档要重渲 | 统一 `chartFont(base)` 助手 + 档变钩子 |
| 旭日/引线标签(lens.js) | JS px | 层4 · 同上 | 引线布局按字宽算,放大要重排 | `renderLeaders` 读 scale 重算槽位 |
| 表单 input/select | — | **层5 · iOS 16px 地板** | <16px 聚焦触发整页放大 | `max(16px, 14px×scale)` |
| 隐私模糊 `blur(7px)` | 绝对px | 基本无关 | 特大档遮挡略弱 | 可选:blur 也 ×scale(次要) |
| 触控热区 `::after inset -12px` | 绝对px | 独立 | — | 不动,已够大 |

## 4 · 机制:一个变量,五层(概要 · 详见 tech-design)

- `--fs-scale` 由 `html[data-fs]` 设:`标准 1.0 / 大 1.15 / 特大 1.30`。
- **层1** 根字号 `calc(15px × var(--fs-scale))` → rem 语义类 + 间距 + 正文全部自动。
- **层2** 6 个 `text-[Npx]` 用 `calc(Npx × var(--fs-scale)) !important` 重定义(O(6) 非 O(820))。
- **层3** `style.css` 组件类绝对 px 集中改 `calc`。
- **层4** 图表统一 `chartFont(base)=base×scale`,切档复用隐私模式的 canvas 重绘钩子重渲。
- **层5** 输入框 `max(16px, 14px×scale)` 守 iOS 地板。
- **验证载体**:preview 与生产同款 Tailwind Play CDN + style.css,preview 跑通即证明应用可行(已无头渲染实测:text-[10px] 标准 10px → 大 11.5px → 特大 13px,`!important` 稳压 Play CDN;天真对比档回落 10px 复现崩坏)。

## 5 · 决策与备选(推荐已选,待你拍板)

| 决策 | 备选 | 选定 | 理由 |
|---|---|---|---|
| 档位形态 | A 离散三档 / B 自由滑块 / C 系统跟随 | **A 三档** | 家人好懂、可穷尽验证、不会滑到怪比例;滑块要测无穷档、易崩 |
| 放大幅度 | 1.0/1.15/1.30 · 或含"特小/更大" | **1.0/1.15/1.30** | +15%/+30% 覆盖主诉且特大档排版仍稳;下探无意义(主诉是"太小") |
| 控件位置 | A 顶栏 Aa + 弹层 / B 设置页 / 两者 | **A 顶栏** | 对齐隐私眼睛范式,一键可达、最易发现;可后续也放设置页 |
| 记忆 | localStorage(设备)/ 落库(账号跨端) | **localStorage** | 无障碍偏好跟设备走(同一人不同设备视力场景不同),不入库、不跨端、零后端 |

## 6 · 非目标

- 不做逐元素自定义字号 / 不做字体族切换(issue 只提字号;换字体会破坏账册美学一致性)。
- 不用 CSS `zoom` / `transform:scale` 整体拉伸(会糊 canvas 图表、扰乱 fixed 定位与媒体查询)。
- 不做深色模式 / 高对比模式(本次只解字号;若后续无障碍再开专版)。
- 不改后端、不加迁移、不落库(纯前端 + localStorage)。
