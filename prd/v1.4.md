# PRD · v1.4 · 持仓截图智能解析(大账户拆真实持仓)

> **状态**:草案 · 待评审(PRD 阶段 · 未进 TDD)· 交互 preview `preview/v1.4/holdings-import.html`
> **一句话**:基金/理财/券商这类大账户里堆着十几支真实持仓,手 key 太累没人维护 → 用户咔咔截图上传,AI 视觉自动解析出每一支持仓(名称 + 市值),逐个建模并打标,用户扫一眼确认即入库;让旭日下钻 / 交叉透视 / 资产体检能下钻到**真实持仓**,而不是「一个大账户一套粗糙标签」。

## 0 · 背景与短板

- **现状**:只有 STOCK / CRYPTO / METAL 账户能拆持仓(`stock_holding` 表);WEALTH(基金 / 理财)、以及部分 CASH(如蚂蚁财富)是「**一个账户 = 一个总额**」,内部零建模。
- **真实数据(prod / beta 实查)**:「蚂蚁财富-基金」一个账户 22 万,内部十几支不同基金(消费 / 科技 / 医药 / 债 / 货币…),却只能挂账户级一套 `asset_class` / `industry` —— beta 上它的 `industry_tag` 干脆是 `NULL`,因为它根本没有单一行业。
- **根因**:手 key 十几支持仓的名称 + 市值太累,违背「**10 分钟 / 月**」的产品铁律 → 用户理性偷懒 → 数据粗糙 → 旭日下钻 / 透视 / 体检在这些大账户上全是「一坨」,分析失真。
- **机会**:用户手机里本来就有这些 app 的持仓列表页。把「手 key 十几行」变成「**拍几张图 + 扫一眼确认**」,既解决准确性,又不违背省事铁律。

## 1 · FR(用户视角)

- **FR-1 · 截图上传**:在账户详情页(基金 / 理财 / 券商类)提供「截图导入持仓」入口,支持一次选多张图(相册连拍 / 长图分段),**移动优先**。
- **FR-2 · AI 自动解析**:上传后系统自动识别出每一支持仓的「**名称 + 当前市值**」(截图里若有收益额 / 收益率也一并读取),几秒出结果。
- **FR-3 · 自动打标**:每支持仓自动带上「**资产类型 / 行业投向 / 平台**」标签(复用现有 AI 打标白名单),用户可改。
- **FR-4 · 确认后入库(铁律)**:解析结果先进一张「**可编辑确认表**」——逐行可改名称 / 市值 / 标签、可删、可加,用户**显式点「确认导入」才落库**(承 LensAiTag「显式接受」教训,绝不自动写)。
- **FR-5 · 拆分即生效**:确认后,该账户从「一个总额」变成「N 支真实持仓」,旭日下钻 / 交叉透视 / 切片排行 / 资产体检**自动按真实持仓的行业 / 资产类型细分**(承 PivotEngine 持仓级机制,近零额外改)。
- **FR-6 · 对账兜底**:解析出的持仓市值之和 vs 账户原总额,若差异超阈值,提示「**Σ 持仓 = X,账户原记 Y,差 Z**」,让用户决定(补一笔「其他 / 现金」行,还是以持仓为准更新账户)。**绝不悄悄改账户总额。**
- **FR-7 · 更新而非重录**:下次再截图上传,按名称匹配已有持仓 → **更新市值**(而非重复创建);新出现的建新持仓、消失的提示归档。
- **FR-8 · 隐私与留痕**:原图**仅用于识别、识别完即删**(不长期落盘);只有用户确认过的结构化结果入库;上传前明示「图片将发送给 AI 视觉服务识别」;记审计。

## 2 · 交互(见 preview)

- **入口**:账户详情页「截图导入持仓」按钮(WEALTH / STOCK / CRYPTO)。
- **上传**:移动端点开 = 直接调相册 / 相机多选;PC = 拖拽 / 选文件。缩略图预览 + 单张删除。
- **识别中**:进度态(逐张「识别中…」),可继续加图。
- **确认表**:逐行 = `[✓选中] 持仓名 | 市值 | 资产类型▾ | 行业▾ | 平台 | [删]`;顶部「+ 手动加一行」;识别不确定的行**标黄**提示核对;底部**对账条**:`Σ市值 vs 账户原额` + 差异提示;主按钮「**确认导入 N 支**」。
- **完成**:回账户详情,显示 N 支持仓列表(复用现有 `stock_holding` 持仓展示样式)。

## 3 · 核心设计:解析管线(诚实 + 人在环)

三段式,每段边界清晰、职责单一:

1. **视觉转写(读,不算)**:截图 → 视觉大模型 → 逐支持仓的「名称 + 屏幕上显示的市值 / 收益」**原样转写**。只转写屏幕已有的数字,**不做任何计算 / 推导**(承「LLM 严禁做数学」铁律:收益率不让它算、成本不让它反推,只读屏上有的)。
2. **白名单打标(判,带兜底)**:每支持仓名 → 资产类型 / 行业 / 平台(复用 `LensAiTagService` 白名单;枚举外的值丢弃回落)。
3. **人在环确认(定)**:可编辑表,用户改 / 删 / 加 + 对账;显式确认才落库;所有数学(Σ、对账差)由**工程算好**填进去给用户看,不经模型。

**呈现诚实**:市值取屏幕值,识别不确定的行标黄让用户核;对账差异只提示不自动改;收益率 / 成本这类「算出来的」一律不让模型编,缺就空着用户补。

## 4 · 决策与备选(推荐已选 · 待拍板)

| 决策 | 备选 | 选定 | 理由 |
|---|---|---|---|
| **解析技术** | ① 服务器传统 OCR(Tesseract / Paddle)② 云结构化 OCR ③ **视觉大模型(qwen-vl-max)** ④ 前端 OCR(tesseract.js) | **③ 视觉大模型** | 消费类 app 截图版式杂(彩色收益 / 多列 / 图标),传统 OCR 出「文本汤」、跨 app 拼行极脆;视觉模型懂语义(哪列是市值)、能归一基金名、一步到位;且**复用现有 Qwen / DashScope 基建**(同一 OpenAI 兼容端点换 `qwen-vl` 模型 + 现有 AKSK 管理页),不引第二个供应商。前端 OCR 手机上慢 + 中文差,pass。 |
| **识别范围** | 名称+市值 / 名称+市值+成本+收益全量 | **名称 + 市值(收益若屏显则带)** | 市值是拆分 / 透视唯一必需;成本 / 收益各 app 不一定都显示,强求会逼模型编数(违铁律)。缺的用户补。 |
| **是否自动定价** | 每支基金按代码自动拉净值 / **手动值(截图市值,再传即刷新)** | **手动值** | 自动拉净值需基金代码库 + 净值数据源 + 每日任务,是**另一个大工程**;截图本身就是最新市值,再传即更新,简单诚实。列未来非目标。 |
| **落库时机** | AI 直接建持仓 / **确认表显式确认** | **显式确认** | 钱的数据 + 模型可能错 / 漏;确认建信任、防幻觉;承 LensAiTag 教训。 |
| **对账差异** | 自动改账户总额 / **只提示由用户定** | **只提示** | 绝不悄悄动用户的钱数;Σ 持仓与账户额差异交用户判断(补现金行 or 以持仓为准)。 |
| **数据模型** | 新建 `fund_holding` 表 / 泛化 `stock_holding`→`holding` / 扩展复用 `stock_holding` | **留给 TDD 拍板** | 三者取舍(复用 vs 语义 vs 迁移风险)属架构层,PRD 不定;倾向**最大化复用现有持仓管线**(perHoldingLines / LensQueryService / PivotEngine 已支持持仓级),TDD 详证 + 列未选理由。 |
| **隐私** | 原图留存 / **识别即删** | **识别即删** | 只存用户确认的结构化结果;原图不长期落盘;上传前明示「发给 AI 视觉服务」。 |

## 5 · 技术可行性 & 工程量(为什么这是「高杠杆」)

- **视觉端点复用**:Qwen 走 DashScope `compatible-mode/v1/chat/completions`(OpenAI 兼容),视觉只是把 `message.content` 换成含 `image_url`(base64)的多模态数组 + 模型换 `qwen-vl-max/plus`。现有 `QwenLlmClient`(RestTemplate)加一个 `chatWithImage` 变体即可,**复用现有故障转移 / 熔断 / AKSK 管理页**。DeepSeek 当前无视觉 → 视觉链路以 Qwen 为准,**缺 key 时功能优雅禁用**(承 `available()` 模式)。
- **持仓管线复用(核心杠杆)**:`PivotEngine` / `Position` / `LensQueryService` 早已支持「账户拆 N 持仓 + 持仓级 `industry` 维度 + 诚实降级」。新持仓落进去,旭日 / 透视 / 体检**自动细分**,近零下游改动。
- **上传基建复用**:`LogoUploadController` 已有类型 / 大小 / 魔数 / 路径穿越 / 审计范例,新上传端点照搬加固。
- **打标复用**:`LensAiTagService` 白名单校验直接用。
- **待验证的头号技术风险**:`qwen-vl-max` 对**真实**支付宝 / 券商 / 银行截图的解析准确率(名称归一 + 市值对位)。→ **建议先做「真机截图验证 spike」**:beta 开一个临时上传页,用真实截图实测识别质量,再锁 tech-design。**依赖:beta 目前只配了 DeepSeek(无视觉),需先在管理页配一个通义千问(Qwen)key。**

## 6 · 非目标(本迭代不做)

- 不做每支基金的**实时净值自动定价**(需基金代码库 + 净值源,列未来)。
- 不做券商**下单 / 改单**(承券商只读铁律)。
- 不做任意**对账单 PDF / 长文档**解析(v1 只针对「持仓列表截图」)。
- 不做「**零确认全自动**」(人在环是铁律)。
- 不改交叉表 / 明细 / 看板的既有能力(它们已支持多持仓)。

## 7 · 落地面(评审通过后进 tech-design)

- **数据模型**:持仓表方案拍板(复用 / 泛化 / 新建)+ 迁移(**prod 向后兼容**:老 WEALTH 账户零持仓时行为不变)。
- **视觉链路**:`LlmClient` 加多模态方法 + `QwenVisionClient`;prompt(转写规范 + few-shot + **禁算约束**)+ 白名单;缺 key 优雅禁用。
- **上传**:多图上传端点(加固)+ **识别即删** + 审计。
- **前端**:账户页入口 + 上传 / 识别 / 确认表(移动优先)+ 对账条。
- **装配**:`LensQueryService` 扩展到 WEALTH / CASH 持仓展开;`Position` 组装;Lens 缓存失效事件(承 AFTER_COMMIT 覆盖)。
- **守护**:qa(端点 / 白名单 / 禁算 / 确认才落库 / 对账不改额)+ e2e(上传 → 解析 mock → 确认 → 旭日细分)。
- **管理页**:视觉模型开关 + 模型名(`K_LLM_VISION_MODEL`)。
