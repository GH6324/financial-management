# PRD · v1.4 · 持仓截图智能解析(大账户拆真实持仓)

> **状态**:草案 v3 · 待评审(纳入评审反馈 10 点)· 视觉链路已真机验证 · 交互 preview `preview/v1.4/holdings-import.html`
> **一句话**:在**填报页选中某个具体账户** → AI 识别截图 → 与该账户已有持仓做**左旧右新的逐项比对(匹配更新 / 新增 / 卖出)** → 用户确认 → 落库并记一条可回看的流水明细(含原图)。让大账户(基金/理财/券商)拆成真实持仓,旭日/透视/体检下钻到每一支。

## 0 · 背景与短板

- 只有 STOCK/CRYPTO/METAL 账户能拆持仓;WEALTH(基金/理财)、部分 CASH(支付宝)是「一个账户 = 一个总额」,内部零建模,标签粗、分析失真。
- 手 key 十几支太累(违「10 分钟/月」铁律)→ 没人维护。
- 用户手机里就有持仓列表页。**真机验证**:`qwen-vl-max` 读真实支付宝/招行截图市值 100% 对、跳过汇总行、截断行诚实标疑。

## 1 · FR(用户视角 · 含评审 10 点)

- **FR-1 · 入口在填报页 · 选账户后再导入**:在**填报页**,选中某个具体的基金/理财/券商账户后,该账户行给「**AI 截图识别导入**」入口(而不是全局入口)。选对账户 → 才进导入。手动逐笔录入依旧保留(FR-9)。
- **FR-2 · 一账户多图 + 前端压缩**:一次可选多张(相册连拍/长图分段),缩略图预览、删单张、继续补图;上传前浏览器压缩(长边 ~2000px、保证文字清晰),几 MB → 几百 KB。
- **FR-3 · 导入前成本预估**:随着用户加图,在点「导入本月本账户」**前**,按**当前配置的视觉模型**实时显示「本次预估成本 ≈ ¥X(N 张 × 单价)· 免费额度内≈0」。
- **FR-4 · 视觉模型可换(管理页)**:管理页 `/admin/integrations` 增加「视觉识别模型」下拉(qwen-vl-max 默认 / qwen-vl-plus 省钱档 / 关闭),用户自选「更准 vs 更省」。
- **FR-5 · 扫描动画 + 预估耗时**:识别时在每张图上做「AI 扫描线」动画,并按 ~10s/张估算显示「预计约 N 秒」,让等待有反馈、好看。
- **FR-6 · 上传/识别状态机 + 断点续看**:导入是一个**有状态的持久任务**(上传中→扫描中→待确认→已确认/已放弃)。用户若因扫描久而退出,**再次进入该账户能看到上次已完成的识别结果**,不用重来。
- **FR-7 · 左旧右新逐项比对(核心交互)**:识别完进一个**比对列表**——**左边是该账户已有持仓,右边是这次识别出的持仓**,按子项名称**默认自动匹配一遍**,用户可手动改匹配。每一项有明确状态:
  - **匹配更新**:左右配上了 → 更新市值(展示 旧→新)。
  - **新增**:右边有、左边没有 → 建新持仓。
  - **卖出**:左边有、右边这次没有 → 标「卖出/未出现」,由用户定夺(默认保留;多图可能没截全,不自动删)。
- **FR-8 · 确认后入库(铁律)**:比对结果可编辑(改名/市值/标签、改匹配、加删),显式点确认才落库;所有加总/涨跌/对账差由工程算好。
- **FR-9 · 手动更新依旧可用**:不强制走截图;用户随时能手动新增/改/删持仓(复用现有持仓 CRUD)。
- **FR-10 · 拆分即生效**:确认后账户拆成 N 支真实持仓,旭日/透视/体检自动按行业/资产类型细分。
- **FR-11 · 原图压缩持久化 + 可回看**:用户上传的截图**压缩后持久保存**(不再识别即删),归到本次导入记录名下;日后能在该账户的流水明细里**回看当时上传的原图**。
- **FR-12 · 导入产生流水明细**:每次确认导入 → 记一条**账户级「持仓估值调整」流水事件**(钱赚侧,剔出人赚净流入,不污染收支口径),其**明细可展开**:逐项变化(新增/更新旧→新/卖出)+ 当时的原图。承现有填报页行内 ledger 展开机制。
- **FR-13 · 账户总额对账兜底**:Σ持仓 vs 账户原额,差异只提示不自动改(防历史净值跳变)。

## 2 · 交互流程(见 preview)

```
填报页 → 选中某基金/理财/券商账户行 → 点「AI 截图识别导入」
  → 上传页:多选截图 + 前端压缩 + 缩略图;实时显示「本次预估 ≈ ¥X(模型档)」
  → 点「导入本月本账户」→ 每张图「AI 扫描」动画 + 「预计约 N 秒」
  → (若中途退出,再进该账户 = 直接回到「待确认」态,不重来)
  → 左旧右新比对列表:自动匹配 + 三态(匹配更新/新增/卖出)+ 可手动调匹配/编辑
  → 底部对账条(Σ持仓 vs 账户额)
  → 确认 → 落库 + 写回当期估值 + 记一条「持仓估值调整」流水(明细含逐项变化+原图)
  → 回账户:N 支真实持仓;旭日/透视自动细分;流水里可回看这次明细
```

## 3 · 核心设计:解析管线(诚实 + 人在环)

三段式:**① 视觉转写(读,不算)** qwen-vl 只读屏幕可见的名称+市值(禁计算/推导);**② 白名单打标** 复用 LensAiTag;**③ 比对 + 人在环确认** 左旧右新三态 diff,用户改/删/加/定夺,显式确认才落库,数学全工程算。诚实:市值取屏幕值、截断标 low、卖出不自动、对账差只提示。

## 4 · 决策与备选(推荐已选 · 待拍板)

| 决策 | 选定 | 理由 / 未选 |
|---|---|---|
| 入口位置 | **填报页选中账户后** | 承评审第 1 点;选对账户再导入,语境清晰。账户详情页也留一个日常维护入口。 |
| 视觉模型默认 | **qwen-vl-max**(plus 可切) | 实测 max 更干净(plus 会误纳汇总行);成本两档都可忽略,故默认更准的。管理页可换。 |
| 成本预估 | **前端按图数×模型单价实时算** | 导入前透明,用户可控。 |
| 比对交互 | **左旧右新 + 自动匹配 + 手调** | 承第 4 点;比扁平表更直观「这支是同一支的更新 vs 新增 vs 卖了」。 |
| 卖出判定 | **用户定夺(默认保留)** | 多图可能没截全,不自动删。 |
| 导入任务 | **持久化 job + item(状态机)** | 承第 6 点断点续看 + 第 8 图片 + 第 9 明细,一套表全承载。 |
| 原图 | **压缩持久化(可回看)** | 承第 8 点;~300KB/张、月增几 MB,可接受;供第 9 点回看明细。(反驳「太大」:不大。) |
| 流水记录 | **一条账户级 VALUATION 事件 + 明细** | 承第 9 点;持仓涨跌是钱赚不是人赚 → 记 VALUATION/adjustment,不污染净流入口径;明细展开看逐项+原图。 |
| 数据模型 | **复用 stock_holding** + 导入记录表 | 见 §7。 |
| 对账 diff | **复用券商 reconcile 三态** | 已有实现。 |
| 备份 | **不改** | 见 §8。 |

## 5 · 非目标

- 不做每支基金实时净值自动定价(截图市值=最新,再传即刷新)。
- 不做券商下单/改单(只读铁律)。
- 不做 PDF/长文档解析(只针对持仓列表截图)。
- 不做零确认全自动 / 不自动判卖出。
- 不把持仓涨跌记成收入(人赚/钱赚口径不乱)。

## 6 · 技术可行性(已验证)

`qwen-vl-max` 走现有 DashScope 端点 + 现有 Qwen key(真机 3 张、~18 支、市值全对、~10s/张)· 持仓/估值/装配/对账/透视全链路现成 · 上传/压缩/serve/备份复用 logo 基建。详见 tech-design/v1.4.md。

## 7 · 数据模型(底层是否满足:满足)

- **持仓**:复用 `stock_holding`(MANUAL=名称+manual_value 适配基金);扩展:`supportsHoldings()` 放开 WEALTH/CASH、加可空列 `asset_class_tag`/`risk_tag`/`liquidity_tag`(空回落账户级)、`sync_source` 加值 `SCREENSHOT`。**不新建持仓表、不改历史**。
- **导入记录(新表)**:`holding_import`(job:账户/期/状态机/模型/成本估/时间)+ `holding_import_item`(逐项:识别名/市值/匹配到的持仓/状态 匹配更新·新增·卖出/旧值→新值)+ 压缩原图路径。承第 4/6/8/9 点。
- **流水**:导入确认时,复用现有 `cash_flow` 的 VALUATION 类型记一条账户级估值调整事件,`refImportId` 指向 `holding_import`(供明细展开);`adjustment=true` 剔出人赚。

## 8 · 向后兼容 + 备份(线上历史数据)

- **历史零回溯**:老账户历史 `period_snapshot`(手填单一余额)原样保留,净值曲线该段不变。
- **当期交接**:当前 OPEN 期导入持仓 → `AccountValuationService` 接管 → Σ持仓 写回当期 snapshot(与 STOCK 同);**没持仓的老账户系统绝不碰**(既有红线)。
- **防跳变**:FR-13 对账让用户对齐 Σ持仓 vs 账户额,交接当期收益不虚高。
- **备份不改**:`backup.sh` = 整库 mysqldump(新表自动含)+ `tar uploads/`(压缩原图放 uploadRoot 自动含)。仅需确认 prod `UPLOAD_ROOT` 指向被 tar 的持久盘(非 /tmp)。图片月增几 MB,56 天滚动保留无压力。

## 9 · 成本(可忽略)

图片 token 封顶 1280 + 新用户 7000 万免费 token。单次 ~2200 token;`qwen-vl-max` ~¥0.01/张、`qwen-vl-plus` ~¥0.005/张。prod 单家庭 17 个候选账户 → 月 ~15–30 张 → **月几毛,或免费额度内≈0**。plus 实测市值也全对但更脏 → 默认 max、plus 可切。详见 tech-design/v1.4.md §9。
