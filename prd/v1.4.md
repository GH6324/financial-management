# PRD · v1.4 · 持仓截图智能解析(大账户拆真实持仓)

> **状态**:草案 v2 · 待评审(PRD 阶段 · 已做真机 spike 验证视觉可行)· 交互 preview `preview/v1.4/holdings-import.html`
> **一句话**:基金/理财/券商这类大账户里堆着十几支真实持仓,手 key 太累没人维护 → 用户咔咔截图上传,AI 视觉自动解析出每一支持仓(名称 + 市值),与该账户**已有持仓做增/改/删对账**,用户扫一眼确认即入库;让旭日下钻 / 交叉透视 / 资产体检能下钻到**真实持仓**,而不是「一个大账户一套粗糙标签」。

## 0 · 背景与短板

- **现状**:只有 STOCK / CRYPTO / METAL 账户能拆持仓(`stock_holding` 表);WEALTH(基金 / 理财)、以及部分 CASH(如支付宝)是「**一个账户 = 一个总额**」,内部零建模。
- **真实数据(用户真机截图实测)**:一张支付宝「全部持有」= 余额宝 + 活钱+ + 兴全合润 + 交银互联网 + 天弘沪深300 …十几支基金;一张招行 = 兴银/招银/浦银理财 + 中欧基金 + 黄金。全塞在一个账户里,只能挂账户级一套标签,分析全失真。
- **根因**:手 key 十几支持仓的名称 + 市值太累,违背「**10 分钟 / 月**」的产品铁律 → 用户理性偷懒 → 数据粗糙。
- **机会**:用户手机里本来就有这些 app 的持仓列表页。把「手 key 十几行」变成「**拍几张图 + 扫一眼确认**」。**已用 `qwen-vl-max` 对用户真实截图实测**:市值 100% 读对、自动跳过汇总行、截断行诚实标疑 —— 技术路线成立。

## 1 · FR(用户视角)

- **FR-1 · 截图上传(移动优先 · 一账户多图)**:在**填报流程**和**账户详情页**都能进入「截图导入持仓」;一次可选多张(相册连拍 / 长列表分段截图),缩略图预览、可删单张、可继续补图。**多张图会先合并去重再对账**(不会因为分段截图把没截到的当成卖出)。
- **FR-2 · 前端压缩**:上传前浏览器端把大图压缩(长边限 ~2000px · 保证文字清晰的前提下降体积),几 MB 的截图压到几百 KB 再传 —— 省流量、省视觉 API 负载、避开体积上限。
- **FR-3 · AI 自动解析**:识别出每一支持仓的「**名称 + 当前市值**」(截图里有基金代码 / 收益也一并读),几秒出结果。
- **FR-4 · 自动打标**:每支持仓自动带上「**资产类型 / 行业投向 / 平台**」标签(复用现有 AI 打标白名单),用户可改。
- **FR-5 · 与已有持仓对账(增 / 改 / 删三态 · 核心)**:导入不是「重录」,而是和该账户**已有的导入持仓**做匹配比对,给出三态:
  - **① 新增**:这次出现、库里没有 → 建新持仓。
  - **② 价值变化**:名称匹配上了 → 更新市值(展示 旧值 → 新值 的涨/跌)。
  - **③ 卖出 / 消失**:库里有、这次没截到 → **标记「本次未出现」,默认保留、由用户决定是否归档(卖出)**。绝不因为你没截全就自动删。
- **FR-6 · 确认后入库(铁律)**:三态结果进一张「**可编辑确认表**」——逐行可改名称 / 市值 / 标签、可删、可加、可对每条「消失」项选保留或归档;用户**显式点「确认」才落库**(承 LensAiTag「显式接受」教训)。所有加总 / 对账差由**工程算好**,不经模型。
- **FR-7 · 拆分即生效**:确认后,该账户从「一个总额」变成「N 支真实持仓」,旭日下钻 / 交叉透视 / 切片排行 / 资产体检**自动按真实持仓的行业 / 资产类型细分**(承 PivotEngine 持仓级机制,近零额外改)。
- **FR-8 · 账户总额对账兜底**:Σ 持仓市值 vs 账户原总额,若差异超阈值,提示「**Σ 持仓 = X,账户原记 Y,差 Z**」,让用户决定(补一笔「现金 / 其他」行,还是以持仓为准)。**绝不悄悄改账户总额**;这也是防「历史净值跳变」的关键(见 §9)。
- **FR-9 · 隐私与留痕**:原图**仅用于识别、识别完即删**(不长期落盘);只有用户确认过的结构化结果入库;上传前明示「图片将发送给 AI 视觉服务识别」;记审计。

## 2 · 交互与入口(见 preview)

- **入口(两处)**:
  - **填报流程**:录入某个基金 / 理财 / 券商账户余额时,旁边给「截图导入持仓」快捷入口(比手 key 十几行省事)。
  - **账户详情页**:`/accounts/{id}/holdings` 顶部「截图导入持仓」按钮,做日常维护 / 再次对账。
- **上传**:移动端点开 = 直接调相册 / 相机多选;PC = 拖拽 / 选文件。缩略图预览 + 单张删除 + 继续补图。
- **识别中**:进度态(逐张「识别中…」)。
- **确认表(含三态)**:逐行 = `[✓选中] 状态徽记(新增/涨/跌/未出现) | 持仓名 | 市值(旧→新) | 资产类型▾ | 行业▾ | 平台 | [删]`;顶部「+ 手动加一行」;识别不确定的行**标黄**;「消失」项单独一组,每条可选 保留 / 归档(卖出);底部**对账条** `Σ市值 vs 账户原额`;主按钮「**确认 N 项变更**」。
- **完成**:回账户详情,显示 N 支持仓列表(复用现有 `stock/holdings.html` 持仓展示)。

## 3 · 核心设计:解析管线(诚实 + 人在环)

三段式,每段边界清晰、职责单一:

1. **视觉转写(读,不算)**:截图 → 视觉大模型(`qwen-vl-max`)→ 逐支持仓**原样转写**「名称 + 屏幕上的市值(+ 基金代码 / 收益)」。只转写屏幕已有的,**不做任何计算 / 推导**(承「LLM 严禁做数学」铁律)。
2. **白名单打标(判,带兜底)**:每支持仓名 → 资产类型 / 行业 / 平台(复用 `LensAiTagService` 白名单;枚举外的丢弃回落)。
3. **对账 + 人在环确认(定)**:与已有持仓做三态 diff(§8),可编辑表,用户改 / 删 / 加 / 定夺消失项;显式确认才落库;所有数学(Σ、对账差、涨跌)由**工程算好**填进去给用户看。

**呈现诚实**:市值取屏幕值,识别不确定的行标黄;收益率 / 成本这类「算出来的」一律不让模型编;截断 / 遮挡行标 `confidence:low`(已实测生效);卖出判定绝不自动、交用户。

## 4 · 决策与备选(推荐已选 · 待拍板)

| 决策 | 备选 | 选定 | 理由 |
|---|---|---|---|
| **解析技术** | ① 传统 OCR ② 云结构化 OCR ③ **视觉大模型 qwen-vl-max** ④ 前端 OCR | **③ 视觉大模型** | 消费类 app 截图版式杂,传统 OCR 出「文本汤」;视觉模型懂语义、归一名称、一步到位;**复用现有 Qwen/DashScope 基建**。**已真机验证**:市值 100% 对。 |
| **识别范围** | 名称+市值 / 全量成本收益 | **名称 + 市值(+代码/收益若屏显)** | 市值是拆分唯一必需;成本 / 收益各 app 不一定显示,强求逼模型编数。 |
| **是否自动定价** | 按代码拉净值 / **手动值(截图市值,再传即刷新)** | **手动值** | 自动拉净值需基金代码库 + 净值源 + 每日任务,是另一个大工程;截图本身就是最新市值。列未来非目标。 |
| **落库时机** | AI 直接建 / **确认表显式确认** | **显式确认** | 钱的数据 + 模型可能错;承 LensAiTag 教训。 |
| **卖出 / 消失处理** | 自动归档 / **标记 + 用户定夺(默认保留)** | **用户定夺** | 一账户多图 = 可能没截全;不能因没截到就当卖出误删。 |
| **数据模型** | 新建 fund_holding 表 / 泛化 rename holding / **复用 stock_holding** | **复用 stock_holding** | 它本就是通用持仓表(MANUAL=名称+manual_value 天然适配基金);复用估值/CRUD/装配/对账全链路;只加可空标签列 + `sync_source=SCREENSHOT`。详见 TDD §决策。 |
| **对账 diff** | 自造 / **复用券商 reconcile 三态** | **复用券商 reconcile** | `BrokerSyncService` 已实现「按键匹配→增/改/归档,只动本 source、不碰手填」,直接借。 |
| **隐私** | 原图留存 / **识别即删** | **识别即删** | 只存确认的结构化结果。 |

## 5 · 技术可行性(已验证)& 工程量

- **视觉端点复用(已验证)**:`qwen-vl-max` 走现有 DashScope OpenAI 兼容端点 + 现有 Qwen key,只把 message.content 换成含 image_url(base64)的多模态数组。真机 spike:3 张真实截图、~18 支持仓、市值全对、~10s/张。DeepSeek 无视觉 → 视觉链路以 Qwen 为准,缺 key 优雅禁用。
- **持仓管线复用(核心杠杆)**:`stock_holding` + `AccountValuationService`(Σ持仓→写回快照)+ `LensQueryService`(账户拆 N 持仓)+ `PivotEngine`(持仓级维度 + 诚实降级)全部现成,新持仓落进去,旭日/透视/体检自动细分。
- **对账复用**:`BrokerSyncService.reconcile` 三态算法。
- **上传/压缩复用**:`LogoUploadController` 安全范例 + logo 的 canvas 压缩模式。
- **打标复用**:`LensAiTagService` 白名单。

## 6 · 非目标(本迭代不做)

- 不做每支基金**实时净值自动定价**(截图市值 = 最新,再传即刷新)。
- 不做券商**下单 / 改单**(券商只读铁律)。
- 不做任意**对账单 PDF / 长文档**解析(v1 只针对「持仓列表截图」)。
- 不做「**零确认全自动**」、不自动判卖出(人在环铁律)。
- 不改交叉表 / 明细 / 看板既有能力。

## 7 · 与已有持仓对账(增 / 改 / 删三态 · 展开)

复用券商 `reconcile` 的思路,但适配「截图不一定截全 + 手填持仓要保护」:

- **来源隔离**:导入建的持仓打 `sync_source = SCREENSHOT`。对账**只在同账户、同 `SCREENSHOT` 来源的持仓之间**做增删改。用户**手填(sync_source=NULL)和券商同步(FUTU/TIGER)的持仓,永不被截图对账碰**。
- **匹配键**:基金代码(6 位,若截到)优先;否则**归一化名称**(去空格/全半角/常见后缀噪声)。
- **三态**:
  - **新增**(截图有、库无)→ insert MANUAL 持仓(名称 + 市值,shares=1、manual_value=市值)。
  - **价值变化**(匹配上)→ update `manual_value` + `manual_value_at`,确认表展示 旧→新。
  - **消失**(库有 SCREENSHOT 行、本次合并后仍没有)→ **不自动删**;确认表单列「本次未出现」组,用户逐条选 保留 / 归档(卖出)。
- **多图合并**:一次导入的所有截图**先合并成一个持仓集**再对账(避免分段截图误判消失)。

## 8 · 底层结构是否满足(数据模型)

**结论:满足,近零改造。** `stock_holding` 已是通用持仓表:

- 现有字段够用:`account_id / display_name / valuation_mode(AUTO|MANUAL|CASH) / shares / manual_value / manual_value_at / currency / industry_tag / sync_source / archived_at`。基金 = MANUAL 模式(名称 + manual_value),无需 ticker/market。
- **需扩展(全部向后兼容)**:
  1. `AccountValuationService.supportsHoldings()` 放开到 **WEALTH / CASH**(现仅 STOCK/CRYPTO/METAL)。
  2. 加**可空**持仓级标签列 `asset_class_tag`(+ 视需要 `risk_tag`/`liquidity_tag`);为空时回落账户级标签 —— 老 STOCK 持仓不受影响。
  3. `sync_source` 允许取值 `SCREENSHOT`。
- **不做**:不新建 `fund_holding` 表、不 rename `stock_holding`(见 TDD 取舍)。

## 9 · 线上历史数据如何兼容(关键)

线上已有 WEALTH/CASH 账户带多期历史 `period_snapshot`(单一余额)。导入持仓**复用 STOCK 账户既有的「有持仓即接管估值」机制**,历史不动、曲线不断:

- **历史期不回溯**:P1…P(n-1) 的 `period_snapshot`(用户手填的单一余额)**原样保留**,净值曲线该段完全不变。
- **当期交接**:在**当前 OPEN 期**导入持仓后,`AccountValuationService` 算 Σ持仓 → **写回当期 snapshot**(与 STOCK 同,note 标「系统估值」),此后该账户由持仓估值当家。
- **防跳变靠 FR-8 对账**:导入时展示 Σ持仓 vs 账户当前余额,用户对齐(补现金/其他行)→ 当期 Σ持仓 ≈ 实际余额 → MoM 收益不出现虚高/虚低尖峰。
- **红线(承既有)**:账户**没有持仓时,系统绝不碰它的手填 snapshot**(`holdings.isEmpty() → skip`);已关账的历史期不改。
- **收益口径**:交接当期的 MoM 可能有一次性的口径校准(手填粗值 → 持仓精算),属正常且更准;之后精确。TDD 会给「交接期收益」说明与 e2e 断言曲线不断。
