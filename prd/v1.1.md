# PRD · v1.1 · 资产透视(多维打标 + OLAP-lite 下钻)

> 承 v0.17 封板 v1.0.0 后的第一个 v1.x 特性。把"孤立的单维视图(体检一张图 / 配置一个环 / KPI 一堆卡)"升级为**可按任意维度切片 + 下钻的资产透视**。前提是给资产补更多**结构化标签(维度)**。
> **坚持理念**:每月 10 分钟、快照式;**近似打标不做基金成分穿透**;**要 OLAP 的交互(切片/下钻/换维),不上 OLAP 的重型引擎**(单家庭 <50 账户 / <200 持仓,内存 group-by 毫秒级)。

## 1. 背景与动机

- 用户原话:"我们对资产的分析诊断依然不够,要给账户做更多维度的打标——目前只做了①类型②风险。用户想看自己的资金归属哪些行业、能不能多种下钻;比如先看风险分布,再进高资产看里面,再看行业分布,可能需要一个 OLAP 的分析。"
- 现状只有 2 个可分析维度(**类型**、**风险**),且每个分析是孤立视图,不能"这个维度看完换那个维度、点进去再拆"。
- 业界(蚂蚁财富 / 雪球 / 天天基金 / 银行理财)的核心做法:**在最细粒度(持仓/基金成分)打行业/风格/地域标签,聚合时按维度 group-by**,并支持持仓穿透 + 大类资产诊断 + 缺口分析。行业分析天生是**持仓级**的事。

## 2. 理念坚持(设计红线)

1. **近似打标,不做成分穿透**:基金/理财是跨行业一篮子,精确穿透需基金成分数据源(我们没有、且违背 10 分钟理念)。做法:**个股持仓标到具体行业(准);基金/理财/手填账户给"主题/宽基"粗标(近似)**。UI 明说这是"账户/持仓级打标的近似",不给假精确(承 [[feedback_llm_no_math]] + [[feedback_decision_weight_honesty]])。
2. **OLAP-lite**:采用切片/下钻/上卷/换维的**交互模型**,用内存 group-by 实现;**不引入 Druid/Kylin/ClickHouse 等 OLAP 基础设施**。
3. **复用既有维度**:类型 / 风险 / 流动性 / 币种 / 主理人 / 市场(持仓 Market)已存在,直接接进透视;只**新增行业、大类、平台**三个维度。
4. **面向用户友好命名**(承 [[feedback_user_friendly_naming]] + [[feedback_no_emoji]]):维度/行业用家庭成员看得懂的中文;图标 inline SVG。

## 3. 功能需求(FR · 用户视角)

### FR-1 · 多维打标(补足分析维度)
给资产补三个新维度,连同既有维度构成透视基础:

| 维度 | 现状 | 本版打在哪 |
|---|---|---|
| 类型 / 风险 / 流动性 / 币种 / 主理人 | 已有 | 账户(直接接入透视) |
| **大类资产**(现金 / 固收 / 权益 / 另类 / 不动产 / 保险) | 新增 | 账户级,可由 类型 + 产品类目 派生默认,允许覆盖 |
| **平台 / 机构**(招行 / 支付宝 / 富途 / 中国人寿 …) | 新增 | 账户级标签(现在藏在账户名里 → 结构化) |
| **行业 / 主题**(白酒 / 新能源 / 医药 / 宽基 …) | 新增 | 个股持仓级(准)+ 手填/基金账户级粗标(近似) |
| 市场 / 地域(A股 / 美股 / 港股 / 加密 / 贵金属) | 持仓已有 Market | 持仓(接入透视) |

- 打标入口:账户编辑页 + 个股持仓编辑页,**全部可选、有合理默认**(不打标也能用,退化到"未分类")。
- 内置一份**行业清单**(约 10–12 个家庭友好的粗行业,非 GICS 全集),避免选择过载。

### FR-2 · 资产透视页(OLAP-lite · 新页面)
一个新的「资产透视」页(挂在报表 / 体检旁):
- **选主维度**(风险 / 大类 / 行业 / 平台 / 类型 / 主理人 / 地域…)→ 分布图(环形 + 条形,金额 + 占比,数字浮图上,承 [[feedback_chart_datalabels]])。
- **下钻**:点某一片(如"高风险")→ 进入该切片,**在切片内换维度**再看(如"高风险资产里的行业分布")→ 面包屑记录路径(`风险=高 › 行业=?`),可逐级回退。
- **度量切换**:金额 / 占比 /(选做)收益率 / 收益额 —— 后者回答"哪个行业 / 平台最赚"。
- **币种无关**:占比类三币种一致、金额按 fx 缩放(承 [[feedback_currency_invariance]])。
- **空态友好**:维度未打标时显示"未分类 X%"并引导去打标(承 v0.16 空态巡检精神)。

### FR-3 · 体检增强(用新维度做诊断 · 喂 AI)
资产体检新增两类集中度诊断:
- **行业集中度**:单一行业占权益 > 阈值 → 预警(如"新能源占权益 65%,行业过度集中")。
- **平台集中度**:单一平台占总资产 > 阈值 → 预警(平台 / 信用风险,如"70% 在支付宝")。
- 这些结构化结论喂给 AI 洞察 → 更**可执行**的建议(承接你 Q2 选的"AI 诊断更可执行");阈值走管理页可配(承 [[feedback_admin_runtime_config]])。

## 4. 用户故事
- 「我想知道资金归属哪些行业」→ 透视页选"行业"→ 环形显示 新能源 32% / 消费 20% / 宽基 18%…。
- 「先看风险,再看高风险里都是什么行业」→ 选"风险"→ 点"高风险"→ 切"行业"→ 看到高风险几乎全是新能源 → 体检提示行业过度集中。
- 「我在支付宝到底放了多少」→ 透视选"平台"→ 支付宝 45%。

## 5. 非目标(明确不做 · 坚持理念)
1. **不做基金成分穿透**(无稳定数据源;账户/持仓级近似打标)。
2. **不上 OLAP 重型引擎**(内存 group-by)。
3. **v1.1 不做变化归因 / 情景分析 / 回撤压测**(留 v1.2 / v1.3;本版聚焦"打标 + 透视 + 集中度")。
4. **不强制打标**(可选 + 默认 + "未分类"退化)。

## 6. 待你拍板的决策(评审 gate)
- **D1 · 行业粒度**:内置约 10–12 个粗行业(推荐,防选择过载)vs 更细(GICS 式)?
- **D2 · 平台标来源**:手填 / 下拉选(推荐,结构化准)vs 从账户名自动派生(省事但脏)?
- **D3 · 透视度量是否含"收益率/收益额"**:含(更有用,但需按每维度归集收益,较重)vs v1.1 先只做金额/占比、收益维度留 v1.2(推荐)?
- **D4 · 大类资产是否作独立维度**:是(权益/固收/另类… 业界标配,推荐)vs 复用"类型"够了?

## 7. 影响面 / 复用(概览 · 详见后续 tech-design)
- **复用**:`product_category`(已有 risk/liquidity/benchmark,可扩行业/大类属性)、`AllocationDiff` 分组、`allocationByType`、体检集中度、FX、图表 datalabels。
- **新增**:行业 / 大类 / 平台 三维度的存储(账户级 + 个股持仓级)+ 内置行业清单 + 资产透视页(纯函数 group-by + 下钻状态)+ 两条集中度体检规则。
- **迁移**:纯新增可空标签列 + 种子,**向后兼容**(承 [[feedback_prod_backward_compat]];未打标 = 未分类,零影响)。
