# PRD · v1.1 · 资产透视(多维查询网关 + 交叉透视表 + 旭日下钻)

> 从"一个透视页"抬升为**内存版语义层 + pivot 引擎**:后台一个通用「多维查询网关」,前端所有分析组件(旭日图 / 交叉透视表 / 条形 / 明细)+ 用户完全自由的查询,**全部架在这一个接口上**。
> **坚持理念**:每月 10 分钟、快照式;**内存 group-by**(单家庭 <200 头寸,毫秒级),**不上外部 OLAP / BI 平台**;**近似打标不做基金成分穿透**;**移动端一等公民**。

## 1. 背景与动机(诉求合并)
- 现状只有 2 个分析维度(类型、风险),且每个分析是孤立视图,不能"换维度看、点进去再拆、行列交叉"。
- 用户诉求(逐条):① 真正的**多维下钻**,不止单维饼图;② 类似 **Excel 交叉透视表**(什么维度在行 / 在列);③ **默认策展看板** + 用户**完全自由查询**;④ 后台一个**统一多维查询网关**,前端所有组件都架在上面;⑤ 饼图**二次下钻**(点一块继续钻,环外再生成第二层环 = 旭日图);⑥ 能**下钻到明细**(明细 = 账户 / 持仓);⑦ **兼容手机端**。
- 业界(蚂蚁 / 雪球 / 银行理财):最细粒度打标 + 按维度聚合 + 持仓穿透 + 大类诊断。行业分析天生是持仓级的事。

## 2. 理念红线(设计约束)
1. **内存语义层,不上外部 OLAP**:自建"维度 / 度量注册表 + 通用 pivot 网关",内存 group-by;不引入 Druid / Kylin / ClickHouse / Superset。
2. **近似打标,不做成分穿透**:个股标准行业(准),基金 / 理财 / 手填账户给主题粗标(近似);UI 明说是近似,不给假精确(承 [[feedback_llm_no_math]] + [[feedback_decision_weight_honesty]])。
3. **一个网关撑起所有分析**:不为每种图 / 每个看板写专用后端;新组件 = 发一个 query spec。
4. **移动端一等公民**:旭日 / 透视表 / 明细都要有可用的手机交互(承 [[feedback_verify_user_path]] 移动视图)。
5. **友好命名 + inline SVG**(承 [[feedback_user_friendly_naming]] + [[feedback_no_emoji]])。

## 3. 功能需求(FR · 用户视角)

### FR-1 · 多维打标(维度基础 · 前置)
给资产补三个新维度,连同既有维度构成透视基础:

| 维度 | 现状 | 打在哪 |
|---|---|---|
| 类型 / 风险 / 流动性 / 币种 / 主理人 | 已有 | 账户 |
| **大类资产**(现金 / 固收 / 权益 / 另类 / 不动产 / 保险) | 新增 | 账户级(可由 类型 + 品类 派生默认,可覆盖) |
| **平台 / 机构**(招行 / 支付宝 / 富途 / 中国人寿…) | 新增 | 账户级标签 |
| **行业 / 主题**(白酒 / 新能源 / 医药 / 宽基…) | 新增 | 个股持仓级(准)+ 手填 / 基金账户级粗标(近似) |
| 市场 / 地域(A股 / 美股 / 港股 / 加密 / 贵金属) | 持仓有 Market | 持仓 |

- 全部可选、有默认;未打标退化为「未分类」。内置约 10–12 个家庭友好粗行业(非 GICS 全集)。

### FR-1b · AI 推荐打标(入口 · 显式接受,已拍板 D4)
- 打标页提供「AI 推荐」入口:把**未打标**的账户名 / 持仓名(如「招行储蓄卡-工资」「宁德时代」)交给现有 LLM 接入,**推荐** 平台 / 行业 / 大类 标签。
- 结果以**待确认清单**呈现:逐条 接受 / 修改 / 忽略,或"全部接受"。**绝不静默写入**(承贷款预填教训:系统猜的必须显式接受)。
- 分类是 LLM 擅长域,不涉数学(不违反 [[feedback_llm_no_math]]);LLM 不可用时入口降级隐藏,手动打标始终可用。规则默认(类型→大类派生)独立于 AI,始终生效。

### FR-2 · 统一多维查询网关(后台 · 一个接口撑起所有分析)
- **通用查询接口** `POST /lens/query`:输入 `{ 行维度[], 列维度[], 度量[], 筛选{维度:[值]}, 期次 }` → 输出**交叉表结果**(行键 × 列键 × 度量值 + 行 / 列小计 + 总计 + 每格的头寸 id 列表(供钻明细))。
- **事实模型 = 头寸(position)粒度**:手填账户 = 1 头寸(快照余额);持仓账户 = N 头寸(每个持仓市值)。每头寸挂满维度标签 + 度量(金额本位币…)。全家 <200 头寸,内存 group-by。
- **维度 / 度量注册表**:每个维度、度量**注册一次**(名字 + 取值函数 + 排序);之后网关、透视表、旭日、看板、自由查询、任何新组件**自动支持它**——加维度只在一处登记(承 [[feedback_enum_add_sweep]] "一处网住整类")。
- 币种无关:占比类三币种一致、金额按 fx 缩放(承 [[feedback_currency_invariance]])。

### FR-3 · 旭日图多层下钻(饼图二次下钻)
- 内环 = 主维度(如 风险)全部切片。**点某切片(如 低风险)→ 环外长出第二层环**,是该切片按"下一维度"(如 拥有者)的分解。
- 可继续往外钻 / 或**点中心上卷**返回;面包屑记录路径(`风险=低 › 拥有者`)。
- 用 **ECharts sunburst**(项目已带 echarts)· 触摸响应 · 数据标签浮环上(承 [[feedback_chart_datalabels]])· **移动端限 2 环 + 面包屑**,防拥挤。

### FR-4 · 交叉透视表(Excel 式行列自由摆)
- 用户自选**什么维度在行、什么维度在列、看哪个度量、加什么筛选**(如 行=风险、列=行业、度量=金额),行 / 列可多层。
- 渲染交叉矩阵:单元格 = 度量值 + **行 / 列小计 + 总计**,单元格**热力着色**(值越大越深),一眼看出交叉集中。
- **点单元格 → 下钻明细**(FR-5)。移动端:横向滚动 + 冻结行头。

### FR-5 · 下钻到明细(叶子 = 头寸 → 账户详情)
- 任何聚合(透视格 / 旭日块 / 条形)钻到底,展开的是落在该切片的**头寸明细列表**:账户 + 个股持仓 + 金额(如「高风险 × 新能源」→ 宁德时代持仓 ¥800K · 富途证券)。
- 每条头寸**点进去 = 现有的账户详情页**(复用,不新建明细页)。→ 明确回答"明细是否就是账户明细":**叶子是头寸,头寸落到既有账户明细页**。

### FR-6 · 预设看板(5 块策展)+ 自定义透视
预设看板按"家庭用户真实关心的问题"倒推,每块 = 一组 query spec(旭日 + 透视表 + 明细同时切换),**非硬编码页面**:

| # | 看板 | 回答的问题 | 旭日 | 透视表 |
|---|---|---|---|---|
| 1 | **风险总览**(默认) | 钱的风险结构摆得对不对 | 风险 → 大类 | 风险 × 大类 |
| 2 | **行业集中** | 是不是押注单一行业 | 行业(筛权益) | 行业 × 平台 |
| 3 | **平台安全** | 鸡蛋是不是都在一个篮子 | 平台 | 平台 × 大类 |
| 4 | **夫妻结构** | 夫妻各自管的钱什么样(本产品特色场景) | 主理人 → 风险 | 主理人 × 大类 |
| 5 | **币种与市场** | 汇率 / 地域暴露多大 | 币种 | 市场 × 行业 |

- **自定义透视**:「+ 自定义」构建器 —— 把维度 chip 拖进 行槽 / 列槽 / 度量槽 / 筛选槽 → 即时出表 → **存为我的看板**(出现在看板 chip 行,与预设并列)。

### FR-6b · 页面组件布局(默认 4 组件 + 1 自由区 · 全部联动)
资产透视页一页式布局,所有组件吃**同一个 drill-path**(筛选栈),点谁都联动:

- **看板 chip 行**(顶部):5 预设 + 用户自存 + 「+ 自定义」;下方**面包屑**显示当前 drill-path。
- **组件 A · 旭日图**(主视区,左 ~60%):当前看板的主维度;点块 → 外环下钻;点中心 → 上卷。
- **组件 B · 切片排行**(右 ~40%):当前切片下按"下一维度"的排行条形(金额 + 占比),与旭日同步。
- **组件 C · 交叉透视表**(全宽):热力 + 行列小计;**行 / 列 / 度量 chip 可直接拖拽换维**(自由分析入口之一)。
- **组件 D · 明细抽屉**(全宽,默认折叠):当前切片的头寸明细(→ 账户详情);点透视格 / 旭日块自动展开对应明细。

**用户自由度所在**:① 组件 C 的 chip 区随时拖换行 / 列 / 度量;② 「+ 自定义」构建器建自己的看板;③ 旭日下钻时可选"下一层按什么维度展开"。

### FR-7 · 体检增强(用维度做集中度诊断 · 喂 AI)
- **行业集中度**(单一行业占权益 > 阈值)、**平台集中度**(单一平台占总资产 > 阈值)预警;阈值走管理页可配(承 [[feedback_admin_runtime_config]]);结构化结论喂 AI 洞察 → 更可执行(承 Q2 "AI 诊断更可执行")。

## 4. 用户故事
- 「先看风险,低风险里是谁的钱」→ 旭日内环选风险 → 点低风险 → 外环按拥有者 → 迪娃 60% / 妻子 40%。
- 「高风险 × 新能源 里到底是哪些标的」→ 透视表 行=风险 列=行业 → 点「高风险×新能源」格 → 明细:宁德时代 ¥800K(富途)→ 点进账户详情。
- 「我在支付宝放了多少、都是什么大类」→ 透视 行=平台 列=大类。

## 5. 交互设计要点(全组件共用一套下钻模型)
- **一套 drill-path**:所有组件共享"筛选栈(维度=值)+ 当前分组维度",面包屑统一展示、可逐级回退。
- **组件联动**:切了筛选 / 钻了一层,旭日 / 透视 / 明细 / 体检都跟着同一 drill-path 走。
- **移动端**:旭日 ECharts 触摸 + ≤2 环 + 面包屑;透视表横滚 + 冻结行头;明细为卡片列表;顶部维度 / 度量选择器改为可横滑 chip。

## 6. 非目标(明确不做)
1. 不上外部 OLAP / BI 平台(自建内存语义层)。
2. 不做基金成分穿透(账户 / 持仓级近似打标)。
3. **度量定稿 5 个**(已拍板 D5,从现有指标体系选):①金额(本位币现值)②占比 ③本期收益额(latestPnl)④累计收益额(cumPnl)⑤累计收益率(Σ累计收益 / Σ净投入 · 加权比值 · 币种无关)。**不做年化 XIRR 聚合**(跨账户 XIRR 不能简单平均,硬聚合 = 假精确);收益归因粒度按头寸可得性诚实降级(个股 AUTO 持仓可算持仓级,手填账户为账户级,算不出的落「未归因」,详见 tech-design)。
4. v1.1 不做变化归因 / 情景分析(留 v1.2 / v1.3)。
5. 不强制打标(可选 + 默认 + 「未分类」退化)。

## 7. 决策(已全部拍板 · 2026-07-15)
- **D1 = 全做**:网关 + 打标 + 旭日 + 交叉透视表 + 明细 + 预设看板,一次打起能力底座。
- **D2 = 自定义透视同期做**(拖行列 / 存看板)。
- **D3 = 粗分**:~10–12 个家庭友好粗行业。
- **D4 = AI 推荐 + 手动调整**:保留 AI 推荐默认选型入口(FR-1b),用户显式接受 / 修改;手动打标始终可用。
- **D5 = 5 个度量**:金额 / 占比 / 本期收益额 / 累计收益额 / 累计收益率(见非目标 §3 的口径与降级)。
- **D6 = 5 块预设看板通过**(风险总览 / 行业集中 / 平台安全 / 夫妻结构 / 币种与市场)。

## 10. 打标维度体系 Review(2026-07-16 · 已拍板)

> **拍板结果(2026-07-16)**:①「大类资产」维度更名**「资产类型」**(原「类型」维度联动更名「账户类型」以免混淆);②平台/机构 = **A 保留现状**;③行业清单 = **A 语义定为「投向」保留混合清单**;④其余维度与维值通过。
> 附加展示要求:旭日下钻**同一维值全局同色**(值→色稳定哈希,"高风险"在任何环/任何看板同色,切片排行同步)。
> **修订(2026-07-16 · 用户评审)**:内外环本质是两个独立维度,共用一套色系导致层级不可辨 → 改为**每环一套独立配色**(内置深/浅两套:内环深调定基调、外环浅调作铺陈),**环内**仍旧同维值同色(稳定哈希,"高风险"在本环任何父块/任何看板下同色);切片排行按外环维度排行,同步用外环色系。
> **修订二(2026-07-16 · 配色方案化 + 信息可见性)**:
> ① 环级配色升级为**五套内置方案**(A 飞书 VChart 官方原味 / B 外环原版内环压墨 / C 色相错位 / **D 莫兰迪高级灰=默认** / E 国风传统色),`/admin/calc-tweaks` 管理页 radio+色卡即改即生效(FamilyConfigService 热配,白名单校验脏值回落 D);preview 见 `preview/v1.1/sunburst-palette.html`。
> ② 旭日**比例/金额可见性**(用户无法看清比例金额 → 参照饼图 datalabels 铁律):扇区常显「名称+占总比」,角度 ≥28° 且非隐私模式再加短金额(¥98万/¥1.02亿);**中心信息盘**(内洞 18%→26%)默认显当前范围合计,hover 任一环扇区实时显示该块 名称/金额/占比 —— 内环金额扇区里放不下,由中心盘补齐(双环难点的解法);隐私模式下 canvas 金额不绘制(CSS blur 管不到 canvas),开关切换经 MutationObserver 自动重绘,中心盘金额带 data-priv 照常模糊。
> **补充(2026-07-17 · 小扇区可见性)**:角度 < 14° 的小块 label 被 minAngle 隐藏 → **Excel 式引导线**:PC 端 graphic 自绘折线从块中心拉到圆外空白(色点+名称+占比,左右分侧、纵向避让每侧 ≤8 条,外半径收窄至 76% 腾空间,占比 <0.1% 的趋零块不拉线防噪);移动端外侧放不下文字,退化为图下「小块」补注清单,信息等价。ECharts sunburst 原生无 labelLine,故自绘。
> **修订三(2026-07-16 · TUI 拍板:命名平民化 + 行业修订 + 自研搜索下拉)**:
