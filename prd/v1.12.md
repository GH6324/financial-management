> 状态:**PRD 待评审**(2026-08-14)
> 目标版本:`app.version = 1.12.0`(已 bump)
> 前置:v1.10(封板骨架 + 单一入口 `SealedPeriodService`)· v1.11(指标审计,查出 F4 / F5)

## 0 · 这一版在解决什么

v1.10 给报表页立了一条产品承诺:**已关账的月份是封板快照,不再变**。
v1.11 的指标审计把这条承诺逐项验了一遍,结论是「**在账户属性不变的前提下**可证」——
括号里那个前提就是 F4,这一版要把它拿掉。

同时把 v1.11 明确记为「没做完」的性能债还上:报表页单请求仍有约 761 条 SQL,
上一版卡在**定位不到是谁发的**,这一版先补采样手段,再修。

两件事放同一版,是因为它们动的是同一片代码(事实层的取数路径)。分开做等于把同一片代码翻两次。

## 1 · FR 清单

### FR-350 · 已关账月份的分类归属不再被今天的设置改写(修 F4)

**现象**:今天在管理页把某个账户的产品类目从「货币基金」改成「债基」,
**全部历史月份**的下列指标当场跟着变:

- 集中度 / HHI
- 流动性分层,以及由它派生的紧急储备月数
- 资产大类分布 / 按类型分布
- 账户级「vs 基准」(基准 % 来自产品类目)

金额一分没变,变的是分类归属。也就是说**3 月打印的月报,和 8 月重新渲染的同一个月,可能对不上,而且不报警**。

**根因**:金额侧的事实全都按期落库了(余额 / 收支 / 汇率 / 持仓估值都是 per-period 的),
但分类侧不是 —— 事实查询是拿**当前**的账户行和产品类目行去 join 每一期的数据。

**要求**:关账时把该账户当期的分类属性一并定格;已关账期的指标从此只认定格值。

**规则**(需要维护者确认这三条):

| 情形 | 行为 |
|---|---|
| **已关账期** | 用关账那一刻定格的分类属性。之后改账户设置,历史不动 |
| **未关账的当期** | 跟着当前设置走(和「仪表盘 = 实时」的分工一致) |
| **重开后再关账** | **重新定格**,以重新关账那一刻的属性为准。理由:重开就是「这期还要改」,改完重新封板才是用户意图 |

**验收**:
1. 改一个账户的类型 / 产品类目 → 已关账期的上述四类指标**逐字不变**;当期跟着变。
2. 页面底部那句漂移说明(`driftNotes`)改成如实描述新行为,不再说「会改写历史期」。

**这条必须说清的取舍**:定格是**从这一版生效**的。已经发生过的漂移**追不回来** ——
「当时的属性是什么」这个信息从来没被记录过,回填只能拿今天的属性去填。
所以回填出来的历史 = 今天算出来的历史,**和现状完全一致**。
这一版兑现的是「**从此不再变**」,不是「修正过去」。这句话要如实写进页面说明,不许含糊。

（这个性质同时给了最强的验收手段,见 §3 第 1 条。)

### FR-351 · 有办法知道一次请求发了哪些 SQL

**现象**:v1.11 把最大的一个 N+1 修掉后(881 → 761 条),剩下的定位不动 ——
`SHOW GLOBAL STATUS LIKE 'Questions'` 只给总数增量,知道有 761 条,不知道**哪 761 条**。

**要求**:能按请求聚合、能指认到**具体的 mapper 方法**、能看出谁被调了几百次。

**约束**:
- 只在 beta 开,prod 默认关 —— 开关走**管理页**,不写服务器配置文件(项目铁律)。
- 关闭状态下对正常请求**零开销**(不是「开销很小」,是不进这条路径)。

**验收**:在 beta 上打开开关访问报表页,能拿到一份「mapper 方法 → 调用次数 / 耗时」的排序清单。

### FR-352 · 消掉剩余的 N+1

**要求**:拿 FR-351 的清单逐个看,把重复查询收成批量取数。

**验收**:给出**优化前 / 后的实测** SQL 条数与中位耗时(和 v1.11 一样,不接受只说「优化了」)。
不预设目标数字 —— 先看清单再定,清单出来后把目标写进 tech-design。

**关联**:如果某个 N+1 正好被 FR-350 的定格表顺手消掉(分类属性不用再逐行 join),
要在 tech-design 里说明,不要重复计功。

### FR-353 · 储蓄率等比率在数据不足时不显示荒谬数字(修 F5,搭车)

**现象**:prod 收支数据稀疏(逐笔收支只有个位数行),储蓄率算出 **−2383%** 这类值。
口径没错,是分母太小。但页面上摆一个 −2383% 会让人以为系统坏了。

**要求**:比率类指标在 `|值| > 500%` 时显示为「收支数据不足」并给补录入口,而不是一个数字。

**验收**:阈值落成常量、有护栏;正常范围的值显示不受影响。

> 这条是搭车做的小修,**如果评审觉得会拖慢主线,可以砍掉挪到下一版** —— 它不影响 FR-350/351/352。

## 2 · 非目标

- **不做 v1.10 §2.3 方案 C 的完整指标落库**。那个方案是把**算好的指标值**落成 KV 快照,
  它要一整套读侧双轨 + 重新封板入口 + 权限审计,复杂度和一次 UI 大改相当。
  这一版只冻结**分类输入**,不冻结**指标输出** —— 这样保住了 v1.10 明确珍视的那条性质:
  **口径改了自动对全部历史生效**(v1.9.4 那种「一改就全对」的修复靠的就是它)。
  冻输出会把口径 bug 一起冻住,以后改口径 = 历史全废。
- **不改两页分工**(仪表盘 = 实时 / 报表 = 封板)。
- **不做「重新封板」的独立权限与审计体系** —— 现有的重开(reopen)已经留痕,够用。
- **不加新页面、不做新图表**。所以这一版**没有 preview** ——
  唯一的界面改动是漂移说明那句话的文案,和 FR-353 的一个降级文案。
  (如果评审认为需要看这两处文案的预览,说一声,我补。)

## 4 · 风险

| 风险 | 处置 |
|---|---|
| 回填脚本在 beta 的 ~175 期上跑很久 / 在 prod 的 3 期上没验到边界 | 回填做成幂等,先在 beta 全量跑并对零差异基线;prod 部署前单独验一次 |
| 定格表和账户表不一致(比如账户被删) | 定格表只存值不存外键约束到 product_category(类目可能被删),账户走软删已有语义 |
| 读侧双轨(有定格读定格 / 没有回落实时)漏一处 | 收在 `SealedPeriodService` 单一入口 —— v1.10 特意为这次改动准备的;落 grep 护栏钉住不许绕过 |
| 两件事同版翻车(v1.8 的教训) | 零差异基线是这一版的**分水岭**:先把 FR-350 做到零差异,再动 FR-351/352 的性能。差异一出现就停下查因 |
