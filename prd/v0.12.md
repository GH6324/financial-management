# PRD · v0.12 · 收入录入重构:账户级多笔明细 · 支持全资产类型 · 直接入账留流水

> 状态:**待评审(PRD + preview 阶段)** · 对应 preview `preview/v0.12/income-entry.html`
> 评审通过后再出 `tech-design/v0.12.md`。

## 背景 / 痛点(用户原话拆解)

真实用户是互联网工程师:除现金外还有**股票收入**(工资入券商、股息、RSU 归属、利息)。当前收入录入两处脱节、且不支持非现金:

1. **要录两次**:填报页顶部「第一步·我的本月收支」填家庭总收入(写 `period_member_cashflow`,PMC「2框」,不关联账户、不改余额);要让钱真正进到某个账户,还得去该账户行点「+收入」再录一次(写 `cash_flow` + 改该账户期末余额)。同一笔收入录两遍。
2. **不支持股票类型收入**:账户行的「+收入」类目被**硬编码成「工资」**,没有股息/利息/RSU 等类目;用户对股票账户往往干脆**直接改期末余额**。
3. **改余额 → 收益率虚高**:系统 `PnL = ΔNW − 净流入 − 净划转`。直接把股票余额调高(不记一笔收入现金流),这笔本金流入就被当成「投资赚的」,收益率(XIRR/钱赚)被高估。

> 机制现状(已探明):账户级「+收入」其实**已经**做对了三件事 —— 写 `cash_flow` 流水、`applyDeltaToBalance` 加到期末余额、作为外部流入被 PnL 正确剔除;且**不限账户类型**。缺的是:①能选类目(尤其非现金类)②单账期多笔的顺手录入面 ③和「2框」不再重复 ④人赚/储蓄率能从这份明细汇总出来(而不是另填 PMC)。

## 核心原则(决定整套设计)

- **一次录入,处处正确**:一笔收入只录一次(金额 + 类目 + **目标账户**),系统同时完成:入该账户当期余额、留一条流水、算进家庭「人赚/净流入/储蓄率」。杜绝「2框 + 账户 +收入」双录。
- **所有资产类型都可收**:现金 / 股票 / 理财 / 房产 / 其他都能作为收入的落点(LOAN 除外,见非目标)。类目按语义扩展(工资 / 奖金 / 股息 / 利息 / 租金 / 报销 / 经营 / 其他)。
- **收入=外部流入,不是投资收益**:凡走「收入」入账的,一律记为外部净流入 → 不计入 PnL → 收益率不虚高。这正是替代「直接改股票余额」的关键价值。
- **10 分钟不变**:录入更顺(一个区块连续加多笔),不是更繁。既有「余额校准」仍是期末真值来源;收入明细是对「余额为什么变」的解释。

## 功能需求(FR)

### FR-140 · 本期收入 = 账户级多笔明细
- 填报页新增/重构「本期收入」区:可在**当前 OPEN 账期**连续录入**多笔**收入明细行。
- 每行 = `金额` + `类目`(下拉) + `目标账户`(下拉,列全家活跃非 LOAN 账户) + `备注`(选填) + `日期`(默认本期,可选)。
- 保存单行即入账(见 FR-142),可继续加下一行;本期已录的收入明细以列表展示。

### FR-141 · 收入支持全资产类型 + 类目扩展
- 目标账户可为 现金 / 股票 / 理财 / 房产 / 其他(任意非 LOAN 类型)。
- 类目扩展(新增到 `cash_flow_category`,kind=INCOME):工资、奖金、**股息/分红**、**利息**、**投资赎回/卖出回款**、租金、报销、经营、其他收入。类目仅作标注与分析,不改变「外部流入」性质。
- (可选增强)按目标账户类型给类目**智能默认/排序**:股票账户默认「股息」、现金账户默认「工资」、房产默认「租金」。

### FR-142 · 直接入账 + 留流水(替代改余额)
- 保存一笔收入 → ①写一条 `cash_flow`(INCOME,含 account_id、category、amount、note)②把该账户**本期期末余额**加上该金额(`applyDeltaToBalance`)③在该账户「本期流水」与「跨期流水档案」中可见。
- 该笔作为**外部净流入**参与恒等式,**不进 PnL** → 股票账户收股息不再抬高收益率。
- 与「余额校准」共存口径:期末余额仍是用户最终填的真值;收入明细解释其中「外部进来的」部分,未被收入/支出/划转解释的余额变动才归为投资损益(沿用现有 `unexplained`/PnL 口径,不改恒等式本身)。

### FR-143 · 单一录入源 · 消除「2框 + 账户」双录
- 家庭「人赚 / 净流入 / 储蓄率 / 月均收入」由**本期收入明细汇总**得出(替代「2框」的「总收入」手填)。收入只在明细里录一次。
- 「2框」顶部区调整(**待评审拍板**,见下方决策 A):推荐**收入侧退成明细汇总(只读展示家庭本月总收入=SUM 明细)**;支出侧本迭代先保留成员「本月总支出」快填(见决策 B)。
- 防重复计入:净流入口径切到「收入明细 − 支出」后,`pmcFirstNetInflow` / `cashflowBreakdown` / 储蓄率 三处同步改,避免 PMC 与明细同时计入(承接历史「决策 B」的反向调整)。

### FR-144 · 明细可编辑 / 删除(可逆)
- 本期任一收入明细行可删除/改额:删除即**冲回**其对该账户余额的加值 + 移除对应 `cash_flow` 流水;改额按差额调整。保证「录错能改」。

### FR-145 · 关账后只读
- 已 CLOSED 账期的收入明细只读展示(与现有关账语义一致);补录需走重开账期(现有能力)。

## 待评审的关键决策(请你拍板)

- **决策 A · 「2框」收入侧怎么处理**:
  - A1(推荐)**收入侧改由明细汇总**:顶部不再手填「总收入」,而是显示「本月家庭总收入 = SUM(收入明细)」;录入完全在明细区完成 → 彻底消除双录。
  - A2 保留「总收入」快填作为「懒人整月一个数」入口,但**填了明细就以明细为准**(总收入框置灰/隐藏)。
- **决策 B · 支出这迭代动不动**:
  - B1(推荐)本迭代**只重构收入**;支出维持现「2框·本月总支出」快填(支出没有「股票类型」痛点,先不扩;人赚 = SUM 收入明细 − 总支出)。
  - B2 支出也同步做成账户级明细(对称,但工程量翻倍、且改支出的净流入口径风险更大)。
- **决策 C · LOAN 账户**:收入不落 LOAN(还贷是「划转/支出」,不是收入);目标账户下拉排除 LOAN。是否同意?
- **决策 D · 每笔收入是否要归属成员**:PMC 是成员级(支撑各成员储蓄率)。收入明细按「目标账户的 primary owner」自动归属成员即可,还是要在行内单独选成员?(推荐前者:账户已有 owner,少一步。)

## 非目标 / 已知局限

- 不做逐日流水账(仍是月度快照 + 当期外部现金流的定位)。
- 不做股票「按持仓自动算股息」;股息仍手工录一笔收入(金额用户填)。
- LOAN 账户不作为收入落点。
- 历史 PMC 数据迁移:老账期的 PMC「2框」保持只读历史,不强制回填成明细(tech-design 定迁移/兼容策略)。
- 不改净资产/收益的恒等式本身,只改「收入怎么录入 + 净流入从哪汇总」。

## 验收标准

1. 填报页「本期收入」可连续录入多笔(不同账户、不同类目),每笔即时入账并出现在该账户本期流水。
2. 对**股票账户**录一笔「股息 ¥X」→ 该账户期末余额 +X、流水多一条 INCOME、且该账户/家庭 XIRR 与「钱赚」**不因这笔上升**(它是外部流入,不是投资收益)。
3. 家庭「人赚/净流入/储蓄率」= 收入明细汇总(− 支出),与逐笔明细对得上;同一笔不被 PMC 与明细重复计入。
4. 删除一笔录错的收入 → 账户余额冲回、流水移除、家庭汇总同步回退。
5. 收入不再需要「2框 + 账户 +收入」两处各录一遍(单一入口)。
6. 现金/股票/理财/房产账户都能作为收入落点;LOAN 不在下拉。
7. 关账期收入明细只读;移动端可顺畅录入。
8. 不破坏既有:余额校准、划转、净资产/PnL 恒等式、币种不变性。
