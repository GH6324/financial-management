# PRD · v0.12 · 收支填报「收入侧」升级:结构化录入 · 关联账户 · 直接入账(约束:只收入 + 现金/股票)

> 状态:**精化中(股票收入 = 持仓版)** · 对应 preview `preview/v0.12/income-stock-journeys.html`(现金侧仍见 `income-entry.html`)
> 定位红线(memory `project_finance`):账户级颗粒度 · 10 分钟/月 · 不是流水/记账 APP · 不做逐笔明细账。
> **本迭代 = 现有「收支填报(2 框)」的收入侧升级**,不是新建明细账模块,不动支出侧,不做全类型。
>
> **v0.12.0→精化增量(本轮)**:股票收入从"填一个金额"改为**对齐股票账户「余额变动」的持仓机制**——先选类型(现金/股票),股票则选账户 → **联动该账户已有持仓**,按持仓入账(上市/未上市都录**股数**、券商现金录金额)。为此**未上市(MANUAL)持仓升级为「股数 × 单股估值」**。**卖出回款不再算收入**(见 FR-144/非目标)。

## 背景 / 要解决什么

现在录一笔收入很割裂,且股票收入录不进:
1. **双录**:填报页「第一步·我的本月收支」填家庭总收入(PMC「2 框」,不关联账户、不改余额);要让钱真正进到某账户,还得去账户行点「+收入」再录一次。
2. **股票收入无处落**:账户「+收入」类目写死「工资」,没有股息/利息/卖出回款;股票账户用户干脆**直接改期末余额** → 被 `PnL = ΔNW − 净流入 − 净划转` 当成「投资赚的」→ **收益率虚高**。

## 本迭代方案(延续上一版基础逻辑 + 两个约束)

把「收支填报」的**收入侧**从"手填一个总收入数"升级为**结构化收入录入**:每笔收入 = `金额 + 类目 + 目标账户`,可在一个账期录多笔。每笔**一次录入、处处正确**:入该账户本期余额、留一条流水、记为外部流入(不进 PnL)、并**汇入家庭本月收入**(储蓄率/人赚从这份汇总取)。收入只录这一处 → 消除双录;股票收入按类目录到券商账户 → 收益率不虚高。

**两个约束(本版刻意收窄)**:
- **约束 A · 只做收入侧**:成本/支出侧**本版不动**,维持现在的「本月总支出」单框填法。收支填报框架保留(收入+成本都在),只升级收入。
- **约束 B · 目标账户只限「现金 / 股票」**:收入目标账户下拉本版只列 现金、股票 两类(理财/房产/其他 later)。

> 关键:这不是"逐笔明细账/流水账"。它就是月度填报里"我这月进了哪些钱、进到哪个账户"的**收入侧填报**,仍是账户级、10 分钟内可完成。

## 核心原则

- **一次录入,处处正确**:收入录一次(金额+类目+账户)→ 入账 + 流水 + 家庭收入汇总,不再"2 框 + 账户"两处各录。
- **收入 = 外部流入,不是投资收益**:走收入录入的一律记外部净流入、不进 PnL → 股票股息不抬高收益率。这正是替代"改股票余额"的价值。
- **收入侧单一来源**:家庭「本月收入 / 人赚 / 储蓄率」的**收入侧**改从"收入录入汇总"取(替换手填总收入);支出侧仍用现有「本月总支出」。同一笔不被 PMC 与录入重复计入。
- **10 分钟不变**:录入更顺(收入一处连续加几笔),不新增额外步骤;支出维持一个数。

## 功能需求(FR)

### FR-140 · 收入侧 = 结构化多笔录入(替换"总收入"单框)
- 「收支填报」收入侧改为可连续录入**多笔**收入行:每行 = `金额` + `类目`(下拉) + `目标账户`(下拉,**本版仅现金/股票**) + `备注`(选填)。
- 归属成员 = 目标账户的 primary owner(不额外选成员);各成员各自录入自己账户的收入,家庭汇总 = SUM。

### FR-141 · 每笔直接入账 + 留流水 + 外部流入
- 保存一笔 → ①写 `cash_flow`(INCOME · account_id · category · amount)②该账户**本期末余额 += 金额**(`applyDeltaToBalance`)③账户「本期流水 / 跨期流水档案」可见。
- 记为**外部净流入**,不进 PnL → 收益率不虚高。与"余额校准"共存口径不变(收入解释外部进来的部分,恒等式不变)。

### FR-142 · 家庭收入侧改从录入汇总(消除双录 · 防重复计入)
- 家庭「本月总收入 = SUM(收入录入)」,顶部不再手填总收入。
- `人赚/净流入/储蓄率/月均收入` 的**收入侧**从此汇总取(替换 PMC 手填收入);**支出侧仍取现有「本月总支出」**。
- 防重复:收入口径切换后,`pmcFirstNetInflow` / `cashflowBreakdown` / 储蓄率 三处同步改,确保收入不被"PMC 总收入 + 录入汇总"双计(承接历史「决策 B」的反向调整;加口径护栏)。

### FR-143 · 收入类目 = 分「现金类 / 股票类」· 默认顺序固定
- 类目下拉**默认第一项「工资」、第二项「薪资-股票」**(本质是股票薪酬,如 RSU 归属),覆盖工程师用户最高频的两笔;其余按类型排在后面。
- 类目按落点类型分两组(本版仅现金/股票):

  | 组 | 类目 | 绑定账户类型 |
  |---|---|---|
  | 现金类 | 工资、奖金、利息 | 现金 |
  | 股票类 | 薪资-股票(RSU/股票薪酬,含上市与未上市)、股息/分红 | 股票 |

- `cash_flow_category` 增补上述缺失的 INCOME 类目 + 记录每个类目**绑定的账户类型**(用于 FR-147 联动/校验)。
- **卖出回款/赎回 不作为收入类目**(它是账户内"减股+加现金"的调整,不是外部流入;强行记收入会重复计 → 家庭收入唯一以收入模块为准)。v0.12.0 曾建 `stock_sell` 类目,本轮**停用**。

### FR-147 · 类目 ↔ 账户类型 联动校验(防录错 · 关键)
- **前端联动**:用户选了类目后,**目标账户下拉即按该类目绑定的账户类型过滤** —— 选「工资」只列现金账户、选「薪资-股票/股息」只列股票账户。反向:先选账户则类目下拉只留该账户类型的类目。二者始终一致。
- **服务端校验**:提交时校验「类目.绑定类型 == 目标账户.类型」,不匹配直接拒绝(不可绕过前端)。杜绝「工资录进股票账户」「股息录进现金账户」这类错配。
- 错配的语义危害:工资本是现金薪水却记进股票账户、或股息记进现金账户,会让账户余额/收益归因错乱 —— 用校验从源头堵死。

### FR-144 · 股票收入 = 按持仓入账(对齐「余额变动」)· 与自动估值不打架
- 选「股票」→ 选账户 → **联动展示该账户已有持仓**,按持仓类型入账(全部记外部净流入、不进 PnL;`is_adjustment=0` + 类目):
  - **上市持仓(AUTO)+股数**:归属到某已持有的上市票(RSU),录 `+股数`,系统按**最新已知价**计值 = 流入额;持仓股数 += 增量,账户估值随之上升。
  - **未上市持仓(MANUAL)+股数**:归属到某已持有的未上市股(如字节),录 `+股数`,**× 该持仓联动的单股估值(手填)** = 流入额;持仓股数 += 增量。
  - **新建持仓**:首次拿到某票——上市(代码+市场+股数)或未上市(名称+股数+单股估值);创建持仓(**不扣现金**,因是收入非买入)+ 记流入。
  - **券商现金(CASH)+金额**:股息/利息现金到账,加到该账户现金行(与 v0.12.0 一致)。
- **不打架**:上市/未上市入账后**重算该账户当期估值**写回 snapshot(含新股数);现金进 CASH 行不被估值刷新覆盖(V33 语义)。收入值在录入时定格(外部流入),之后价格波动归 PnL(市值涨跌),归因正确。

### FR-145 · 录错可改/删(轻量 · 非"明细账管理")
- 本期收入行可删除/改额:删除即**冲回**对该账户余额的加值 + 移除对应 `cash_flow` + 回退家庭汇总;改额按差额调整。只为"录错能改",不做复杂明细管理。

### FR-148 · 收入录入 ↔ 账户流水:同一条,不是副本(删改天然联动)
> 你提的场景:上面「收入侧」录了一笔 → 下面账户明细出现这条流水;用户又在账户级直接录了别的流水;此时在上面删/改刚才那笔,账户明细里的流水怎么正确联动。
- **原则:一笔收入录入产生的,就是账户 `cash_flow` 里的那一条流水本身(同一行,不是两份)。**「收入侧」区块与「账户明细 / 本期流水」是**同一批 `cash_flow` 的两个视图**:收入侧筛「INCOME + 本期 + 现金/股票」,账户明细展示「该账户全部流水」。→ 天然没有"两份数据要同步"的问题。
- 在收入侧删/改某笔 = 按 `cash_flow.id` 删/改那一行 → 账户明细里它**同步消失/变更**(本就同一行);该账户本期余额按该笔金额**冲回 / 按差额调整**;用户在账户级直接录的**其它流水(支出/划转/其它收入)完全不受影响**。
- 反向对称:同一条流水在"账户明细"里删,也走**同一后端**(按 id 删除 + 冲回余额),与在"收入侧"删结果一致。
- 一致性红线(tech-design 保证):余额冲回必须与「余额校准值」及「其它流水」**互不串扰** —— 采用"按账户从上期末 + 本期全部流水/校准基线**重算**期末余额"或"幂等按 id 冲回",杜绝"删一笔把别的流水或校准值带歪"。删/改后展示的账户余额、未解释额、家庭汇总三处同时正确。

### FR-149 · 未上市(MANUAL)持仓升级为「股数 × 单股估值」(股票收入的前提)
- 现状未上市持仓只存"整笔市值"一个数、无股数。为支持"未上市收入只录新增股数",**未上市持仓改为记 `股数 + 单股估值`,市值 = 股数 × 单股估值**(与上市 AUTO 孪生,只是价格由用户手填而非市价)。
- **新建未上市持仓**:名称 + 股数 + 单股估值(账户币种)。
- **编辑未上市持仓**:可分别更新 `股数` 与 `单股估值`(收入录入只联动展示单股估值、不在收入里改;改单股估值走持仓[更新]入口)。
- **向后兼容(prod 已上线)**:迁移把现有未上市持仓按 **1 股** 折算(单股估值 = 原整笔市值,股数 = 1),市值不变;用户之后可手动改成正确的股数 / 单股估值。

### FR-150 · 收入录入 = 类型优先 · 股票联动持仓(交互)
- 收入录入**先选类型:现金 / 股票**。
- **现金**:类目 + 现金账户 + 金额 + 备注(FR-140/141)。
- **股票**:选股票账户 → **联动列出该账户已有持仓卡片**(上市 / 未上市 / 券商现金),在卡上就地入账(上市/未上市录 +股数、现金录 +金额),或**新建持仓**入账。
- 仍受 FR-147 类型校验(现金类目不进股票账户、反之亦然)与 FR-145/148(删改联动、同一条流水)约束。

### FR-146 · 关账后只读
- 已 CLOSED 账期的收入录入只读(与现有关账语义一致)。

## 约束 / 非目标(明确不做)

- ❌ **不做支出侧结构化**:成本/支出本版维持「本月总支出」单框(收支填报框架保留,支出 later)。
- ❌ **目标账户不含 理财/房产/其他**:本版仅现金/股票(其余 later)。
- ❌ 不定位成"逐笔明细账 / 流水账"模块;不做复杂明细管理 UI。
- ❌ **卖出回款/赎回不算收入**(账户内减股+加现金的调整,走股票账户既有卖出/现金机制;不进收入模块 → 不重复计)。家庭收入唯一以收入模块汇总为准。
- ❌ 不做"按持仓自动算股息"(股息金额用户手填一笔进券商现金);收入不落 LOAN。
- ❌ 不改净资产/收益恒等式本身;不动支出口径。

## 验收标准

1. 收支填报「收入侧」可连续录多笔:每笔 金额+类目+目标账户(账户下拉仅现金/股票);保存即入账并出现在该账户本期流水。
1b. 类目下拉**默认第一「工资」、第二「薪资-股票」**;选「工资」时目标账户只列**现金**账户、选「薪资-股票/股息」时只列**股票**账户;服务端拒绝错配(工资→股票账户 / 股息→现金账户 一律不允许保存)。
2. 对**股票账户**:①选未上市持仓录「+N 股」→ 该持仓股数 +N、账户估值 += N×单股估值、流水多一条 INCOME(薪资-股票);②选上市持仓录「+N 股」→ 股数 +N、估值 += N×最新价;③券商现金录「股息 ¥X」→ 现金行 +X。三者**XIRR 与「钱赚」都不因这笔上升**(外部流入);之后「刷新股票估值」不会冲掉现金那笔、且按新股数正确重算。
3. 家庭「本月收入/人赚/储蓄率」= 收入录入汇总(收入侧)− 现有「本月总支出」;同一笔不被 PMC 与录入重复计入。
4. 删除/改一笔收入 → 它在**账户明细里的那条流水同步消失/变更**、该账户余额冲回/按差额调整、家庭汇总回退;**账户级其它流水(支出/划转/其它收入)不受影响**;账户余额、未解释额、家庭汇总三处同时正确。
5. 收入不再需要"2 框 + 账户 +收入"两处各录一遍(单一入口)。
6. 支出侧行为、储蓄率支出口径**不变**;理财/房产账户本版不作为收入落点(下拉不列)。
7. 月度填报仍 10 分钟内;移动端可用;不破坏余额校准/划转/净资产 PnL 恒等式/币种不变性。
