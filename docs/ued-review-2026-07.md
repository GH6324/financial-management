# A · 系统性问题(跨页复现,优先修)

这 10 条不是某一页的毛病,是同一个原因在多页重复,修一次收益覆盖全站。

## A1 · 左下浮钮遮挡正文内容 —— P0,6 页复现

**现象**:隐私眼(`bottom:18px`)+ 目录 FAB(`bottom:66px`)固定在屏幕左下,压住正文。实测:

| 页面 | 被压住的内容 |
|---|---|
| dashboard(移动) | **"本月资产收益 ¥123,784" 的金额被黑色 FAB 压掉 ¥ 符号** |
| entry(移动) | 说明文字"…口在每个账户行右侧 ↔" |
| accounts(移动) | 筛选行"筛选 ·"标签 |
| lens(移动) | 旭日图左下弧区 |
| reports(移动) | 双口径说明块整段 |
| checkup(移动) | 资产配置条形图的"理财""房产"标签 |

**违反**:spec §3.3(可点性)、P1(看得清优先)。浮钮压住金额是最不可接受的一种 —— 这是财务产品。

**建议**:三选一 —— ①浮钮移到**右下**(左下是内容起始边,右下是留白边);②滚动时自动半透明/收起,停止滚动 1s 后恢复;③给 `main` 加 `padding-bottom` 预留浮钮区高度。我倾向 ① + ③ 组合。同时补 `env(safe-area-inset-bottom)`(见 A9)。

## A2 · 同一指标跨页数值不一致 —— P0,信任问题

实测同一时刻两页的同名指标:

| 指标 | dashboard | checkup | 差异 |
|---|---|---|---|
| 净资产 | ¥4,209,016 | **¥5399878** | 差 119 万 |
| 总资产 | ¥5,395,716 | **¥6586578** | 差 119 万 |
| 紧急储备 | 7.2 月 | **723.0 个月** | 差 100 倍 |

注意:checkup 的"净资产 ¥5399878" ≈ dashboard 的"总资产 ¥5,395,716" —— 看起来是 **checkup 的"净资产"标签下装了不含负债的口径**,或用了不同账期。

**违反**:P4(秩序表达可信)。财务产品里两页数字不一致,用户会立刻不信任全部数字。

**建议**:这是本次 review 里**唯一必须先查代码再谈设计**的一条。先确认是口径差异还是 bug;若是口径差异,两页都必须在 ⓘ 里写明"含/不含负债、账期为 X",且**标签文字不能同名**。

## A3 · checkup 全页金额无千分位 —— P0

**现象**:`¥5399878` / `¥6586578` / `¥1186700` / `¥60250`。而 dashboard/accounts/lens 都是 `¥4,209,016` 有千分位。PC 和移动都缺。

**违反**:spec §2.3 硬性规则第 2 条(千分位必须有)。7 位数无分隔,人眼无法快速读出量级。

**建议**:checkup 的金额格式化统一走 `MoneyFormat`。这条最简单也最该立刻修。

## A4 · 移动端首屏 0 内容 —— P0,4 页复现

首屏(844pt)内看到的东西:

| 页面 | 首屏内容 | 第一个数据/主体出现在 |
|---|---|---|
| dashboard | 标题 + 环比 + 账期 + 期间 6 chip + 账户范围 + 币种 + "展开账户多选筛选" | KPI 第 3 个才露头 |
| entry | 标题 + 3 段说明 + 账期 + 进度卡(3 指标垂直堆 ~700px) | **第 2 屏之后**才有账户行 |
| accounts | 标题 + 说明 + 2 按钮 + 9 格汇总带(~950px) | **第 2 屏**才有账户卡 |
| reports | 标题 + 已关账印 + 2 段说明 + 账期 + 期间 + 账户范围 + 币种 | KPI 在首屏末 |

**违反**:spec §7.2(L1 结论层必须在首屏)、约束一(低频用户要的是结论)。

**建议**:
1. 移动端把"账期 / 期间 / 账户范围 / 币种"四组控件**收进一个可折叠的"筛选"条**(默认收起,显示当前值摘要如 `2026-07 · 全部账户 · CNY`)
2. 页面说明文字移动端默认折叠(`<details>`),只留一行
3. 腾出的空间放 L1 结论层 —— dashboard 已经有素材了("环比 +52.55% · 储蓄率 98.4%"),只是现在字号小、位置在标题下方,权重低于控件

## A5 · 网格末位空格露底成色块 —— P1,3 处

**现象**:`grid gap-px bg-rule` 的格子数不满时,空位露出 `--rule` 底色,形成一块突兀的米灰色矩形。

| 位置 | 情况 |
|---|---|
| accounts 汇总带 | 9 个类型 ÷ 6 列 → 第二行 3 格 + **3 格空白**(PC);2 列 → 第 5 行 1 格 + **1 格空白**(移动,占半屏宽) |
| checkup KPI | 5 个 ÷ 2 列 → **1 格空白**(移动,右下明显色块) |
| dashboard KPI | 5 个 ÷ 2 列 → 第 5 个独占整行(不对称) |

**建议**:两种解法 —— ①给空位补 `bg-card` 占位元素;②改用 `flex-wrap` + 子项 `border` 替代 `gap-px + bg-rule` 的取巧写法。后者更根本。dashboard 的第 5 个 KPI 建议直接采用 spec §7.4 的"英雄数字 + 横滑 chip"方案。

## A6 · 专业缩写与技术词裸露 —— P1,全站

实测出现在**面向用户界面**上的:

| 类别 | 实例 | 出现页 |
|---|---|---|
| 金融缩写 | XIRR、PNL、PP(-2.61PP)、FIRE、CPI、M2、MoM | reports、checkup、goals、dashboard |
| 状态英文 | OK / WARN / RISK / CACHED / SUCCESS / CLOSED / OPEN / LOAN | checkup、admin、entry |
| 技术标识 | `/ADMIN/FAMILY` 等 **15 个 URL 路径当卡片 eyebrow**、`Spring Boot 3.3`、`PRD`、`frankfurter.dev` | admin |
| 枚举 code | `现金 (CASH)`、`股票 (STOCK)`… 全站类型 pill | accounts、checkup、entry |

**违反**:约束二(服务非技术用户下限)、P5(自解释)、既有纪律"面向用户的命名避免技术词"。

**建议**:
1. admin 的 15 个 URL eyebrow 全部换成中文分类词(顺带做 A10 的分组)
2. 状态英文换中文:OK→正常、WARN→注意、RISK→风险、CACHED→已缓存
3. 金融缩写保留(专业性有价值)但**首次出现必须带 ⓘ**,且中文在前:"资金加权年化(XIRR)"
4. `(CASH)` 这类 code:PC 保留(便于对照),**移动端隐藏** —— 移动端宽度金贵,code 是纯噪音

## A7 · 异常值无兜底 —— P1

**现象**:紧急储备 `723.0 个月`(= 60 年),因月均支出接近 0 导致除法爆炸。checkup 页还基于它给建议:"建议紧急储备 ≥3 个月家庭支出",与 723 并列显得荒谬。

**建议**:所有比值型指标设上下界。超界时显示语义值而非数字:`> 24 月 · 极充裕(月均支出过低,数据可能不完整)`。同时给"分母过小"一个显式提示,引导用户去填支出。

## A8 · 移动端页面过长,无锚点/无返回顶部 —— P1

entry **13.9 屏**、accounts 8.9 屏、dashboard 7.8 屏、reports 7.8 屏。

entry 是每月核心任务页,18 个账户卡片各约 400px 且**结构完全一致**,滚动中极易失去位置感。目录 FAB 只在 dashboard/reports/checkup 有,entry 和 accounts 没有。

**建议**:
1. entry:账户卡片**默认折叠为单行摘要**(名称 + 上期末 + 本期值 + 已填/待填),点开才展开表单。18 行摘要约 3 屏,可控
2. entry / accounts 补目录或成员锚点吸顶(accounts 移动端已有成员 tab,entry 也有,但都在页面顶部一次性出现,滚下去就看不到了 —— 应改为 sticky)
3. 超过 3 屏的页面统一补"返回顶部"

## A9 · iOS 硬约束未处理 —— P1

对照 spec §7.6 实测代码:

| 项 | 现状 | 后果 |
|---|---|---|
| `overscroll-behavior` | **全站 0 处** | lens 指标/看板 pill 横滑、交叉表横滑时,边缘滑动会触发 **Safari 返回手势**,直接离开页面 |
| `scroll-snap` | **全站 0 处** | 横滑区停在半个 pill 位置(lens 首屏已可见"本期收…"被截断) |
| `safe-area-inset` | 仅目录 sheet 1 处 | 隐私眼 `bottom:18px`、FAB `bottom:66px` 未适配,带 home indicator 的机型上贴近系统手势区 |
| `touch-callout` | 仅隐私态金额 | 长按图表出现系统"拷贝图片"菜单 |
| `100dvh` | 未使用 | 未来做全屏查看器会遇到地址栏收放导致高度跳变 |

**建议**:前三项是三行 CSS 的事,建议一次做完。第一项优先 —— 用户横滑时莫名退出页面,几乎不可能自己想到原因。

## A10 · admin 15 个入口无分组 —— P2

3×5 平铺,15 个纯文字卡片,无图标、无分组,卡片高度因描述行数不同而底部不齐。

**建议**:按 4 组重排 —— 家庭基础(家庭/成员/账户/模板)· 数据口径(指标/现金流类别/产品类目/数值阈值)· 运营(周期/提醒/汇率/数据源接入)· 系统(备份/审计)。每组一个小标题,卡片补 16px 图标。
