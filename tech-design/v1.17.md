## 0 · 这一版真正要解决的技术问题

PRD 定了「我们发一个可选的 launcher 镜像」。落到工程上,要回答的是六件事:

1. 富途的命令行 OpenD 在容器里**怎么才能稳定起住**(实测里踩到三个坑,见 §1)。
2. app 在**另一个容器**里,怎么把账号/密码/验证码喂给它、怎么读它的登录状态 —— 这是方案 B 与方案 A 最大的实现差异。
3. 我们托管的镜像,怎么做到**可被用户独立验证**(不含富途文件 / 官方包哈希 / 镜像来源)。
4. 「可选」怎么做到**默认零成本**。
5. Java 侧不要变成两套实现(原生一套 + 容器一套),否则下一次改动必然只改一边。
6. 顺带把原生路径上今天就坏的那几处修好。

## 1 · 实测台账(2026-08-17 · beta 本机 docker 29.1.3)

设计前先把地基测实。**其中第 4 条推翻了我上一轮自己的记录**,原样列出来。

| # | 实测结论 | 怎么测的 | 对设计的约束 |
|---|---|---|---|
| 1 | `debian:12-slim`(glibc **2.36**)上 `FutuOpenD` / `FTUpdate` / `FTWebSocket` 三个可执行文件 `ldd` **零缺失** | `docker run --rm -v <解包目录>:/opt/opend:ro debian:12-slim ldd …`,grep `not found` 无命中 | 基底选它就够,不需要 gtk3/fuse,也不必背一个 JRE(见 D1) |
| 2 | 该基底**自带** `tar` / `sha256sum` / `script`(pty),**缺** `curl` 与 `ca-certificates` | 同一个容器里 `command -v` 逐个探 | launcher 只需 `apt install curl ca-certificates` 两个包 |
| 3 | **非 root 运行时,如果该 uid 不在 `/etc/passwd` 里,OpenD 直接段错误** | `docker run -u 10002:10002 debian:12-slim` → `Segmentation fault (core dumped)`;换成镜像里 `useradd -u 10002` 的用户 → 2 秒起好、正常监听 | ① launcher 必须自己建用户,不能靠调用方传 `-u`;② 用户若在 compose 里覆盖 `user:` 会得到一个无法理解的段错误 → entrypoint 必须先自检并说人话(见 D2) |
| 4 | **stdin 给 `/dev/null` 也能起住**:T+8s 监听 11111 与 22222,T+63s 仍存活 | 后台起进程,`/proc/net/tcp` 查 `0A` 状态的 `:2B67` / `:56CE` | 上一轮我记的是「`< /dev/null` 会立刻退出、必须开着 stdin」—— **那条是错的**。因此 entrypoint 不需要 pty 包装,可以 `exec` 直起(PID 1 = OpenD,`docker stop` 的 SIGTERM 直达) |
| 5 | 但**没有 pty 时,OpenD 往 stdout 写 0 字节** | 同上,`wc -c < d.log` = 0;而用 `script -qec` 造 pty 时能看到「版本信息/启动时间/API监听地址」等横幅 | `docker logs` 会是**空的** → 状态和日志必须另找来源(见 D2) |
| 6 | **OpenD 忽略 `$HOME` 环境变量**,状态目录按 `getpwuid(getuid())->pw_dir` 落在 `/home/futu/.com.futunn.FutuOpenD/`,日志是 `Log/GTWLog_*.log` | 显式 `-e HOME=/work` 起进程,`find` 到的却是 `/home/futu/.com.futunn.FutuOpenD` | 数据卷必须挂到 **`/etc/passwd` 里那个 home 路径**上;设 `HOME=` 无效 |
| 7 | telnet 控制面可用且**无鉴权**:连上发一个换行即收到 `Futu OpenD版本信息: 10.10.7008…, 输入help获取更多信息` + `请输入密码` | 容器内 `exec 3<>/dev/tcp/127.0.0.1/22222` | 控制通道技术上成立;但它必须**不出容器**(见 D3) |
| 8 | **官方模板把 `telnet_ip` / `telnet_port` 整行注释掉了**(示例值 `127.0.0.1` / `22222`),即控制口**默认不启用**;只替换标签内容会把值改进注释里,OpenD 日志连 `Telnet监听地址` 都不打印 | 容器实跑:配置生成后 `grep telnet` 只看到 `<!-- <telnet_ip>…` 两行,`/proc/net/tcp` 里没有 22222 | 生成配置必须**取消注释再设值**({@code setOrEnableTag});先前"默认 0.0.0.0"的说法是把我自己改过的测试文件当成了官方原文,已纠正 |
| 9 | **OpenD 完全不响应 SIGTERM**:给 60 秒宽限期仍被 SIGKILL(退出码 137);而控制口在**未登录状态下不受理任何命令**(`help` / `exit` 都只回"请输入密码") | `docker stop -t 60` 计时;控制口手工发 `help`/`exit` | "exec 让信号直达"这个收益是**零** → D2 的取舍前提要改写;停止实际就是硬杀,靠 `stop_grace_period` 控制等多久 |
| 10 | **硬杀之后能正常恢复**:SIGKILL 掉的容器 `docker start` 起来,安装物与状态目录完好,控制口照常工作 | 上一条那次 137 之后直接重启验证 | 所以不必为优雅停止引入一层 bash 包装(那在未登录时也没用) |
| 11 | 官方包 445MB,CDN 的 `etag` **就等于文件 MD5**:`4297cdec5653565556802fcd1b148f05` | `curl -sSI` 取 etag,再把整包流式过 `md5sum`,逐字符相同 | 给用户一条廉价交叉验证命令;但同一条 TLS/CDN,不是独立锚(PRD §4 已写明) |
| 12 | 富途 Java SDK **支持 API 加密**:`FTAPI_Conn.setRSAPrivateKey(String)` + `initConnect(host, port, isEncrypt)`;我们现在第三个参数传的是 `false` | `javap -p` 反查 `futu-api-10.7.6708.jar`;对照 `FutuBrokerClient.java:221` | 11111 可以真正加鉴权,不必只靠"不 publish"(见 D4) |

> 待实测、本轮拿不到的两条(需要**真实富途账号**):`-login_by_remember` 能否跨容器重启免密;首次问卷/协议究竟在哪一步做。§9 单列。

## 3 · 关键决策

### D1 · launcher 的基础镜像

| 备选 | 体积 | 取舍 |
|---|---|---|
| **`debian:12-slim`(选定)** | ~116MB 解压 / 加 curl+ca-certificates 约 +12MB | glibc 2.36 ≫ 官方包要求的 2.27;**实测 ldd 零缺失**;`tar`/`sha256sum`/`script` 自带;Debian 稳定版安全更新节奏可预期 |
| `ubuntu:24.04` | 相近 | 同样能跑,但 24.04 起把 `libgtk-3-0`/`libfuse2` 改名成 `*t64`,而我们文档里那段过期依赖提示正是被这个坑到的;换 Debian 少一层名字漂移的风险 |
| `alpine` | ~8MB | **不可行**:musl。官方包是 glibc 动态链接的,`ldd` 会直接找不到解释器 |
| 复用 app 镜像基底 `eclipse-temurin:21-jre` | 493MB | 上一轮的实测就是在它上面做的,能跑;但为一个 shell 下载器背一个 JRE,而且和 app 镜像的版本节奏绑在一起 —— 违背"launcher 要小到能一眼读完" |

### D2 · 进程怎么托起、日志从哪来

实测 #4/#5 把这题的答案改了:**不需要 pty**,但**不能靠 stdout**。

| 备选 | 取舍 |
|---|---|
| **`exec FutuOpenD` + 后台 `tail -F` 日志转发(选定)** | entrypoint 先 `mkdir -p` 日志目录、后台起 `tail -F …/Log/GTWLog_*.log &`(`-F` 能等文件出现),再 `exec` OpenD。`docker logs` 有内容(来自 tail),不多一个常驻进程 |
| `script -qec "FutuOpenD …" /dev/null` 造 pty | 只为拿启动横幅而引入 pty;横幅里的信息在 GTWLog 里都有 |
| 用 bash 包一层 + `trap TERM` → 通过控制口发 `exit` 优雅停止 | **实测否掉**:控制口在未登录状态下不受理任何命令(`exit` 也只回"请输入密码"),而登录后的行为无法在没有真实账号时验证 —— 换来的是"一半场景有效"的复杂度 |
| supervisor / s6-overlay | 为两个进程引入一个进程管理器 + 一套配置语法,和"镜像小到能读完"的目标相反 |

> **关于优雅停止,前一稿写错了**:我原本用"SIGTERM 直达进程"当作选 `exec` 的主要理由。实测(表 #11)
> **OpenD 完全不响应 SIGTERM** —— 给 60 秒也照样被 SIGKILL。所以这个收益是零,`exec` 的真实理由只剩"少一个进程、少一层语义"。
> 停止 = 硬杀,靠 compose 的 `stop_grace_period` 决定白等多久(设短些,反正等也没用);表 #12 已验证硬杀后能正常恢复,
> 文档里要如实写这一点,别让用户以为是 bug。

配套(实测 #3/#6 的直接结果):

- 镜像里 `useradd -r -u 10002 -m -d /home/futu futu` 并 `USER futu`;数据卷挂 **`/home/futu`**(不是靠 `HOME=`)。
- entrypoint **第一件事**是自检并给人话错误,而不是让 OpenD 段错误:
  - `getent passwd $(id -u)` 为空 → `富途网关不能以自定义 uid 运行(你可能在 compose 里加了 user:)。请去掉 user: 覆盖。`
  - `/home/futu` 不可写 → 报明确的卷权限错误。

### D3 · app 怎么喂凭据、读状态(方案 B 的核心)

风险面要先说清:OpenD 的 telnet(22222)**没有鉴权**(实测 #7),连上就能重登、发验证码、退出进程。

| 备选 | 取舍 |
|---|---|
| (a) app 直接连 `futu-opend:22222` 讲 telnet | 最少构件,PRD preview 里画的也是这条。但那意味着**无鉴权控制口暴露在整个 compose 网络**里:用户自己在同一个 compose 里跑的任何其它服务(或它被攻破)都能操作这个券商网关。"不 publish 到宿主"只挡住了外网,挡不住同栈 |
| (b) launcher 里加一个带 token 的 HTTP 控制面 | 能鉴权,app 侧也好写;代价是要往镜像里塞一个 HTTP 服务(python3 约 +25MB,或引入 Go 编译链),攻击面和"镜像小到能读完"都变差 |
| **(c) 共享卷文件通道 + telnet 只绑容器内 127.0.0.1(选定)** | 生成配置时把 `telnet_ip` 按死成 `127.0.0.1`(官方模板里这两行是**注释掉的**,要取消注释再设值)→ **控制口根本不出容器**,同栈其它容器连不到。app 与 launcher 共挂一个小卷 `/ctl`:app 写 `cmd/<序号>.req`,launcher 的 `control-loop.sh`(纯 bash + `/dev/tcp`)轮询执行、写 `cmd/<序号>.done` 与 `status`。零新端口、零新依赖、零鉴权协议 —— **文件权限就是鉴权**;而且这个循环用户能逐行读 |

**为什么不选 (a)**:它把"无鉴权"从一个容器内部问题变成了一个网络问题,而这一版的卖点恰恰是"值得信任"。
**为什么不选 (b)**:为了拿到 (c) 已经免费给到的隔离,多付一个 HTTP 服务的复杂度和体积。

(c) 的两个诚实代价,要写进文档而不是藏着:

1. **凭据会短暂落卷**。密码写进 `cmd/<序号>.req` 后由 launcher 读取并**立刻 `unlink`**;文件 `mode 600`、卷不对外挂载、内容不进任何日志(只记「已发送密码(不记录内容)」)。容器实跑时用一个 canary 口令验证过:执行后 `grep -r` 整个 `/ctl` 与 `/home/futu` 都搜不到它,`docker logs` 里也是 0 命中。比今天的 `.env` 长期明文好一个量级,但不是零落盘 —— 想零落盘要用 FIFO,阻塞语义会把这个循环搞复杂,不值。
2. **轮询延迟**:1 秒一轮。用户点"登录"到页面出现"已发送验证码"多等最多 1 秒,可接受。
3. **报文格式是 `key=value` 而不是 JSON**(前一稿写的是 JSON)。理由很实在:这个镜像里没有 `jq`,用 bash 解析 JSON 会脆;为了解析 JSON 往镜像里塞 python3(+25MB)又与"小到能读完"相悖。`key=value` 两边都省事:bash 一行 `sed -n "s/^key=//p"`,Java 侧也只是 split。

### D4 · 11111 要不要加鉴权

如果只做 D3 而放着 11111 不管,那是**假安全**:控制口锁了,但同栈容器仍能通过 11111 读到全部持仓。

- **选定:启用 RSA 加密通道**。实测 #9 表明 SDK 现成支持:launcher 首启生成私钥写 `/ctl/opend.pem`(mode 600),XML 配 `rsa_private_key`;app 侧 `FutuBrokerClient` 读同一文件 `setRSAPrivateKey(...)`,并把 `initConnect(host, port, false)` 的第三参改成 `true`。app 侧净改动是**两行 + 一次文件读**,密钥分发复用 D3 已有的 `/ctl` 卷。
- 未选:只靠不 publish。理由如上 —— 锁一个口、开着另一个,等于没锁。
- 未选:给 11111 也套一层代理。RSA 是官方支持的通道级加密,自己套代理只会多一个中间件。
- **兼容注意**:原生/外部 OpenD(逃生阀那条路)可能没配 RSA → 加密开关必须**按连接来源决定**,不能全局写死(见 D8 的 `OpendChannel`)。

### D5 · 安装包哈希:钉在哪、在哪校验、没钉过的版本怎么办

| 备选 | 取舍 |
|---|---|
| **仓库里的清单 + 编译进镜像 + 运行时校验(选定)** | `deploy/futu-opend-releases.json`:`{版本, 文件名, 字节数, sha256, md5}`。它同时被两处消费:launcher 镜像构建时 `COPY` 进去(离线可用、不依赖 app)、app 侧读同一文件用于**页面公示**。校验发生在 launcher 下载完、解包**之前**;不匹配 → 删文件 + 退出并打印期望/实得两个值 |
| 只由 app 下发哈希给 launcher | launcher 就不能独立启动了(app 没起来时它连自检都做不了),而且多一条要鉴权的链路 |
| 只信 TLS | 就是今天的行为,也是这一版要修的东西 |

**"最新版"与"已核对"的冲突**(PRD §8 第 1 条,维护者点头的建议):

- 默认 = 清单里最新的**已核对**版本 → 富途发新版后到我们跟上之前,默认装的是旧版(能用,不是最新)。这是自觉的取舍。
- 用户显式勾"用官方当前最新版" → 走 `fetch-lasted-link`,下载后**照样算 sha256/md5**,把实算值显示在页面上,并明确写"这一版我们没核对过,请你自己判断"。选择记在配置里,不每次问。
- 我们跟版的动作因此变成"往清单里加一行 + 发一次 launcher 镜像",不需要改代码。

### D6 · 富途凭据存哪

- **选定**:存库,经管理页填(FR-6)。新增两个 family config key `broker_futu_account` / `broker_futu_password`,复用现有 `FamilyConfigService`(和老虎的 `K_BROKER_TIGER_*` 同一套机制,行为一致)。
- 未选:继续放 `.env` —— 违反项目既有原则(运营参数走管理页),也是 PRD §0 列的四条不合理之一。
- 未选:放 launcher 卷里由它自己登录 —— app 就看不到状态,向导页又要退化成"你自己去容器里看"。
- **加密**:这一版**不做**。理由要说白:老虎的 RSA 私钥今天也是明文存库(`TigerBrokerClient` 直接 `getString`),只给富途加密会造成"看起来加密了"的错觉,而真正的账户风险面没变。凭据加密应当是**独立一版**、两家一起做、连带 `audit_log` 一起过一遍。这一版只保证:不落 `.env`、不进日志、不进 LLM prompt。

### D7 · 「可选」怎么落地

| 备选 | 取舍 |
|---|---|
| **compose profile(选定)** | 富途服务写进主 `docker-compose.yml` 并标 `profiles: ["futu"]`;默认 `up -d` / `pull` 完全跳过它。启用:`docker compose --profile futu up -d`,或 `deploy/docker-up.sh --with-futu`(脚本现在没有任何参数解析,要新加一个;并把选择记进 `.env` 的 `FUTU_ENABLED=1`,这样用户之后自己敲 `docker compose up -d` 不会漏掉 profile) |
| 保留今天的独立覆盖文件 | 那条 87 字符的 `-f a -f b` 命令是 PRD §0 抱怨的对象之一。而且覆盖文件模式下 app 侧要多挂一个卷,主文件也得跟着改,反而不干净 |
| 单独一个 compose 项目 | 两个项目就是两个网络,还得手动 `external network`,把简单事做复杂 |

**已知坑,要在文档和护栏里点出来**:profile 服务起来之后,用户不带 profile 跑 `docker compose up -d` **不会**停掉它(compose 不动未选中的服务),但带 `--remove-orphans` 会把它当孤儿删掉。所以 `docker-up.sh` 在 `FUTU_ENABLED=1` 时必须自动补上 `--profile futu`,并且脚本里任何 `--remove-orphans` 都要一起带 profile。

### D8 · Java 侧不要写成两套

今天 `FutuOpendManager` 是"本机进程管理器",里面有 7 处 `Env.DOCKER` 硬拦(`:194` `:217` `:242` `:359` 等),模板里另有 10 处 `channel != 'DOCKER'` 分支。照现状加容器支持,必然变成两套并行实现。

- **选定:抽一个 `OpendChannel` 接口**(install / start / status / requestSms / submitSms / stop / tail / target),**两个**实现:
  - `LocalProcessChannel` —— 今天的逻辑搬过去(原生 systemd / macOS),顺带修掉过期 host、文件名、`osTag`、依赖提示、废弃启动参数。
  - `ContainerGatewayChannel` —— 走 D3 的 `/ctl` 卷通道。
  - ~~`ExternalChannel`~~ —— **实现时收掉了**。原计划给"OpenD 在别处"(家里 NAS / 反向隧道 / 用户自备镜像)也做一个通道类,写下来发现它每个方法都只能抛"不支持":那条路本质是**我们不托管**,只是 `family_config` 里的一个 host:port,由 `FutuBrokerClient` 直接用。为对称而造一个空壳类,只会让人以为那里有逻辑。逃生阀改为用能力位表达(向导页显示"指向外部 OpenD",隐藏安装/登录步骤)。
- 选择依据从「`/.dockerenv` 存不存在」改成**「能力探测」**:`/ctl` 卷在不在 + 目标服务连不连得上 + 库里有没有手填地址。理由:`/.dockerenv` 只能回答"我在容器里",回答不了"网关在哪"——而后者才是真正要分支的东西。
- 模板侧同步:10 处 `channel != 'DOCKER'` 收敛成**按能力**渲染(`caps.canInstall` / `caps.canLogin` …),这样第四种拓扑出现时不用再加一个 `channel` 值。
- 未选:保留 `Env` 枚举再加一个 `DOCKER_GATEWAY` 值 —— 那正是 memory `feedback_enum_add_sweep` 记着的老坑:加枚举值编译器只抓穷尽 switch,抓不到模板里的字符串条件,v0.14 加 `METAL` 就是这么上线才发现的。

### D9 · 「镜像里没有富途文件」怎么机器证明

- **选定**:CI 里构建完 `docker create` + `docker export`,把 tar 的**文件清单**过一遍禁用模式(`FutuOpenD`、`FTUpdate`、`FTWebSocket`、`Futu_OpenD_*.tar.gz`、`libf3c*`),命中即 `exit 1`。理由:看的是最终镜像的**全部层**,不受 Dockerfile 写法影响(多阶段、`COPY --from` 都躲不过)。
- 未选:只 grep Dockerfile —— 只能证明"我没写",不能证明"层里没有"。
- 未选:生成 SBOM 再扫 —— SBOM 记的是包管理器认识的包,手工塞进去的二进制它未必记。
- 配合 FR-15:`docker/build-push-action` 打开 `provenance: true` + `actions/attest-build-provenance`,README 给 `gh attestation verify` 的命令。**镜像按 digest 引用**,tag 只作方便。

### D10 · 版本发现

- **选定**:清单(D5)是唯一权威;`fetch-lasted-link` 只在用户显式选"最新版"时用。向导页**删掉版本号输入框**(今天的 placeholder 还写着 `9.3.5308`)。
- 白名单同步改成官方现行下载域名 —— 今天的白名单只放 `softwarefile.futunn.com`,用户手填现行官方 URL 会被我们自己拒(PRD §1 #3)。

### D11 · 重启后要不要重新收验证码

`-login_by_remember` 本轮**无法实测**(需要真实账号)。两条路都设计好,不让它卡住实现:

- 若能免密:launcher 首启登录成功后把凭据留在 `/home/futu` 卷里,重启走 remember,页面显示"已自动恢复"。
- 若不能:重启后状态停在 `NEEDS_SMS`,向导页出现验证码输入框(和首次登录同一个组件),不需要用户碰命令行。
- 无论哪条,**`status.json` 里都要有一个明确的状态字段**,页面不去猜。
