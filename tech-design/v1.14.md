## 0 · 施工前的查证

**改动面确实只有一个文件**:`src/main/resources/templates/holdingimport/import.html`。
后端零改动,DB 零迁移。全仓库确认**没有任何** `dragover` / `drop` / `paste` 监听
(grep `templates/` 全空),所以不存在与既有行为冲突的问题。

三条会影响设计的事实:

1. **`#dropZone` 有 inline `onclick`**(第 63 行)`onclick="document.getElementById('fileInput').click()"`。
   加拖拽不能碰它 —— 点击选图是现有主路径。drop 事件不会连带触发 click,两者并存安全。

2. **现有上传逻辑整个写在 `fi.addEventListener('change', …)` 的回调体里**(第 210–223 行):
   压缩 → 缩略图 → `FormData` → POST → `uploaded/uploading` 计数 → `upd()`。
   这一整块就是要抽出来的 `handleFiles`。**但回调体第一行的 `fi.value=''` 不能一起抽走** —— 见 §1.1。

3. **`accept="image/*"` 只约束文件选择器,不约束 drop 和 paste**。
   拖进来的文件夹在 `DataTransfer.files` 里是一个 `type === ''` 的条目,
   现在的 `compress()` 会走到 `img.onerror` → `res(null)` → **静默减计数**,
   用户看到的是「什么都没发生」。这正是 FR-373 要解决的场景,而且它比 PDF 更隐蔽。

## 1 · 架构选型

这一版是纯前端小改动,选型不多,但有几处**选错了会留坑**:

### 1.1 · `handleFiles` 的边界:`fi.value=''` 留在哪

| 方案 | 取舍 | 结论 |
|---|---|---|
| A · 整个回调体(含 `fi.value=''`)抽进 `handleFiles` | 抽得干净。但 `fi` 是**文件选择器专属**的状态,drop / paste 路径根本没有这个 input —— 抽进去会让另外两条路径执行一句与自己无关的副作用,并且把 `handleFiles` 和 DOM 上一个具体元素绑死 | 不选 |
| **B · `handleFiles(fileList)` 只管「拿到一组文件之后做什么」** | `change` 回调变成 `handleFiles(fi.files); fi.value='';`。`fi.value=''` 是「让同一个文件能被再次选中」的输入框语义,留在它该在的地方 | **选定** |

**这个边界不是洁癖**:`fi.value=''` 必须在**读完 `fi.files` 之后**执行,而 `handleFiles` 内部
是异步的(`compress` 返回 Promise)。抽进去以后清空时机会变得依赖内部实现,是个将来会咬人的耦合。
现有代码已经做对了(先 `slice` 成数组再清空),保持这个顺序。

### 1.2 · 全局默认行为拦截的范围(FR-371)

这是 PRD 说的**真正的坑**,而且独立于拖拽功能存在:现在把图拖到页面任何位置松手,
浏览器都会导航到那个文件,**当前导入的进度全丢**。

| 方案 | 取舍 | 结论 |
|---|---|---|
| A · 只在 `#dropZone` 上 `preventDefault` | 最小。但**完全没解决 FR-371** —— 坑就在区域**外**。区域内本来也不会导航(因为我们要处理 drop) | 不选 |
| B · `document` 上拦 | 有效。但 `document` 上的 drag 事件在某些嵌套 iframe / 插件场景下会被更外层吃掉 | 不选 |
| **C · `window` 上拦 `dragover` + `drop`** | 冒泡链的最外层,一定拦得到;`#dropZone` 自己的处理器先跑并 `stopPropagation` 不到 window 也没关系 —— 它已经自己 `preventDefault` 了 | **选定** |

**必须两个都拦**:只拦 `drop` 是不够的 —— 不 `preventDefault` `dragover`,浏览器根本不会派发
`drop`(这是 HTML5 DnD 最经典的坑),而默认的导航行为照样发生。

这条对移动端无害(触摸设备不产生 drag 事件),符合 FR-374。

### 1.3 · 拖拽高亮:为什么必须计数(FR-372)

`#dropZone` 里有两个子 `div`。拖着文件在区域内移动时,鼠标从父元素进到子元素会
**先 `dragenter`(子)后 `dragleave`(父)**,如果 `dragleave` 直接取消高亮 → **闪烁**。

选定:`dragenter` 计数 +1、`dragleave` 计数 -1,归零才取消高亮。

**但计数器有个真实的失效场景要补救**:把文件拖出**浏览器窗口**时,`dragleave` 不保证触发,
计数器卡在 >0 → 高亮**永久亮着**,用户以为页面卡了。处置是在
`window` 的 `drop` / `dragend` 上**强制归零**(不是 -1,是清零)。
`dragend` 只在拖拽源是本页元素时可靠,所以两个都要挂。

不选「用 `dragover` 做高亮 + 定时器超时取消」:定时器方案会让高亮跟着鼠标一顿一顿地闪,
而且引入一个与用户动作无关的时间常量。

### 1.4 · 粘贴入口的范围(FR-375 · 作者拍板加)

| 方案 | 取舍 | 结论 |
|---|---|---|
| A · 只在 `#dropZone` 聚焦时接 paste | 范围最窄。但 `div` 默认不可聚焦,要加 `tabindex` 并要求用户先点一下区域 —— **粘贴比拖拽短一步**这个价值就没了 | 不选 |
| **B · `document` 级监听,但主动让位** | 监听 `document` 的 `paste`;若 `document.activeElement` 是 `input` / `textarea` / `contenteditable` → **直接返回**,不拦截;只接 `clipboardData.items` 里 `type` 以 `image/` 开头的项 | **选定** |

「主动让位」这一条是必须的:同一页面下方的比对表格里有 `.j-mv` 数值输入框,
用户在那里 Ctrl+V 粘数字时,不能被截图上传逻辑吃掉。判据用 `activeElement` 而不是
`e.target`,因为 paste 事件的 target 在没有聚焦元素时是 `body`。

剪贴板里同时有图和文字(常见:截图工具 + 复制了文件名)时,只要有 `image/` 项就按图片处理
并 `preventDefault`,否则一律放行。

### 1.5 · PC-only 的提示文案怎么判定(FR-374)

移动端要求**逐字不变**,但拖拽提示只对 PC 有意义。

| 方案 | 取舍 | 结论 |
|---|---|---|
| A · Tailwind 响应式 class(`hidden sm:block`) | 纯 CSS,零 JS。但判据是**视口宽度**:窄窗口的桌面浏览器会被误判成"移动",而它明明能拖文件;反过来横屏平板会显示出一句它做不到的提示 | 不选 |
| **B · 指针能力探测** | `matchMedia('(hover: hover) and (pointer: fine)')` 为真才 JS 注入这句提示 | **选定** |

B 的判据是**「这台设备能不能拖文件」**本身,而不是它的屏幕多宽 —— 和要表达的意思对齐。

**别把「DOM 里没有」说过头**:提示文案是 JS 注入的,所以手机上 `#dzTip` 这个元素**渲染出来是空的**;
但那句话作为字符串字面量仍然在页内 `<script>` 里 —— `document.documentElement.outerHTML` 里搜得到 `Ctrl+V`。
FR-374 要保证的是**用户看得见的内容**逐字不变,不是 HTML 源码字节不变(整段脚本本来就重写了)。
e2e 的判据因此定在 `body.innerText`,不是 `page.content()`(第一版写成后者,当场红了 —— 结论正确、判据写错)。

### 1.6 · 非图片的拒绝怎么呈现(FR-373)

不用 `alert`(阻塞、样式与全站不一致、移动端体验差)。在拖拽区下方插一行常驻提示:
「已忽略 2 个非图片文件:对账单.pdf、持仓.xlsx」,下一次成功上传时清掉。

**图形一律 inline SVG**(Feather-style 24×24 viewBox / `stroke=currentColor`),
**不要 emoji**(memory `feedback_no_emoji`)。现有 `＋` 与 `✕` 是既有文案,本版不动它们。

## 2 · 落地结构

```js
// 一个入口,三条路径喂给它
function handleFiles(fileList) {
  var all    = Array.prototype.slice.call(fileList);
  var images = all.filter(function(f){ return f.type && f.type.indexOf('image/') === 0; });
  var reject = all.filter(function(f){ return !(f.type && f.type.indexOf('image/') === 0); });
  showRejects(reject);                 // FR-373 · 文件夹的 type 是 '',落在这里
  images.forEach(uploadOne);           // ← 现有第 211–222 行原样搬进来,一行不改
}

fi.addEventListener('change', function(){ handleFiles(fi.files); fi.value=''; });   // §1.1

dropZone.addEventListener('dragenter', ...);   // 计数 +1 → 高亮
dropZone.addEventListener('dragleave', ...);   // 计数 -1 → 归零才取消
dropZone.addEventListener('dragover',  function(e){ e.preventDefault(); });  // 不写 drop 不触发
dropZone.addEventListener('drop', function(e){ e.preventDefault(); reset(); handleFiles(e.dataTransfer.files); });

window.addEventListener('dragover', function(e){ e.preventDefault(); });   // FR-371
window.addEventListener('drop',     function(e){ e.preventDefault(); reset(); });
window.addEventListener('dragend',  reset);                               // §1.3 补救

document.addEventListener('paste', function(e){ ...§1.4... });            // FR-375
```

`uploadOne` 就是现有 `files.forEach(function(f){…})` 的循环体,**逐字搬运,不重写** ——
PRD FR-370 明确要求压缩 / 计价 / 并发计数 / `scanBtn` 启用条件**一行都不复制**。
搬运后原 `change` 回调只剩两句。

## 4 · 测试

无后端改动,单测无新增。验收靠真机:

- **PC**:拖 3 张图 vs 点选 3 张 → 缩略图数、`本次 N 张`、预估金额、`开始识别` 可用性**逐项一致**。
- **PC**:拖到页脚松手 → 页面纹丝不动,已上传缩略图还在(FR-371,这是本版最该守住的一条)。
- **PC**:拖一个**文件夹** + 一个 PDF → 提示列出被忽略的名字,不静默(§0 第 3 条)。
- **PC**:截图工具截图后直接 Ctrl+V → 上传(FR-375);在比对表格的数值框里 Ctrl+V → **不被拦截**(§1.4)。
- **PC**:拖着文件划出浏览器窗口再回来 → 高亮不残留(§1.3 的补救)。
- **移动端**:页面渲染结果与升级前逐字一致(§1.5 的 B 让提示文案连 DOM 都不进)。
- 双端截图 + UED 复看:拖拽态高亮不能糊成一片(memory `feedback_ui_ued_review`)。
