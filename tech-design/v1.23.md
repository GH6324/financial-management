## 一、现状实测(已核过,与方案无关的客观事实)

| 事实 | 位置 | 备注 |
|---|---|---|
| 关账调度 `cron = "0 30 0 * * *"` | `PeriodOpener.openIfDue()` | 次月 1 日 **00:30** 即 force-close 上期 |
| 关账挂在「新期滚动」这个事件上 | `PeriodOpener.closePriorOpenPeriods` | **没有独立的关账扫描** —— 见 §三 |
| 已关账期硬拦写入 | `EntryService.requireOpenPeriod`、`BillCommitService` | 不是劝阻,是拒绝 |
| 重开入口在管理页且要填原因 | `PeriodService.reopen` | 三步操作 |
| `findCurrentOpen` 双 OPEN 下静默取最新 | `PeriodMapper:41` | `ORDER BY period_start DESC LIMIT 1` |
| 全仓 **30 处** 调用点 | 分类见 PRD §1.1 | A 9 / B 7 / C 6 / D 4 + 导入 1 |
| 关账一次做 **6 件事** | `PeriodService.close()` | 含属性定格 + 分组定格,见 PRD §1.2 |
| `CARRIED_FORWARD` 标记已存在 | `LedgerSource:37`,仅 `PeriodOpener:132` 写入 | FR-619 的守门判据,**不需要新字段** |
| 双 OPEN **今天已可达** | 管理页重开旧期时 | 本版不是引入风险,是补齐既有未定义状态 |

## 二、一条不能碰的红线(无论最终方案怎么定)

**余额 / 估值永远锚最新 OPEN 期,绝不回写上一期。**

理由见 PRD §3.0:世界上只能有一个「现在的市值」。
A 类那 9 处调用点(估值 / 持仓 / 券商 / 截图导入 / 汇率)之所以一行都不用改,
正是因为它们本来就遵守这条。

对应护栏:`v1230-BALANCE-AXIS-LATEST-ONLY`。

## 三、无论选哪条路都要有的闸

| # | 闸 | 为什么 |
|---|---|---|
| 1 | **独立的每日关账扫描** | 关账现在挂在「新期滚动」上;宽限到期那天没有滚动事件,不加扫描则账期**永远悬在 OPEN** |
| 2 | **`findCurrentOpen` 调用点白名单** | 双 OPEN 下静默取最新,漏审计的那处不报错、不进日志,只给一个看起来合理但错的数 |
| 3 | **零差异基线(硬门)** | `close_delay_days = 0` 时与 v1.22.5 逐分相等,否则不发。基线取已发布 tag(`feedback_metric_refactor_baseline`) |
| 4 | **三期 OPEN 视为数据异常** | 宽限最长 T+5,不可能跨到第三期;断言而不是兼容 |
