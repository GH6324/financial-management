# Tech Design · v1.5 · 基金持仓穿透

> 承 prd/v1.5.md。架构选型 + 取舍。核心是把「1 持仓 = 1 套单值标签」升级为「账户 → 持仓 → 持仓方向」,穿透结果与打标体系融合,旭日/透视/体检复用同一份。Spike 已用 prod 真实持仓验证(2026-07-24)。

## 1 · 数据源选型

| 备选 | 给什么 | 取舍 |
|---|---|---|
| **东财天天基金 F10 / pingzhongdata / push2**(选定) | 资产配置(股/债/现金)+ 前十大重仓股 + 个股细行业 | 免费 · 境内直连 · spike 验证可用;接口非官方会变(用重缓存 + 降级兜) |
| Tushare `fund_portfolio` | 只给个股持仓,行业要自己映射 | 需 2000–5000 积分门槛 · 多一步;留作交叉校验(未接) |
| 巨潮季报 / 年报 PDF | 最权威(全量持仓 + 行业) | 解析重、滞后大 · 不适合自动化 |
| AKShare(封装东财) | 同东财 | 需 Python 服务 · 部署加重 —— 否决 |

**为什么不用 Python/AKShare**:AKShare 本质是封装东财 HTTP。直接在 Java 用 `RestTemplate` 打东财底层接口即可,不背一个 Python sidecar(部署更轻,和现有股价/汇率 client 一致)。承 [[feedback_resttemplate_signed_url]] 调用纪律。

## 2 · 细行业粒度选型

| 备选 | 粒度 | 覆盖 | 取舍 |
|---|---|---|---|
| F10「行业配置」HYPZ | 证监会门类(制造业/金融业) | 全股票仓位 | **太粗**,达不到"家电/白酒"诉求;且联接/指数基金直接持股行业几乎空(钱在 ETF 里) |
| **前十大重仓股 → 个股东财细行业**(选定) | 东财细行业(白酒Ⅱ/白色家电) → 映射申万一级 | 仅前十大(股基常 40–70%) | 细度达标;未覆盖记「其他持仓」诚实降级 |

**取舍**:用户明确要"家电/消费"级 → 必须走个股。前十大覆盖不足的部分**不假分摊**,记「其他持仓」(承 PivotEngine 诚实降级)。

## 3 · 实体模型:加「持仓方向」层

- 备选 A:把持仓的 `industry_tag` 单列改成多值(JSON/多列)—— 破坏现有打标 + lens 取值,改动面大。
- **选定 B:新增 `holding_allocation`(持仓方向)** —— `holding_id + weight_bp(万分比) + asset_class + industry + kind(STOCK/BOND/CASH/OTHER) + source(PENETRATED/MANUAL/DEFAULT) + report_period`。
  - 无穿透持仓**不建方向行**,lens 回落隐式 1 条 100%(用持仓现有单标签)→ **老数据零迁移**。
  - 穿透基金 = N 条;手改标 MANUAL,重拉只删 PENETRATED/DEFAULT 保留 MANUAL。
- `stock_holding` 加 `fund_code`(穿透键)+ `penetrate_state`。

## 4 · 缓存:全局共享 vs 每家庭

- **选定:全局共享 `fund_penetration_cache`**(无 family_id · 按公开基金代码)· 穿透结果全体家庭复用,每基金每季度查一次。
- **隐私**:只拿公开代码去问"这支基金行业构成",**金额 / 家庭身份不入表、不出服务器**;缓存表零家庭数据。
- 物化:`拉取` 时从缓存(缺则实时抓)物化成该持仓的 `holding_allocation` PENETRATED 行(支持手改 + 解耦缓存刷新)。

## 5 · Lens 融合:拆多头寸 vs 改结构

- 备选:给 `Position` 加多值维度字段 —— 引擎/注册表/旭日全要改。
- **选定:`LensQueryService.assemble` 每持仓有方向则按 `weight_bp` 拆成多个 `Position`**(valueBase × 权重,assetClass/industry 取方向值,holdingCumPnl 按权重分)。`Position` 结构不变,PivotEngine / 旭日 / 透视 / 切片排行**下游零改动**,加权子头寸自然聚合出真实分布。

## 6 · 穿透计算(工程算 · LLM 不碰)

前十大逐股 → 东财细行业(push2 f127)→ 关键词映射 `IndustryTag` → 按占净值聚合;`其他持仓` = 股票仓位 − 前十大覆盖;债/现金按资产配置;全部转万分比后**归一化到 10000**(末项吸收舍入)。承 [[feedback_llm_no_math]]。

## 7 · IndustryTag 扩容:追加 vs 替换

- **选定:追加申万一级细行业(+29),保留旧 20 粗值**(向后兼容 —— 现有 CONSUMER/TECH_INTERNET 等已打标数据不破)。
- 下拉(`IndustryTag.values()`)、旭日环配色(稳定哈希)、AI 白名单(`values()` 动态)**自动跟进**;新值补 pinyin 供搜索。承 [[feedback_enum_add_sweep]] 扫模板/计数,本次无硬编码险点。
- **为什么不替换成纯申万 31**:替换需迁移存量粗标(CONSUMER→? 有损),风险高;追加零迁移。

## 8 · 名→码解析:人工核对

- spike 实测有份额错配(A/C)+ 误匹配("月月宝"→"天弘月月宝")风险,错配 = 行业全错。
- **选定:打标页 `拉取穿透` + 导入确认核对**(承 v1.4 确认流);份额 A/C 底层同 → 归一化匹配后穿透一致,自动归并。
- 理财/券商/投顾无公募代码 → `UNPENETRATED`,保持账户级粗粒度,诚实标注。

## 9 · 触发路径

- 打标页:单支「↻ 拉取穿透」(同步)+「全家一键穿透」(`@Async` 后台 · 完成 publish `LensStaleEvent` 失效缓存)。
- 截图导入确认落库后:`penetrateFamilyAsync` 后台自动穿透。
- 季度刷新:缓存 `FRESH=80 天`,过期重抓。

## 11 · 追加迭代架构(v1.5.2 · 交叉表可读性 + 打标一致性)

**① 交叉表指标参与笛卡尔(item9 · 纯前端 `lens.js`)**
- 取舍:后端 `PivotEngine` 已返回 `cells[].values[]`(全指标数组),前端选显示哪几列 → **指标作为一个前端维度即可,不改后端契约**(备选:后端按指标展开成额外列 → 需改查询协议 + 破坏 e2e,弃)。
- `state.measurePos`(`col`/`row`,默认 `col`);`renderPivot` 三分支:单指标(退化,`m0` 一值/格)、多指标 `mpos=col`(colKeys × measures 两级表头,`colspan=指标数`)、多指标 `mpos=row`(rowKeys × measures,首列 `rowspan=指标数`)。热力 `heatM` 按**每指标各自量纲** `maxAbsByM`,`priv` 逐指标判隐私。`renderMeasurePills` 加「指标放 列/行」拨片(`data-mp`)。

**② 交叉表移动端提示(item7/8 · `_section.html` + `lens.js`)**
- 方案「提示 + 竖屏重排」,**不做 iOS 假横屏**:`screen.orientation.lock` 在 iOS Safari / PWA 不支持,CSS-rotate hack 破坏点击命中与滚动,均弃。
- `#pivotHint`(`md:hidden` 仅移动端)可 × 掉,`sessionStorage.pivotHintX` 记忆本会话不再打扰(boot 时检查);`.sticky-col` 首列已 `position:sticky;left:0`,加 `box-shadow` 右缘阴影 → 横滑可读性(治本:不旋转屏,而是让竖屏本身能看)。

**③ 打标「平台」模板默认(item6 · schema + Java + 模板)**
- 取舍:平台属**模板元数据**,选 **V52 附加 nullable 列 `account_template.platform`**(备选:Java 静态 code→平台映射表 → 数据知识散在代码里,且 admin 只读页看不到,弃)。附加 nullable 列对 prod 存量零影响,承 [[feedback_prod_backward_compat]]。
- 默认时机:仅 **建户** `AccountController.create` 内,`platformTag` 为空且有 `templateId` 时从模板带出(编辑页有显式平台输入框,不覆盖用户;`blankToNull` 后为 null 才默认)。向导 `data-tpl-platform` 仅告知(源真相在服务端,JS 禁用也生效)。管理页只读列 + 模板数动态计数(承 [[feedback_enum_add_sweep]] 修写死「14 个」)。
- 守护 `v152-PIVOT-CARTESIAN` / `v152-PIVOT-MOBILE-HINT` / `v152-TPL-PLATFORM`。
