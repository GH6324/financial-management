> 状态:**精化 TDD(股票收入=持仓版)** · 对应 `prd/v0.12.md` · 预览 `preview/v0.12/income-stock-journeys.html`(现金侧 `income-entry.html`)
> 本文是实施权威源。每个关键决策列备选 + 取舍 + 为什么不选。红线:账户级颗粒度 · 10 分钟/月 · 不做逐笔明细账 · **prod 已上线须 backward-compat** · 币种不变性([[feedback_currency_invariance]])。

## 决策 1 · 收入端点与后端底座(承 v0.12.0 · 扩股票子模式)
- **选定**:现金侧沿用 `POST /entry/income`(periodId, accountId, categoryCode, amount, note)→ `recordIncome`。**股票侧新增按持仓的端点**(决策 8/9),因为股票不是"一个金额"而是"对哪个持仓 +多少股 / +多少现金":
  - `POST /entry/income/stock/holding`(accountId, holdingId, addShares, categoryCode, note)— 已有持仓 +股数(AUTO/MANUAL)
  - `POST /entry/income/stock/new-auto`(accountId, displayName?, ticker, market, shares, categoryCode, note)— 新建上市持仓入账
  - `POST /entry/income/stock/new-manual`(accountId, displayName, shares, unitValue, categoryCode, note)— 新建未上市持仓入账
  - `POST /entry/income/stock/cash`(accountId, currency?, amount, categoryCode, note)— 券商现金(股息/利息)= v0.12.0 金额路径
  - 删除:`POST /entry/income/{cashFlowId}/delete`(统一按 cash_flow.id · 决策 6)
- **备选(否)** 一个端点塞 mode 分支:参数集差异大(股数 vs 金额 vs 建仓字段),拆端点比一个巨型表单/校验清晰;且前端就是不同卡片不同 action。

## 决策 2 · 类目↔账户类型(承 v0.12.0 · 停用卖出回款)
- **选定**:`cash_flow_category.account_type`(V34 已加)。INCOME 绑定:`工资/奖金/利息→CASH`;`薪资-股票(stock_salary)/股息·分红(dividend)→STOCK`。排序:工资=10、薪资-股票=20。
- **停用 `stock_sell`(卖出回款)**:V35 迁移 `UPDATE ... SET sort_order=999`(排到最后)且**前端收入类目下拉过滤掉它**(`listIncomeOrdered` 加 `WHERE code<>'stock_sell'` 或视图层排除);不 DELETE(保留历史 cash_flow 外键完整、backward-compat)。理由:卖出回款是账户内"减股+加现金"的**内部调整**,不是外部流入;记收入会与卖出机制重复计。家庭收入唯一以收入模块为准。
- **备选(否)** 直接 DELETE 类目:破坏历史引用它的 cash_flow;停用 + 前端隐藏足够。

## 决策 3 · 类目↔账户联动校验(承 v0.12.0)
- 前端 `data-acct-type` 双向过滤 + 服务端红线 `cat.accountType==null || ==account.type`(recordIncome 已实现;股票新端点同样断言)。不变。

## 决策 4 · 股票收入落点(持仓版核心正确性)
- **背景**:股票账户余额由估值算出;直接 `applyDeltaToBalance` 会被估值刷新覆盖。股票收入有两形态:①拿到**股**(RSU,上市/未上市)→ 持仓股数增加;②拿到**现金**(股息/利息)→ 券商现金增加。
- **选定 · 按形态路由,统一"改持仓 → 重算 snapshot"**:
  - **+股数(AUTO)**:`holding.shares += addShares` → 计值 `value = addShares × 最新价 × FX(持仓币种→账户币种)`。
  - **+股数(MANUAL)**:`holding.shares += addShares` → `value = addShares × manualValue(单股·账户币种)`。
  - **新建持仓**:AUTO 用 `createAuto(deductCash=false)`(收入非买入,不扣现金)、MANUAL 用 `createManual(shares, unitValue)`;`value = shares × 单价`。
  - **+现金(CASH)**:`adjustAccountCash(账户币种, +amount)`(加/建 CASH 行)· value = amount。= v0.12.0 路径。
  - **四者统一**:持仓变更后调 `valuationService.refreshAllForFamily(familyId, HOLDING_CHANGE, memberId)` → 从持仓重算 end_balance 写回 snapshot(含本次增量);**不再对股票调 applyDeltaToBalance**(避免与估值链路双加)。再写一条 `cash_flow(INCOME, categoryCode, value, is_adjustment=0)`。
- **PnL 正确性**:`PnL = ΔNW − income + expense − …`。+股数/+现金使 ΔNW += value,同时 income += value → 抵消,收益率不虚高(RSU/股息是外部流入,非投资赚)。之后价格波动才归 PnL(市值涨跌),归因正确。
- **备选(否)** 股票也 applyDeltaToBalance:被估值刷新覆盖(v0.12.0 已证);且 +股数 无单一"金额"可 applyDelta。
- **备选(否)** +股数只记 flow 不改持仓:账户估值不含新股 → 与"直接入账"矛盾,且下次刷新反而抹掉。

## 决策 5 · 家庭收入侧口径(v0.12.0 已实现 · 不动)
- 收入侧已从 cash_flow INCOME 汇总取(替换 PMC 手填收入),支出侧仍 PMC 优先回退 cash_flow;`familyXirr` 外部流入用 cash_flow;币种不变性纳入 `CurrencyInvarianceTest`。持仓版记的 cash_flow(INCOME, is_adjustment=0)天然进同一汇总,**无需改动**。

## 决策 6 · 删/改与冲回(承 v0.12.0 · 适配持仓版)
- **入账统一 `applyDeltaToBalance(+value)`**(与 v0.12.0 现金路径对称、无全量重算的意外跳动):
  - 现金账户收入:`applyDeltaToBalance(+amount)`。
  - 股票 **+现金**(股息):`adjustAccountCash(+amount)` + `applyDeltaToBalance(+amount)`(= 现有 `creditAccountBalance`)。
  - 股票 **+股数**:`holding.shares += addShares` + `applyDeltaToBalance(+value)`(value=addShares×单价·账户币种)。**不走 adjustAccountCash**(那是加现金,这里是加股)。
  - 三者持仓/现金已持久变更 → 下次估值刷新 `Σ持仓` 与 applyDelta 的 +value 一致(价不变时相等;价变部分归 PnL),不双计。
- **删除 = `softDelete(id)` + 反向冲回**,按 `cash_flow.ref_holding_id` 判形态:
  - `ref_holding_id != null`(+股数那笔):`holding.shares −= ref_shares` + `applyDeltaToBalance(−amount)`;持仓已归档/删则只冲 flow + 告警。
  - 否则:`creditAccountBalance(−amount)`(现金/股票现金对称冲回)。
  - `softDeleteCashFlow` 内统一按 ref_holding_id 分支 → 账户明细删按钮 与 收入侧删按钮 走同一后端、结果一致。改额 = 删旧 + 录新。
  - 家庭汇总/未解释额是派生量,删一行自动正确。
- **一致性验收**:删/改后 账户余额、未解释额、家庭收入汇总三处同时对;账户级其它流水不受影响。
- **选定 · 加两列 nullable `cash_flow.ref_holding_id`/`ref_shares`** 记 +股数收入的冲回信息。
- **备选(否)** note 编码 `stock:hid:shares`:零 DDL,但结构化串会在账本/收入列表 UI 露出(丑);nullable 列干净、可测、ADD COLUMN NULL 对 prod 老行 0 影响([[feedback_prod_backward_compat]] 允许)。
- **备选(否)** 删除时按 value÷现价反推股数:价变则错。

## 决策 7 · 未上市(MANUAL)持仓升级为「股数 × 单股估值」(FR-149 · prod schema 语义变更)
- **背景**:现 MANUAL 只存 `manual_value`(整笔总市值)、`shares=NULL`。要支持"未上市收入只录 +股数",必须让 MANUAL 也带股数 + 单股价。
- **选定 · 复用 `shares` + `manual_value` 语义改为"单股估值"**:MANUAL 总市值 = `shares × manual_value`。
  - **迁移 V35(纯数据 · 零 DDL · backward-compat)**:`UPDATE stock_holding SET shares=1 WHERE valuation_mode='MANUAL' AND (shares IS NULL OR shares=0);` → 现有未上市按 **1 股** 折算(单股 = 原整笔值),`1 × manual_value = 原总值`,**估值不变**。用户之后可手动改成正确股数/单股(FR-149)。
  - **估值**:`valuateInternal` MANUAL 分支 `manualBase += (shares==null?ONE:shares) × manualValue`(null 兜底老数据)。
  - **CASH 不受影响**:CASH 仍 `manual_value=金额`、`shares=NULL`,估值分支独立(`manualValue×fx`)——`manual_value` 的"单股 vs 金额"语义按 mode 分流,不冲突。
  - **createManual(displayName, shares, unitValue)**:写 shares + manualValue=unitValue。
  - **编辑未上市**:`updateManual(holdingId, shares, unitValue)`(可分别改股数/单股)。收入录入只**联动展示**单股估值、不在收入里改。
  - **convertToManual**(AUTO→手填):保留 AUTO 的 shares,`manualValue(单股) = currentValueAsBaseline ÷ shares` → 总值不变。
- **备选(否)** 新增列 `manual_unit_value`:更"显式",但与"shares×unit=total"信息重复、要维护两份、DDL 面更大;复用 shares+改 manual_value 语义(按 mode 分流)最小且总值天然向后兼容。
- **备选(否)** 不升级、收入按"整笔增量估值"录:用户明确要"只录 +股数"(与上市对称),整笔估值不满足;且未来持股数是有用信息。
- **红线**:所有读 MANUAL.manualValue 当"总市值"的地方必须改成 `shares×manualValue`(全量 grep `getManualValue` + `ValuationMode.MANUAL`,估值/展示/convert 三处);`shares=1` 迁移保证老数据总值不变。

## 数据模型变更

**V34(已存在 · v0.12.0)** — `cash_flow_category.account_type` + 新类目。本轮不改 V34 文件。

**V35(本轮 · 全 backward-compat)**
```sql
-- V35__stock_income_holding_model.sql
-- 1) 未上市持仓升级为「股数×单股估值」:老数据按 1 股折算(单股=原整笔值,总值不变)
UPDATE stock_holding SET shares = 1
 WHERE valuation_mode = 'MANUAL' AND (shares IS NULL OR shares = 0);
-- 2) 停用卖出回款收入类目(不算收入 · 保留行以维持历史 cash_flow 外键)
UPDATE cash_flow_category SET sort_order = 999 WHERE code = 'stock_sell';
-- 3) +股数收入的冲回信息(nullable · 老行全 NULL · 走现金冲回路径)
ALTER TABLE cash_flow ADD COLUMN ref_holding_id BIGINT NULL
  COMMENT 'v0.12 股票+股数收入:关联持仓 · 删除时按 ref_shares 冲回股数';
ALTER TABLE cash_flow ADD COLUMN ref_shares DECIMAL(15,4) NULL
  COMMENT 'v0.12 该笔收入新增的股数';
```
- MANUAL `shares=1` → `1×manual_value=原值`;stock_sell 仅排序沉底 + 前端隐藏;cash_flow 两列 ADD COLUMN NULL → prod 老行全 NULL、现有 SELECT 不选取、0 影响。

## 关键流程(伪代码)
```
recordStockIncomeExistingHolding(fam, mem, periodId, accountId, holdingId, addShares, cat, note):
  period=requireOpenPeriod;  account=requireStockAccount;  assertCategory(cat, INCOME, STOCK)
  h = holdingService.require(fam, holdingId);  assert h.accountId==accountId && mode in {AUTO,MANUAL}
  unit  = holdingService.currentUnitValueInAccountCcy(fam, h)   # AUTO:最新价×fx;MANUAL:manualValue(单股);无价→throw
  value = addShares × unit                                      # 账户币种
  holdingService.addShares(fam, holdingId, +addShares)          # shares += addShares(持久)
  applyDeltaToBalance(period, account, mem, +value)             # 立即入 snapshot(与现金路径对称)
  insertCashFlow(INCOME, cat, value, note=humanReadable, refHoldingId=holdingId, refShares=addShares, is_adjustment=0)
  markDone; audit

recordStockIncomeNewManual(...): h=createManual(name, shares, unitValue); value=shares×unitValue; applyDelta(+value); insertCashFlow(ref=h)
recordStockIncomeNewAuto(...):   controller 先 fetchMarket(mk); h=createAuto(deductCash=false); unit=currentUnit(h)(null→throw); value=shares×unit; applyDelta(+value); insertCashFlow(ref=h)
recordIncome(现金 + 股票现金/股息): 不变 —— creditAccountBalance(STOCK:adjustAccountCash+applyDelta;else applyDelta) + insertCashFlow

softDeleteCashFlow(fam, cashFlowId):    # 收入侧删 与 账户明细删 共用
  cf=findById; period=requireOpen(cf.periodId); account=requireAccount(cf.accountId)
  if cf.refHoldingId != null:                                   # +股数那笔
     holdingService.addShares(fam, cf.refHoldingId, −cf.refShares)   # 持仓已删则跳过+告警
     applyDeltaToBalance(period, account, −cf.amount)
  else:
     creditAccountBalance(fam, period, account, (INCOME?−:+)cf.amount)   # 现金/股票现金对称冲回
  softDelete(cf.id); audit
```

## 风险与红线
- **MANUAL 语义变更漏改点(最高危)**:任何读 `MANUAL.manualValue` 当总市值处未改成 `shares×` → prod 估值错。用 `ManualHoldingSharesValuationTest` + 全量 grep `getManualValue`/`ValuationMode.MANUAL` 收口;`shares=1` 迁移兜底老数据。
- **股票收入被估值覆盖**:统一走"改持仓 → refreshAllForFamily",不 applyDeltaToBalance(决策 4/8)· `StockShareIncomeTest` 网住。
- **删除 +股数冲回**:靠 cash_flow.note 结构化 `stock:hid:shares`;持仓已删则降级只冲 flow + 告警。
- **无价新 AUTO**:收入值定格需价;无价时提示先刷新价或按 0 记 + 告警(不静默)。
- **backward-compat**:V35 纯数据 + 前端隐藏 · prod 老数据 0 影响 · deploy.sh 交互确认迁移。
- **10 分钟**:股票收入选账户→点持仓卡→填一个数,不超预算。
- **tag/push/发 prod**:完成后走 [[feedback_tag_must_verify]] · 等你验收 + `release vX.Y.Z`。
