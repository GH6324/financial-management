# Tech Design · v0.15 · 券商自动同步(富途 / 老虎 · 只读)

> 状态:**待评审(TDD 阶段)** · 对应 `prd/v0.15.md` · 预览 `preview/v0.15/broker-link.html`
> 本文是实施权威源。每个关键决策列备选 + 取舍 + 为什么不选([[feedback_tech_design_architecture]])。
> 红线:**只读、绝不下单**;复用现有持仓/估值链;凭据私密不入库明文([[feedback_prod_backward_compat]]);币种不变性([[feedback_currency_invariance]]);发布走 [[feedback_tag_must_verify]]。

## 0. 现状触碰面(实施前必读)
- 持仓模型 `stock_holding`(AUTO ticker+market+shares+cost_basis+currency / CASH currency+amount);估值 `AccountValuationService`(AUTO 按拉价、多币种经 FX 到账户币种再到本位币)。→ 券商持仓/现金**天然映射**到 AUTO/CASH,币种走既有 FX(满足 PRD FR-A 币种口径:落 native 币种,估值折算到用户选的账户币种)。
- 拉价路由 `StockPriceFetcher` + 定时 `DynamicScheduleConfig`(cron 受管);管理页 `/admin/integrations` 私密凭据范式(LLM key / 短信 aksk 存 `family_runtime_config`,不回显/不入 audit 明文)。
- 软删:`stock_holding.archive()` 是 `archived_at` 软删、`restore()` 可复原 → FR-B3「找回」的现成底座。
- 审计:`AuditLogService` 可落 JSON body → FR-B3 快照留痕。

## 1. 决策 A · 券商适配层(统一接口,隔离 SDK)
**问题**:两家 API 形态差异大(富途要网关、老虎纯 REST),如何接入不污染核心?

- **选定**:抽 `BrokerClient` 接口(**只读**),两实现 `FutuBrokerClient` / `TigerBrokerClient`,对标现有 `StockClient` 模式。
  ```
  interface BrokerClient {            // 只暴露读方法,物理上无下单入口
    BrokerVendor vendor();
    boolean testConnection(cfg);      // 一键测试:仅拉账户信息
    List<BrokerPosition> positions(brokerAcctId);   // ticker/market/shares/cost/currency/secType
    List<BrokerCash> cash(brokerAcctId);            // currency/amount
  }
  ```
  **为什么**:接口层就杜绝写操作(没有 placeOrder/unlock 方法可调);上层 `BrokerSyncService` 与具体券商解耦;新增券商只加一个实现。
- **SDK 选型(实现风险,TDD 落地前确认)**:
  - 富途:官方 **Java SDK `futu-api`** → 连本地 `FutuOpenD`(TCP 127.0.0.1:11111)。只用 `OpenSecTradeContext` 的 `getPositionList` / `getFunds` 查询,**永不 `unlockTrade`**。
  - 老虎:官方 **Java SDK `openapi-java-sdk`**(tiger_id + RSA 私钥签名)→ 只调 `TradeClient.getPositions/getAssets`。
  - ⚠ 两个 SDK 的 Maven Central 可用性 / 版本需在开工首步确认;不可用则 jitpack 或 vendored jar(记入实施顺序第 0 步)。

## 2. 决策 B · 富途 OpenD 部署(富途优先,门槛最高)
**问题**:FutuOpenD 要常驻 + 登录富途账号,自托管环境放哪跑?

- **备选 B1 · 应用内嵌**:✗ OpenD 是富途闭源二进制,不能进 jar。
- **备选 B2 · 用户自机跑、账房跨网连**:✗ 要暴露 11111 到公网/隧道,安全差、配置乱。
- **选定 B3 · OpenD 作为 compose 可选 sidecar**:docker-compose 加一个 **opt-in profile** 的 `opend` 容器(官方 Linux 版),app 连 `opend:11111`;用户在其中登录自己的富途账号(OpenD 支持配置式登录 + 首次设备/短信验证)。**富途接入整体是可选功能**,没配 OpenD 的用户不受影响。
  - **为什么**:sidecar 把网关收在同一编排内、不出网;opt-in 保证不给不用的人增负担。**代价**:首次登录有设备验证门槛 + OpenD 掉线需重登(登录态自动续期记入 backlog,本版不做)。
- 老虎无网关,纯 key,部署零负担 —— 但**按你定的富途优先**,富途走通 B3,老虎顺带接上。

## 3. 决策 C · 数据模型(迁移 V39)
- **新表 `broker_link`**(账户↔券商绑定 + 同步元数据),比在 account 上堆列更干净:
  ```
  broker_link(id, account_id UNIQUE, vendor ENUM(FUTU/TIGER), broker_account_id,
              enabled, last_synced_at, last_status, created_at)
  ```
- **`stock_holding.sync_source` VARCHAR(8) NULL**(FUTU/TIGER/null-手填):reconcile 只动带标记的行,**绝不碰用户手填**。
- 凭据不进这两处:走 `family_runtime_config` 私密 key(tiger_id / tiger_private_key / futu_opend_host / futu_opend_port),与 LLM key 同款私密纪律(不回显、不入 audit 明文)。⚠ 残留风险:老虎私钥可交易,故文案要求最小权限 key + 我方永不下单;富途只读不解锁,泄露也无法交易。
- 纯新增表 + 新增可空列 → prod 向后兼容零风险。

## 4. 决策 D · 同步 reconcile
`BrokerSyncService.sync(accountId)`:
1. 读 `broker_link` → 选 `BrokerClient` + broker_account_id。
2. `positions()` + `cash()`。
3. 归一:富途 `HK./US./SH./SZ.` + 老虎 symbol+market → `Market`+ticker;**secType ≠ 股票的(期权/期货)跳过并计数**(FR-A / backlog)。
4. 对账(**只动 `sync_source`=本 vendor 的行**):券商有我方无→建 AUTO;都有→更 shares/cost;我方有券商无→**软归档**;现金按币种 upsert CASH。
5. 持仓 `currency` 落 **native 币种**(不强转);估值层按账户币种 FX 折算(满足 PRD 币种口径)。
6. 更新 `last_synced_at/status` → 触发既有估值刷新 → 写回余额;返回"已同步 N 持仓 / M 现金 · 跳过 K 期权期货"。

## 5. 决策 E · 触发(手动 + cron)
- 手动:持仓页 / 填报页「同步券商」按钮 → `sync(accountId)`。
- 定时:`DynamicScheduleConfig` 加受管任务 `broker-sync`(`K_BROKER_SYNC_CRON`,数据源接入页配),遍历所有 `enabled` 的 `broker_link` 同步。

## 6. 决策 F · 只读铁律(硬约束 + 守护)
- `BrokerClient` 接口**只有读方法**,无任何下单/解锁签名 → 上层无从调用。
- 富途:只用查询上下文、**永不 `unlockTrade`**;老虎:只调 `getPositions/getAssets`,**永不 `placeOrder`**。
- **静态守护(qa)**:扫 `FutuBrokerClient`/`TigerBrokerClient` **不得出现** `unlock`/`placeOrder`/`modifyOrder`/`cancelOrder` 等写调用;接口无写方法。
- 「测试连接」只拉账户信息,不做任何写。

## 7. 决策 G · 已有账户关联安全(FR-B3)
- 关联(替换)前:①对被接管持仓写 `audit_log(LINK_BROKER, JSON明细)` ②`archived_at` **软归档**(不物理删)。
- Controller 强制**两步确认**(`confirmed=true` + `acknowledged=true` 参数缺一不执行)。
- 解绑:`broker_link.enabled=false`;同步来的持仓保留(清 `sync_source` 变普通持仓);被归档旧持仓可 `restore`。

## 8. 测试与守护(重要:本特性无法在 beta 真机 e2e)
- **诚实约束**:券商同步需**真实账号 + 凭据**(富途还需 OpenD 登录态 + 设备验证),beta/dev 环境没有 → **不像金价那样能真机 e2e**。故:
  - **UT 为主**:`BrokerSyncService` reconcile(mock `BrokerClient`:新建/更新/归档/现金 upsert/期权跳过/只动 sync_source 不碰手填)· 代码归一(富途/老虎 code→Market+ticker)· 关联替换写审计+软归档 · 两步确认缺参拒绝。
  - **静态守护(qa)**:V39 迁移(broker_link + sync_source)· BrokerClient 只读无写方法 · 两实现无 unlock/placeOrder · 凭据走 family_runtime_config · 管理页券商段。
  - **真机验收**:由**用户用自己的富途/老虎账号**做(自建 OpenD / 填 key → 关联 → 同步 → 核对持仓)。这点在交付说明里讲清。
- 币种不变性:关联账户估值并入净资产,三视图比值不变(纳入 `CurrencyInvarianceTest` 面)。

## 9. 非目标(承 PRD)
不下单/改单/转账;不做期权/期货/债券、不做大陆 API(均入 `docs/backlog.md`);不做富途登录态自动续期;不做逐笔成交流水。

## 10. 实施顺序
0. **确认 futu-api / tiger openapi Java SDK 的 Maven 可用性 + 只读调用面**(不可用则 jitpack/vendored;这步卡住则回报)。
1. V39 迁移 + `broker_link` 域/Mapper + `stock_holding.sync_source`。
2. `BrokerClient` 接口 + `TigerBrokerClient`(先易:纯 key)→ 再 `FutuBrokerClient`(OpenD)。**按你定富途优先,但工程上老虎无网关更快跑通对账逻辑,建议先用老虎跑通 reconcile,再补富途 OpenD**(实现顺序,非交付顺序;两家同版交付)。
3. `BrokerSyncService` reconcile + 归一 + 期权跳过。
4. 关联流程:新建向导 option + 已有账户两步确认 + FR-B3 快照/软归档 + 解绑;持仓页/填报页「同步券商」。
5. 管理页数据源接入「⑥ 券商同步」段(老虎 key / 富途 OpenD + 测试连接)+ `broker-sync` cron。
6. compose `opend` opt-in sidecar + 部署文档。
7. UT + qa 静态守护 + 文档/计数;交付说明写明"真机验收由用户自账号做"。
8. 用户 review → release([[feedback_tag_must_verify]])。

## 迭代补记 · v0.15.x(beta 验收反馈)

**决策 H · 关联与首次同步拆两段事务(修 rollback-only)。**
- 现象:`link()`(`@Transactional`)内直接调也 `@Transactional` 的 `sync()`;富途 stub 抛异常时把共享事务标 rollback-only,即便异常被 catch,外层提交仍抛 `UnexpectedRollbackException` → 用户见「关联失败:Transaction rolled back」。
- 备选:(a) `sync()` 改 `REQUIRES_NEW` —— **否决**:新事务读不到同一未提交事务里刚 insert 的 `broker_link`(读已提交隔离),首次同步会「找不到关联」;(b) 在 `link()` 内 catch 后手动 `setRollbackOnly(false)` —— 否决:脆弱、违背事务语义;(c) **拆两段(选定)**:`link()` 只做快照+软归档+建绑定并提交;controller 在其提交后另起 `initialSync()`(独立事务)跑首次同步。首次同步能读到已提交的绑定,且它失败不牵连关联本身。
- 护栏:`v15-FIX-TX`(qa-run)+ `BrokerLinkSafetyTest` 断言 `link()` 返回 void、`initialSync()` 分离。

**决策 I · 二次确认自建弹窗 + 建证券账户同步提示 + 凭据图文向导。**
- 二次确认去掉 native `confirm()`,改复用现有 paper-card/btn 类的自建模态(ESC/遮罩关闭),与晚清账册风一致([[feedback_no_emoji]] 同源:UI 要自控)。
- 新建账户向导 `select[name=type]=STOCK` 时 JS 切换显示同步提示(searchable-select 在原生 select 上 dispatch change,监听可靠)。
- 凭据门槛高 → 新增 `HelpController` + `help/broker-sync.html` 图文向导(SVG 示意图,不内嵌第三方真实截图:版权 + 会过时;用示意图 + 官方链接),字段一一映射到管理页 ⑥ 段输入框。护栏 `v15-HELP`。

**决策 J · 富途 OpenD 部署方案(承决策 B · 用户「两者平级、补部署方案」)。**
- 关键事实澄清:富途无「keyless/keyed 云端直连 API」,`futu-api` SDK 只能连 OpenD 网关 → 富途必须有一个常驻、且 app 能 TCP 直连的 OpenD。老虎是云端直连、零网关(故老虎才是低运维路径,文档明说「嫌重先用老虎」)。
- OpenD 只是 host:port 配置 → 给三种拓扑,用户按部署形态选:
  - **A 同机 systemd(首选,贴合 prod 现状)**:命令行 OpenD 常驻同机,`deploy/futu-opend.service.example`(账号密码走 `chmod 600` 的 `/etc/futu-opend.env`,`api_ip=127.0.0.1`)。
  - **B docker sidecar**:`deploy/futu-opend.compose.yml` 覆盖文件(`-f` 显式合并才生效,默认部署不受影响;富途无官方镜像 → `${FUTU_OPEND_IMAGE}` 用户自备)。
  - **C 家用机 + SSH 反向隧道**:不在云机放登录态,`ssh -R 11111:127.0.0.1:11111`。
- 共同前提(诚实告知):首次登录需在**有桌面机器**用可视化版过掉问卷 + 协议;OpenD 须常开。护栏 `v15-OPEND`。
- 为什么不做「turnkey 官方 OpenD 镜像」:富途未提供官方镜像、首登问卷需人工 → 不假装一键,给模板 + 覆盖文件 + 诚实文档。

**决策 K · OpenD 傻瓜向导「渠道自适应」(承用户「三渠道全覆盖」)。**
- 起因:应用自管子进程这套本是照 Linux 原生写的,直接套 Docker / macOS 会坏:Docker 运行镜像无 gtk3 + 一容器一进程 + 家目录非持久卷;macOS 是 `.app` 结构、无 `ldd`、包名不同。
- `FutuOpendManager.detectEnv(osName, /.dockerenv)` → `LINUX / DOCKER / MACOS`,分渠道:
  - **LINUX**:现有子进程托管(下载/解压/ldd/启动)。
  - **DOCKER**:`download()`/`configureAndStart()` 直接拒绝并引导 → 向导渲染 sidecar 面板(`deploy/futu-opend.compose.yml`),不在 app 容器内跑。
  - **MACOS**:`packageTag=Mac`、`locateBinary` 深度 6 够到 `FutuOpenD.app/Contents/MacOS/FutuOpenD`、`checkDeps` 短路(mac .app 自带、免 gtk3)、启动参数复用。
- 护栏:`FutuOpendManagerTest` 增 `detectEnv`/`packageTag` 单测;`v15-OPEND-WIZ` 断言含 detectEnv/dockerenv/packageTag/DOCKER 分支。
- 诚实边界:Docker 需自备含 gtk3 的 OpenD 镜像;首登问卷仍是账号级外部前提。
- **上传兜底(墙内可达性)**:服务器连不上富途 CDN 时,向导第 1 步提供「上传已下好的 tar.gz」——裸 `application/octet-stream` 流(绕过 multipart 200KB 限额、CSRF 走 `?_csrf=`、代码内 500MB 上限),`installFromStream` 落盘 + 复用 `extractAndFinish`。彻底不依赖本机外网。护栏 `v15-OPEND-WIZ` 含 installFromStream/`/upload`/上传并解压。

**决策 L · 富途适配器真机接线(stub → 真 SDK 实现,已对活 OpenD 联调通过)。**
- 时机:用户 OpenD 在 beta 登录成功(问卷/短信闸门已过)→ 决策 B 里"无法 runtime 验证"的前提消失,当即接线。
- 结构:`FutuSession implements FTSPI_Conn, FTSPI_Trd` —— 每次调用开一条到 OpenD 的连接,`CompletableFuture` 把异步回调包成同步;**顺序单请求**(每类请求一个 pending future,发送前先置 future)避免 serial 竞态;15s 超时;`onDisconnect` 把 pending 全部异常完成防挂死;用完即 close。
- 只读铁律不变:仅 `getAccList / getPositionList / getFunds`;`BrokerReadOnlyGuardTest` + `v15-RO-1` 仍绿。
- 归一:持仓按 `TrdSecMarket`(1→HK, 2→US, 31/32→CN,其余跳过计数);持仓币种随市场(HK→HKD/US→USD/CN→CNY);现金走 `Funds.cashInfoList` 按币种(CNH 归 CNY),空则回退 `cash+currency`;仅实盘(TrdEnv=1)+ 多头;`brokerAccountId` 匹配 accID、留空聚合全部实盘户。
- 真机验证(beta · 用户真实富途账号):测试连接 → 「实盘交易账户 2 个(共 10 个)」;app 重启后 OpenD 自动重拉且免短信(设备已信任)。
