## 一、需求分析

### 1. 背景 & 目标

见 PRD §0。技术上的主线只有一条:**「分母里有谁」从写死的「全部账户」变成一个显式的、可切换的「分析范围」**,
并且它只作用在「占比类」上;AI 在此之上多两层可配置的文字输入(模板、偏好),这两层**只进提示词、不碰任何数字**。

### 2. 需求理解(验收口径)

| FR | 工程判据 |
|---|---|
| FR-800/801 | `account.analysis_excluded`;只有 `FamilyDiagnose.allocation / riskDistribution`、规则、配置锚、洞察集中度 / 再平衡 / 低利率读它;KPI、收益、流动性、快照、导出、目标**不读** |
| FR-803 | 标记不进 `period_account_attr`(不定格),所有账期读当前值 |
| FR-805 | `RISK-1 / RISK-2` 对 `analysisExcluded` 账户直接返回 empty |
| FR-820 | `AnalysisScopeService.options()` 只返回「排除集非空」的选项;`options().size() == 1` → 模板不渲染切换 |
| FR-826 | 范围内资产行在锚期合计 ≤ 0 → `scope.empty()`;配置 / 风险卡空态、配置类规则不评估、AI 不调用 |
| FR-846 | `GENERAL` 模板 + `ALL` 范围 + 无偏好 + 家里有房产 → 三个配置类 AI 的提示词与 **v1.26.1 tag 生成的金样本逐字相同**(调仓除外:FR-875 要求它多出余额行,只允许多这几行) |
| FR-848 | 缓存键 = f(范围, 排除集, 模板 key@version, 偏好指纹, 自定义锚 JSON) |
| FR-853 | 本机模式:偏好块拼进每轮系统提示词;托管模式:拼进每轮用户事件并回显确认 |
| FR-856 | `AGGREGATE` 口令下 `pivot` / `capabilities` 不出现 `group` 维(未分组时它就是账户名) |
| FR-870 | 某桶在范围内金额为 0(房产 / 保险)→ 该桶不参与,其余目标按原比例放大到 100 |
| FR-873/874 | `AllocationDiff.pickBucket(OTHER) = null`(另算 `otherAmount`);金融盘 = CASH+STOCK+WEALTH+CRYPTO+METAL+INSURANCE |

## 二、关键选型

### 选型一 · 「不参与配置分析」存在哪

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| **A** | `account` 加一列 `analysis_excluded` | 和账户同生命周期;列表 / 编辑页 / 规则都已经拿着 `Account` | 加列 | **选它** |
| B | `family_runtime_config` 存一串账户 id | 不改表 | 账户删除 / 归档后留脏 id;每处都要再查一次配置再对 id;和账户编辑页的表单保存不在一个事务里 | 不选 |
| C | 按账期定格进 `period_account_attr` | 历史报表口径可复现 | PRD ⑥ 定了「不定格」—— 这是「怎么看」不是「资产是什么」;定格后改标记不影响历史,用户会以为没生效 | 不选 |

### 选型二 · 范围怎么作用到计算上(**这版最关键的一处**)

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 按范围再 `factViewService.load(FactFilter(accountIds=范围内))` 取一张切片 | 复用现成筛选 | **「全都标了」→ 空列表 → `FactFilter` 当成不筛选 → 静默全量**;多一次查库 | 不选 · 正是 PRD §9 ④ 那个坑 |
| **B** | 页面照常加载全量切片,占比类在**内存里** `slice.restrictTo(includedIds)` 得到第二张切片 | 空集就是空集,没有「空 = 全部」的歧义;不多查库;绝对数(KPI)和占比数来自同一次加载,不会因为两次加载锚到不同期 | 需要逐个占比入口改成吃第二张切片 | **选它** |
| C | 在规则 / 模板里按账户类型把房产那几行减掉 | 改动小 | 「标记」和「金融资产」两种范围各写一套;规则、洞察、配置锚三处各减一遍 —— 就是本项目「同一件事三份判据」那个 bug 家族 | 不选 |

**选定理由**:B 把「分母里有谁」收成一个值对象 `AnalysisScope`(排除集 + 名字 + 占比),所有占比入口吃它;
「排除」而不是「包含」作为主语义 —— 新建的账户默认就在范围内,不需要谁记得把它加进去。

### 选型三 · 分析模板怎么存

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 内置和自定义都进库(种子迁移) | 一张表 | 我们升级内置模板要写迁移改用户库;回滚 jar 时模板不回滚 | 不选 |
| B | 自定义存「相对内置的差量」 | 省空间 | **内置一升级,用户的定制就跟着变了味,而且没人发现**(PRD §9 ⑥) | 不选 |
| **C** | 内置随代码走(`BuiltinTemplates`,带 `version`);「我的模板」进库,存**完整副本** + 来源 key + 来源版本 | 回滚 jar = 回滚内置模板;用户副本永远逐字不变 | 内置改了,用户副本不会自动得到改进 —— 这是**要的效果**,不是缺点 | **选它** |

模板**不开放整段提示词编辑**(PRD ⑰ / FR-844):模板 = 结构化字段(侧重 1–4 / 立场 / 范围 / 配置锚)+ 可选补充要求(≤500 字);
「不许算数、数字引用、合规底线」留在各 AI 的系统提示词里,模板改不到。

### 选型四 · 家庭默认范围 / 默认模板存在哪

| 方案 | 优 | 劣 | 结论 |
|---|---|---|---|
| `family` 表加列 | 强类型 | 两个「偏好」性质的值要改核心表 | 不选 |
| **`family_runtime_config` 两个键**(`analysis_scope_default` / `analysis_template_default`) | 与阈值、提醒时间同一套运行时配置;5 秒缓存;有页面入口(分析设置)过 `v126-CONFIG-KEY-HAS-HOME` | 字符串值要校验 | **选它** · 不存在或非法 → 按 FR-822 / FR-845 推导(有标记 → 可调整;否则全部;模板 = 综合体检) |

### 选型五 · 分析偏好怎么送到 AI(**托管模式是难点**)

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 只拼进系统提示词 | 简单 | **托管模式每轮不发系统提示词** → 改了偏好要点「更新 Agent」才生效,而且不报错(PRD §9 ③) | 不选 |
| B | 改偏好时自动调「更新 Agent」 | 托管也生效 | 更新是全量替换、有覆盖别环境 agent 的前科(v1.20.2);百炼的会话**锁定创建时的模板版本**,已开的对话照样拿不到 | 不选 |
| **C** | 每轮带一段「分析上下文」:本机模式拼在系统提示词后;托管模式拼在**用户事件**前,并用百炼的回显确认它真的收到了 | 下一句话就生效;不动 Agent 模板;回显可审计 | 托管会话历史里每轮多一段(控制在 10 行以内,没偏好 / 默认模板 / 全部资产时只剩一行「记住」说明) | **选它** |

「分析上下文」一处生成(`AnalysisPromptBlocks.agentContext`),两种运行时只是放的位置不同。

### 选型六 · 超级 Agent 怎么「提议记住」

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| A | 加一个写工具 `save_preference` | 直接 | **只读口令也能调到写工具**(MCP 对外暴露同一张工具表)—— 违反 FR-855;AI 自己就能存,违反「只有用户点了才算」 | 不选 |
| B | 加一个「提议」工具,不写库,返回卡片数据 | 不写库 | 托管模式下工具在百炼侧调、经 `/mcp` 回到我们,卡片要从事件流里扒参数;外部客户端也能调(虽然无害,但「只读口令不能提议」要额外判) | 不选 |
| **C** | 正文标记 `{{remember:…}}`,和既有 `{{next:…}}` / `{{cite:…}}` 同一套机制;渲染成确认卡,「记住」是**用户点的表单提交**(会话鉴权 + CSRF) | 工具表里**物理上没有**写能力,只读口令天然只读;本机 / 托管同一条路径;回放、导出与 `{{next}}` 一样走正文 | 模型可能不写标记(那就是没提议,不出错) | **选它** |

标记语法:`{{remember:原文}}` · `{{remember:原文|STEADY}}`(再给「切到某内置模板」「基于当前模板定制」)· `{{remember:原文||exclude=账户名}}`(再给「把 X 标成不参与配置分析 →」)。
渲染层只认内置模板 key 与本家账户名,其余丢弃。

### 选型七 · 缓存键怎么加维度而不改表

| 缓存 | 现状 | 方案 |
|---|---|---|
| 综合诊断 / 洞察(内存 1h) | `sha256(scope|entity|userPrompt)` | 键里再加系统提示词。范围 / 模板 / 偏好都进了提示词,自然分开 |
| AI 调仓(`rebalance_advice_cache`,唯一键 family+anchor,`anchor_code VARCHAR(32)`) | 只按锚 | **不改表**:`anchor_code = 锚` 或 `锚|16 位指纹`(指纹 = 范围 + 排除集 + 模板@版本 + 偏好 + 自定义锚 JSON)。基线组合(全部资产 · 综合体检 · 无偏好 · 非自定义)仍是纯锚码,老缓存照常命中 |
| AI 月度复盘(`review_ai_cache`,唯一键 family+period+dim,`dim VARCHAR(20)`) | 不含账户筛选、币种(PRD ⑩) | 同法:`dim` 或 `dim|8 位指纹`(账户筛选 + 币种 + 偏好);`deleteByPeriod` 仍一把清 |

不改唯一索引,是因为 prod 表上改唯一键要重建索引;编码进现有列,回滚 jar 后老代码按纯锚码 / 纯维度读,**只是读不到新格式的行**(无害)。

## 三、系统概要设计

### 1. 整体设计思路

```
                  ┌─────────────── 分析设置(管理页)───────────────┐
                  │ 默认范围 · 模板 · 不参与账户 · 配置锚 · 偏好     │
                  └───────┬───────────────┬──────────────┬─────────┘
account.analysis_excluded │ runtime_config│ analysis_template / analysis_preference
                          ▼               ▼              ▼
             AnalysisScopeService   AnalysisTemplateService   AnalysisPreferenceService
                          │               └──────┬───────┘
                          ▼                      ▼
      FactSlice(全量)──restrictTo──► 占比类         AnalysisPromptBlocks(纯函数)
      KPI/收益/流动性 ◄─── 全量          │  配置/风险卡          │ 范围段 · 模板段 · 偏好段 · Agent 上下文
                                       │  配置类规则          ▼
                                       │  配置锚 / 洞察     PromptBuilder / InsightPromptBuilder /
                                       ▼                   RebalanceAdvisor / 复盘 / 透视 / 目标 / Agent
                                    页面卡片
```

### 2. 领域模型设计(同步进 `AGENTS.md` 领域概念节)

| 概念 | 是什么 | 边界 |
|---|---|---|
| **不参与配置分析**(`account.analysis_excluded`) | 账户上的偏好标记 | 只影响占比类;不定格;贷款不可标 |
| **分析范围**(`AnalysisScope`) | `ALL` / `ADJUSTABLE`(排除标记)/ `FINANCIAL`(排除 PROPERTY、OTHER 类型)· 值对象 = 种类 + 排除集 + 排除名字 + 排除占比 + 是否为空 | 以**排除集**为主语义;空排除集的选项不出现 |
| **分析模板**(`AnalysisTemplate`) | 侧重(1–4)· 立场 · 范围(跟随 / 固定)· 配置锚(跟随 / 指定)· 补充要求 | 只改 AI 提示词;不改数字与规则卡片 |
| **分析偏好**(`analysis_preference`) | 家里人写给 AI 的句子,≤200 字 × 10 | 只进提示词;脱敏同真名映射 |
| **有效目标**(配置锚) | 锚目标去掉范围内为 0 的房产 / 保险桶后按比例放大 | 现金、投资桶始终参与;自定义锚没填 → 不出对照 |

### 3. 代码架构设计

新包 `service/analysis/`:

| 类 | 职责 |
|---|---|
| `AnalysisScope` | 值对象;`includes(accountId)`、`apply(FactSlice)`、`excludedLabel()`、`empty()` |
| `AnalysisScopeService` | 选项(只出有区别的)、解析(`?scope=` → 家庭默认 → 推导)、设默认 |
| `AnalysisTemplate` / `BuiltinTemplates` | 5 个内置(`GENERAL`/`STEADY`/`GROWTH`/`PORTFOLIO`/`DEBT`),各带 version |
| `AnalysisTemplateService` | 列表、解析(`?tpl=` → 家庭默认 → GENERAL)、定制(完整副本)、存、删、上限 10 |
| `AnalysisPreferenceService` | 增删停用、上限、启用列表、指纹 |
| `AnalysisPromptBlocks` | **纯函数**:范围段、模板段、偏好段、Agent 上下文;定制页「AI 会收到的要求」也调它 —— 页面看到的与发出去的是同一份 |
| `AnalysisContext` / `AnalysisContextService` | 一次请求解析出「范围 + 模板 + 偏好」,供三个配置类 AI 与页脚用 |

改动的既有类(**新逻辑挂在服务层,不在模板和控制器里各算一遍**):

- `FactSlice.restrictTo(Set<Long>)` —— 唯一的「按范围取第二张切片」入口
- `FamilyDiagnoseService.diagnose(familyId, scope)` —— `allocation` / `riskDistribution` 吃范围切片,其余吃全量;`FamilyDiagnose` 带上 `scope`
- `RuleContext.scope` · `FamilyRules`(`FAM-RISK-2` 补加密 / 贵金属 · `FAM-CON-1` 行动按钮)· `LensConcentrationRules`(头寸按范围过滤)· `AccountRules`(本位币余额 · 跳过被标记)
- `AllocationDiff`(`OTHER` 不进桶 · `effectiveTarget` 放大)· `AllocationService.compute(familyId, slice, scope)`
- `AssetInsightService.compute(familyId, slice, scope)` —— 集中度 / 再平衡 / 低利率吃范围;资产负债表吃全量
- `PromptBuilder` / `InsightPromptBuilder` / `RebalanceAdvisorService` / `ReviewInsightService` / `LensInsightService` / `GoalLlmService` —— 追加段落,基线组合不追加
- `AskConversationService` + 两个 runtime(上下文放置)· `AskCitationRenderer`(`{{remember}}`)· `PivotTool` / `CapabilitiesTool` / `PeriodSummaryTool` / `AccountPerformanceTool`(范围、排除、汇总口令不出账户名)· `ManagedAgentRuntime.updateAgent`(保留远端)

**会不会多出第二条求和路径**:不会。范围切片与全量切片是同一次加载的子集,占比仍由 `allocationByType` / `AllocationDiff` 算;
没有任何地方用「总资产 − 被排除」去凑分母。

## 四、接口协议设计

### 1. 影响评估

| 入口 | 变化 |
|---|---|

### 2. 对外接口

`/mcp` 与 `/api/ask/**`:**仍然只读** —— 工具表里没有任何写工具(选型六);`remember` 只在会话鉴权的站内端点。
汇总口令(`AGGREGATE`)下 `pivot` 拒绝 `group` 维(行 / 列 / 筛选 / 排除),`capabilities` 不列它的取值,`period_summary` 的范围信息只给个数与占比。

### 3. 我们调用的上游接口

百炼 `POST /sessions/{id}/events`:请求形状不变,只是 `content[0].text` 前面多一段分析上下文。回显(实测形状,脱敏):

```
{"data":[{"id":"evt_…","type":"message","role":"user","content":[{"type":"text","text":"[分析上下文 …] … 用户的问题"}]}]}
```

`ManagedAgentRuntime` 读回 `data[0].content[0].text`,含上下文段落里的偏好首句 → `ctx_note` 记「回显确认」。

## 五、稳定性与质量保障

### 1. 兼容性设计

- **没标记、没设任何东西的家庭**:范围只剩「全部资产」→ 切换不出现;模板 = 综合体检 → 模板段为空;偏好为空 → 偏好段为空。
  体检、报表、三个配置类 AI 与 v1.26.1 **逐字相同**,例外只有 D 的纠错(PRD §6 口径变更声明)。
- **回滚窗口**:新代码写的「我的模板」「偏好」「标记」在老代码下无人读;缓存新格式的行老代码读不到(按缺失处理,重新生成)。

### 2. 性能评估

范围切片是内存过滤(单家庭几十个账户 × 13 期);体检页多算一次风险分布与配置 —— 可忽略。
`AnalysisScopeService.options()` 需要锚期余额,体检 / 报表复用页面已加载的切片,管理页单独加载一次。

### 3. 安全性设计

- **LLM prompt 里新增的**:被标记账户名(本来就在上传范围)与合计占比;分析偏好与补充要求原文(**先经同一层真名映射**,`PromptBuilder.applyMapping`,再拼进提示词;诊断路径的「提示词含真名就 abort」防御照常覆盖);调仓的各账户余额(PRD ⑨ 已裁)。
- **偏好 / 补充要求不越权**:固定包裹「以下是家里人写的……数字以系统给的为准,不许据此计算,不许荐股;与事实冲突时以事实为准并说出冲突」,放在所有材料之后(PRD §9 ⑤⑦)。
- **写入口**:偏好、模板、默认值、标记全部是会话鉴权 + CSRF 的站内表单;`/mcp` 无写能力。
- 偏好**不出现在任何对外接口的返回里**。
