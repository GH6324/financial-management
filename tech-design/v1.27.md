### 待实测(阻塞编码)

- [x] **`FactFilter` 的「空列表」语义** —— 构造器里 `accountIds` 为空列表时被改写成 `null` = 不筛选(`FactFilter.java` 构造器)。
  所以「全都标了」如果直接传空列表下去,会**静默变成按全部账户算**。设计上必须在上游拦住(见 §三.3 `AnalysisScope.isEmpty()`)。已读代码确认。
- [x] **透视持仓带不带账户 id** —— `calc/lens/Position.java` 第一个字段就是 `accountId`,`LENS-CON-1/2` 可以按账户过滤后再 pivot。已读代码确认。
- [x] **调仓建议缓存键的列宽** —— `rebalance_advice_cache.anchor_code VARCHAR(32)`,唯一键 `(family_id, anchor_code)`(`V23`)。
  最长锚码 `XQ_CONSERVATIVE`(15)+ 视角后缀 `@ADJ:` + 8 位指纹 = 28 ≤ 32,放得下。除 mapper 外没有任何地方读 `getAnchorCode()`(已 grep),把后缀编进去不会漏到界面上。
- [x] **`AssetInsightService.compute` 的调用方** —— 除体检 `/checkup/insight` 外,**仪表盘也调**(`DashboardController.java:381`)。仪表盘不跟随视角(PRD §4),所以这里只能加重载、不能改默认行为。
- [ ] **提示词逐字基线** —— 实施第一步:用 v1.24.5 的代码对一个固定 fixture 生成三个 AI 的提示词存成测试资源,之后「全部资产」模板与它逐字比对。没存下基线之前不许动 `PromptBuilder` / `InsightPromptBuilder` / `RebalanceAdvisorService`。

### 静默失败预检

| 可能的静默失败 | 怎么让它响 |
|---|---|
| 全都标了 → 空列表 → `FactFilter` 当成「不筛选」→ 页面照常出全量数字 | `AnalysisScope` 自己表达「空」,`isEmpty()` 时**不构建**分片、占比类直接给空态;单测 |
| 某个占比类组件没接视角,一页两个口径 | 占比类只允许从 `ScopedFacts.scoped()` 取;grep 护栏 `v125-SCOPE-ALL-RATIOS` 盯住 `allocationByType` / `riskDistribution` / `AllocationService.compute` / `lensQueryService.positions` 的调用点 |
| 调仓建议缓存按「家庭 + 锚」命中,切视角拿到另一视角的旧建议 | 缓存键 = 锚码 + 视角 + 标记集合指纹;单测 |
| 标记集合变了但缓存还在(标了一套房、又标了车) | 指纹是「被标记账户 id 排序后的哈希」,集合一变键就变;诊断 / 洞察的缓存键本来就是整段提示词的哈希,集合一变提示词就变 |
| 「全部资产」模板被顺手改了一个字,所有现存家庭的 AI 缓存全部失效、结论口吻悄悄变化 | 提示词逐字基线单测(见上) |

## 一、需求分析

### 1. 背景 & 目标

见 PRD §0。技术上现在做的理由:#22 刚把「不适用」修好,用户第一个会按的就是「房产占比过高」那张卡 —— 卡藏掉了,
而配置卡、配置锚、三个 AI 仍按全部资产算,用户会觉得「我明明说了不适用」。两件事是同一个诉求的两半。

### 2. 需求理解(验收口径)

| FR | 工程判据 |
|---|---|
| FR-701 | `account.analysis_excluded` 可写;`type = LOAN` 时编辑页不渲染该项,提交时服务端也强制写 0 |
| FR-702 | `FactMapper` / `FactViewService` 不读该列(grep);仪表盘、报表非配置 section 的数字在标记前后逐字相同 |
| FR-704 | 该列只在 `account` 表,不进 `period_account_attr`,不参与关账定格 |
| FR-710 / 712 | 无标记时 `AnalysisScope.hasMarks() == false` → 模板不渲染切换;`?view=all` 只从请求参数读,不写任何存储 |
| FR-713 | 配置卡、风险卡、7 条配置类规则、诊断与洞察(集中度 / 再平衡 / 现金占比)的输入全部来自 `ScopedFacts.scoped()` |
| FR-714 | 家底三项、收益、流动性、资产负债表的输入全部来自 `ScopedFacts.full()` |
| FR-715 | `AnalysisScope.isEmpty()` 时 `scoped()` 为空、占比类给空态、三个 AI 不调用 |
| FR-716 | `FAM-CON-1` 过线的是 `PROPERTY` / `OTHER` 时,`Advice.ctaHref` = 该类唯一账户的编辑页锚点;多个账户时 = 账户列表按类型筛 |
| FR-721 | `AllocationDiff.renormalizeTarget(target, droppedBuckets)`:被整类拿掉的桶置 0,其余按原比例放大,合计 100.00(尾差并入最大桶) |
| FR-730 / 731 | `AnalysisView.ALL` 时三个 AI 的提示词与基线逐字相同;`ADJUSTABLE` 时多一段视角说明,材料来自 `scoped()` |
| FR-732 | 诊断 / 洞察缓存键 = 提示词哈希(天然分开);调仓缓存键见选型四 |

## 二、关键选型

### 选型一 · 标记存在哪

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| **A · 账户表加一列** | `account.analysis_excluded TINYINT(1) NOT NULL DEFAULT 0` | 它就是账户的属性:账户页直接显示、归档 / 删除时随账户走,不会留孤儿;`family_id` 隔离天然继承 | 要一个迁移 | **选它** |
| B · 家庭配置里存一串账户 id | 同 #22「不适用」的做法,`family_runtime_config` 一行 | 零迁移 | 账户的属性放到账户之外,是两份真相:账户归档了,配置里还留着它的 id;账户页要显示标记还得去翻配置 | 不选 · #22 存的是「规则 + 账户」这种配对,本来就不属于任何一张表;这里是纯粹的账户属性 |
| C · 复用账户组:约定一个「不参与分析」组 | v1.20 账户组 | 零迁移,仪表盘筛选能直接快选它 | 账户组的语义是「这些账户合起来看」,一个账户可以在多个组里;让某个组带上「会改变体检口径」的隐藏行为,用户在组页面把它删了,体检口径就静默变了 | 不选 · 语义冲突 |
| D · 进 `period_account_attr`(按期定格) | 同资产类型 / 平台 / 用途 | 历史报表的配置锚对照不随后来的标记变化 | 定格的是「资产是什么」,这个是「怎么看」;按期存还意味着每期都得带上它、开新期要继承 | 不选 · PRD §13 ⑥ |

### 选型二 · 视角怎么落到计算上

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| **A · 两个分片** | 全量分片照旧;另用既有的 `FactFilter.accountIds` 构建一个「参与分析」分片。占比类从后者取,其余从前者取 | 复用仪表盘已经在用的筛选机制,不新造求和路径;占比在分片内部自然归一,**不需要「先算全部再减掉」** | 体检多一次取数 | **选它** |
| B · 在每个占比计算点事后剔除 | `allocationByType` 算完把被标记账户的金额减掉再重新归一 | 不多取数 | 计算点有七八处,每处一套「减掉再归一」,就是第二条求和路径 —— 本项目有 pivot 与 kpi 两条路径差 0.01 的前科;漏一处就是一页两个口径 | 不选 |
| C · 在 `FactMapper` 的 SQL 里按标记过滤 | 事实层直接不给被标记账户 | 改动集中 | 事实层是全站共用的,会把净资产、仪表盘、报表一起改掉 —— 恰恰是 PRD 明确不做的 | 不选 |

**多一次取数的代价**:体检现在一次请求取一个 13 期分片;选 A 后在有标记时取两个。单家庭数据量下是几十毫秒级,且只在有标记时发生。

### 选型三 · AI 的「两套模板」怎么实现

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| **A · 同一套提示词 + 视角前言 + 按视角取材料** | `AnalysisView` 各自给一段前言(`ALL` 为空串);构造器接收视角,材料从对应分片取 | `ALL` 与现状**逐字相同**,现存家庭的缓存和结论口吻都不动;两套模板只差「前言 + 材料」,不会各自漂移 | 模板之间差异受限于「前言 + 材料」 | **选它** |
| B · 每个视角一份完整的系统提示词 | 复制一份改 | 每个模板可以完全不同 | 三个 AI × 两份 = 六份大段文本,改一处要改两份;半年后必然漂移 | 不选 |
| C · 模板存数据库,管理页可编辑 | 通用模板引擎 | 最灵活 | 维护者明确说更多视角要么等方向、要么走超级 Agent 让用户自己沉淀;现在做编辑器是提前建设 | 不选 · PRD §4 |

**「可调整的资产」前言**(草稿,数字与名称由工程填):

```
## 分析视角:可调整的资产
这个家庭把以下账户标记为「不参与配置分析」—— 短期内不打算卖、也调不动:
  {名称列表}(合计占总资产 {占比},系统已算好)
下面「资产配置」「风险敞口」「集中度」「再平衡」的数字只含其余账户。
- 不要建议处置、降低或调整上面这些账户
- 不要把它们的占比当作配置失衡或集中度过高的依据
- 家底(净资产 / 总负债)与负债率仍是全家数字,照常引用
```

放在系统提示词之后、用户上下文最前面。它引用的「合计占总资产 X%」由工程算好填入 —— 承 `feedback_llm_no_math`。

### 选型四 · 视角状态放哪、缓存怎么分

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| **A · 网址参数** | `?view=all`;缺省 = 有标记则「可调整」 | 不存任何状态;刷新、分享链接保持;家人之间互不影响 | 离开页面再回来回到默认 | **选它** —— 「默认」本身就由用户的标记决定,标记才是持久的那个选择 |
| B · 存家庭配置(记住上次选的) | 同上,外加写配置 | 回来还是上次的 | 一个人切到「全部资产」,另一个人打开也变了;而页面上不会告诉他为什么 | 不选 |
| C · 存会话 | session | 不影响家人 | 换设备就丢;分享的链接打开后和发的人看到的不一样 | 不选 |

**缓存键**:

- 诊断 / 洞察:既有键 = `sha256(scope | entityId | userPrompt)`(`LlmDiagnoseService.java:242`)。视角与标记集合都会改变提示词 → **天然分开,不用改**。
- 调仓建议:既有键 = `(family_id, anchor_code)`,30 天(`RebalanceAdvisorService.java:90`)。改为 `anchor_code = 锚码`(`ALL`,与现状一致,旧行照常命中)或 `锚码@ADJ:{指纹}`(`ADJUSTABLE`)。
  指纹 = 被标记账户 id 升序拼接后 SHA-256 的前 8 位。**不加列、不改唯一键**。

### 选型五 · 配置锚被整类拿掉时的目标

| 方案 | 怎么做 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| **A · 去掉该桶,其余按比例放大** | 标普 4321 去掉房产 → 10/30/20 放大成 16.7/50/33.3 | 保留了原锚「各类之间的相对比例」这层意思;页面当场写出放大后的数 | 放大后的数不是任何「官方」模板 | **选它** |
| B · 该桶标「不参与」,其余目标不动 | 10/30/20,合计 60 | 目标数字不变 | 现状按「可调整」归一到 100,目标只有 60 —— 每一类都显示「超配」,偏离全是假的 | 不选 |
| C · 让用户另设一套不含房产的目标 | 引导去 CUSTOM | 最准 | 已经能做(CUSTOM 锚),不需要本版;但把它当默认路径等于让用户多一步 | 不选作默认 · 放大说明旁给一句「想自己定目标 → 自定义」 |

**整类拿掉的判据**:该桶在全量分片里余额 > 0,在参与分片里余额 = 0。部分拿掉(两套房标一套)不触发放大。

## 三、系统概要设计

### 1. 整体设计思路

```
            account.analysis_excluded (唯一的写入点:账户编辑页)
                         │
                         ▼
     AnalysisScopeService.resolve(familyId, ?view)  ──►  AnalysisScope
                                                        {view, hasMarks, includedIds, excluded[], excludedShare}
                         │
         ┌───────────────┴───────────────┐
         ▼                               ▼
   full 分片(照旧)               scoped 分片(FactFilter.accountIds = includedIds)
   家底 · 收益 · 流动性 ·           资产配置 · 风险敞口 · 7 条配置类规则 ·
   资产负债表                       集中度 · 再平衡 / 配置锚 · 现金占比
         └───────────────┬───────────────┘
                         ▼
                ScopedFacts {full, scoped, scope}
                         │
     ┌───────────────────┼───────────────────────┐
     ▼                   ▼                       ▼
 FamilyDiagnose     AssetInsight            AllocationService
 (体检页 · 规则)     (洞察硬数据)              (配置锚对照)
     │                   │                       │
     └──── 三个 AI:同一套提示词 + AnalysisView 前言(ALL = 空串) ────┘
```

一句话:**「参与分析」是一个分片,不是一堆减法。** 没有标记时两个分片是同一个,所有路径退化成今天的样子。

### 2. 领域模型设计

| 概念 | 定义 | 与既有概念的关系 | 边界 |
|---|---|---|---|
| **不参与配置分析**(`account.analysis_excluded`) | 账户属性,「短期内不打算卖、也调不动」 | 和「归档」不同:归档的账户从此不再出现;被标记的账户照常出现在所有「有多少钱」里。和资产类型 / 平台 / 用途不同:那些按期**定格**,这个不定格 | 贷款类账户不可标(负债不进配置分母) |
| **分析视角**(`AnalysisView`) | `ADJUSTABLE` / `ALL` | 和仪表盘的账户筛选是同一个底层机制(`FactFilter.accountIds`),但筛选是「临时看一部分」,视角是「由标记决定的默认口径」 | 只作用于**占比类**:分母是资产合计的那些 |
| **分析范围**(`AnalysisScope`) | 一次请求里解析出来的:视角、是否有标记、参与账户、被拿掉的账户及其合计占比 | — | 可以是「空」(全都标了),而且必须能表达空 —— 不能用空列表代替(见 §零) |

定稿后同步 `AGENTS.md` 领域概念节。

不适用 · 不新增对外面。

### 3. 我们调用的上游接口

不适用 · 仍是既有的 `LlmRouter`,请求形状不变,只是提示词内容在 `ADJUSTABLE` 视角下多一段前言。

## 五、稳定性与质量保障

### 1. 兼容性设计

- **老数据 × 新代码**:所有账户 `analysis_excluded = 0` → `hasMarks = false` → 两个分片是同一个、提示词逐字相同、缓存键不变。**没有标记的家庭看不到任何变化**(零差异护栏守)。
- **新数据 × 老代码**(回滚窗口):老代码不读新列,标记被忽略,页面回到全部资产口径;缓存里带后缀的调仓行不会被老代码命中(键不同),无害。
- **与 #22 的交互**:「不适用」按 `规则 + 账户` 存,和视角无关 —— 在「可调整」视角下标了某条规则不适用,切回「全部资产」同一条规则仍然是隐藏的。这是对的:用户说的是「这条提醒对我不适用」,不是「在某个视角下不适用」。

### 2. 性能评估

有标记时体检多取一个分片(13 期 × 参与账户数,几十到几百行),几十毫秒级。无标记时不多取。不引入 N+1、不在循环里发外部请求。

### 3. 安全性设计

- **LLM**:见 PRD §8。新增内容只有被标记账户的名称(本就在上传范围)和它们的合计占比;成员真名脱敏走同一层,不变。
- **写入口**:`POST /accounts/{id}/edit` 沿用既有鉴权与 `findById(familyId, id)` 的家庭隔离;`AnalysisScopeService` 所有查询都带 `family_id`(承 `feedback_family_id_isolation`),**不沿用** `FamilyRules` / `LensConcentrationRules` / `AssetInsightService` 里的 `FAMILY_ID = 1L` 写法 —— 范围一律由调用方显式传入。

## 六、护栏设计

| 护栏 ID | 守的设计意图 | 判据怎么写 |
|---|---|---|
| `v125-NO-MARK-NO-CHANGE` | 没标记的家庭什么都不变 | 单测:固定 fixture 下三个 AI 的 `ALL` 提示词与 v1.24.5 生成的基线资源逐字相同;qa-run:未标记时体检页不含视角切换 |
| `v125-SCOPE-SPLIT-LIVE` | 占比类跟、绝对数不跟 | qa-run 真的去 beta 标一个资产账户 → 配置卡各项合计 = 参与账户合计、净资产 / 总负债 / 年化 / 紧急储备与标记前逐字相同 → 还原(声明终态,不依赖中间过程) |
| `v125-SCOPE-EMPTY-NOT-ALL` | 全都标了不许退回全量 | 单测:`AnalysisScope.isEmpty()` 时 `ScopedFacts.scoped()` 为空、不构建 `FactFilter` |
| `v125-SCOPE-ALL-RATIOS` | 新加的占比类组件不许漏接视角 | grep:`allocationByType(` / `AllocationService.compute(` / `lensQueryService.positions(` 在体检、报表、洞察里的调用点,入参必须来自 `ScopedFacts`;新增调用点而没登记会红 |
| `v125-REBALANCE-CACHE-KEYED` | 调仓缓存不串视角 | 单测:同锚、不同视角 / 不同标记集合 → 键不同;`ALL` 视角键 = 纯锚码(旧行照常命中) |
| `v125-ANCHOR-RENORMALIZE` | 整类拿掉才放大、合计 100 | 单测:整类 / 部分 / 目标本来为 0 三种情形 |
| `v125-MARK-ENTRY-REACHABLE` | 入口在用户看得到的地方 | e2e:从顶部导航进体检 → `FAM-CON-1` 卡片按钮 → 落在该账户编辑页的勾选项上(不是只测端点) |

**依赖 LLM 输出的那条验收(PRD §10 #10)不做成护栏**:护栏只守「`ADJUSTABLE` 提示词里有那三条约束」,
AI 实际说了什么靠人工抽读 —— 否则它会因为外部随机输出间歇性变红。

## 七、上线与回滚方案

### 1. 可观测

- 勾 / 取消标记写 `audit_log`(谁、哪个账户、从什么到什么)
- 三个 AI 的调用日志里带上视角(已有 `LlmAuditLogger`,加一个字段)

### 2. 预案评估

- 出问题:让用户取消勾选即回到原样;或回滚 jar(新列无害)
- 无不可逆动作

### 3. 上线方案

- 迁移只加列,不停机
- beta 验证清单(**走用户实际点击路径**):
  1. 账户页给「房产」勾上 → 账户列表出现小标记
  2. 顶部导航进体检 → 出现视角切换,默认「可调整的资产」,副文案写明拿掉了谁、占多少
  3. 配置卡 / 风险卡按参与账户;净资产 / 负债 / 年化 / 紧急储备与勾之前逐字一致
  4. 切「全部资产」→ 与 v1.24.5 一致;刷新保持;另一个会话打开是默认视角
  5. AI 综合诊断 / 资产洞察页脚写明视角;内容不再建议处置房产(人工抽读)
  6. 报表配置锚对照:选标普 4321 → 放大说明正确;选雪球三分法 → 不再出现「房产超配」
  7. 全部资产账户都勾上 → 空态,不出全量数字
  8. 手机端:两个视角选项同尺寸、无横向溢出
- 灰度替代物:没有标记 = 没有变化,本身就是「默认关」

## 八、成本测算

不新增 AI 调用入口。唯一的增量:一个家庭在两个视角之间来回切,诊断 / 洞察 / 调仓各多一份缓存 → 最多各多一次调用。可忽略。
