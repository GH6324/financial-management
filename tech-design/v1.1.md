# Tech Design · v1.1 · 资产透视(多维查询网关 + 交叉透视 + 旭日下钻)

> 对应 `prd/v1.1.md`(D1–D6 已拍板:全做 / 自定义同期 / 粗分行业 / AI 推荐打标 / 5 度量 / 5 预设看板)+ `preview/v1.1/asset-lens.html`。
> 一句话架构:**头寸(Position)事实模型 + 维度/度量注册表 + 一个纯函数 Pivot 引擎,暴露为唯一网关 `POST /lens/query`;前端旭日(ECharts sunburst,已 vendor)/ 交叉透视表 / 明细 / 看板全部是这个接口的客户端**。单家庭 <200 头寸,内存 group-by 毫秒级,不上外部 OLAP/BI。

## 2. 架构选型(备选 → 取舍 → 选定)

### 决策 1 · 事实模型:查询时实时组装头寸 vs 物化事实表 vs 复用 factview
- **A. 实时组装(选定)**:每次查询把「手填账户 snapshot + 持仓市值」组装成 `List<Position>`(内存),挂满维度值。<200 条、全部单机内存,毫秒级;永远与当前数据一致,零同步问题。
- B. 物化 `position_fact` 表:要维护刷新时机(填报/估值/打标都要触发),引入一致性问题,数据量根本不需要。**不选**。
- C. 复用 `AccountPeriodFact`(factview):账户粒度,拆不开持仓 → 行业维度做不了。**不选**,但账户级度量(latestPnl/cumPnl/netPrincipal)从 factview **取数复用**。

### 决策 2 · 维度/度量注册表:Java 注册表 vs DB 配置表 vs 网关内 switch
- **A. Java 注册表(选定)**:`DimensionRegistry` / `MeasureRegistry` —— 每个维度一条登记(key、中文 label、`Function<Position,String>` 取值、值排序);度量同理(聚合函数)。**加维度只登记一处**,网关/旭日/透视/构建器/看板自动支持(承 [[feedback_enum_add_sweep]] "一处网住整类");编译期类型安全。
- B. DB 配置表:运行时加维度无真实需求,徒增 admin 面和校验。**不选**。
- C. 网关里 switch:散点硬编码,恰是本版要消灭的形态。**不选**。

### 决策 3 · 网关协议:`POST /lens/query` 单接口 vs 每图专用端点 vs GraphQL
- **A. 单接口(选定)**:请求 `{rows:[dim], cols:[dim], measures:[m], filters:{dim:[values]}}`;响应 `{rowKeys, colKeys, cells:[{r,c,values[],positionIds[]}], rowTotals, colTotals, grandTotal}`。旭日 = rows=[d1,d2] cols=[];透视 = rows+cols;明细 = 用 cell 的 positionIds 再取明细。**核心是纯函数 `PivotEngine`(calc 包,零 Spring 依赖,可单测)**,controller 只做参数校验 + 组装。
- B. 专用端点:每加一个图加一个后端,违背用户明确要求"统一网关"。**不选**。
- C. GraphQL:引依赖 + 学习成本,单接口 JSON 已覆盖全部需求。**不选**。

### 决策 4 · 新维度落库:account 加列(选定) vs 旁表 vs 全放 product_category
- **选定**:`account` 加 3 个可空列 `platform_tag` / `asset_class` / `industry_tag`;`stock_holding` 加 1 个可空列 `industry_tag`。理由:与保险 11 个"冷展示字段"不同,这 3 个是**分析热字段**(每次透视都读、列表页要显示 pill),且各仅 1 列 —— 贴合 loanKind 先例;旁表反而多一次必然 join。
- 值域形态(与 loanKind/InsuranceSubType 同构,免迁移加值):
  - `AssetClass` Java 枚举(现金/固收/权益/另类/不动产/保险,6 值 + label)存 name();**默认派生函数** `AssetClass.defaultFor(type, categoryCode)`(CASH→现金、LOAN→不计、STOCK/CRYPTO→权益、METAL→另类、PROPERTY→不动产、INSURANCE→保险、WEALTH→按品类 固收/权益)。
  - `IndustryTag` Java 枚举(**12 个粗行业**:宽基综合 / 白酒消费 / 科技互联网 / 新能源电力 / 医药 / 金融地产 / 制造军工 / 固收债 / 贵金属商品 / 加密 / 海外市场 / 其他)存 name();账户级粗标 + 个股持仓级细标共用。
  - `platform_tag` **自由文本 VARCHAR(40)** + 前端 datalist 常用平台建议(招行/工行/支付宝/微信/富途/老虎/中国人寿…)——平台无法枚举穷尽,自由填 + 建议是准确性与自由度的平衡。
- 用户自存看板:新表 `lens_board(id, family_id, name, spec_json, display_order)`;**预设 5 块 = 代码内置 spec 常量**(升级随代码走,不落 DB)。

### 决策 5 · 收益度量的头寸归因(诚实降级,不做假分摊)
5 度量 = 金额 / 占比 / 本期收益额 / 累计收益额 / 累计收益率(=Σ累计收益 ÷ Σ净投入)。归因规则:
- **账户级维度**(风险/平台/大类/主理人/类型/币种):账户整体落一个切片 → 直接聚合 factview 的账户级 `latestPnl/cumPnl/netPrincipal`,**精确**。
- **持仓级维度**(行业/地域)会把持仓账户拆开:金额永远可算(持仓市值);累计收益额 = 市值 − costBasis×shares(AUTO/MANUAL 有 cost 即可);本期收益额 = (期末价−期初价)×shares(仅 AUTO 有价史);**算不出的归「未归因」列并 UI 标注**——绝不按市值比例把账户 PnL 假分摊到持仓(假精确,违 [[feedback_decision_weight_honesty]])。
- 占比/收益率是比值 → **币种无关不变式**必须进 `CurrencyInvarianceTest` 式 property 护栏(承 [[feedback_currency_invariance]]);金额按 fx 缩放。LOAN 不计入资产分母(同 AllocationDiff 惯例)。

### 决策 6 · 前端:原生 JS + fetch JSON + ECharts vs HTMX 局部刷 vs 引前端框架
- **A. 原生 JS(选定)**:`/lens` 页 Thymeleaf 只出壳(nav/看板 chips/容器),`static/js/lens.js` 持有客户端状态(`drillPath` 筛选栈 + 当前行列/度量),fetch `/lens/query`,渲染:旭日(ECharts sunburst,点块 push 筛选、点中心 pop)、透视表(DOM 生成 + 热力背景 + 冻结首列)、明细(cell.positionIds → `/lens/positions?ids=`)。交互太碎太联动,状态在客户端最顺。
- B. HTMX 局部刷:每次拖 chip/点块都整段往返渲染 HTML,状态散落 server/client 两侧,拖拽交互别扭。**不选**(本页例外,项目其它页仍 HTMX 惯例)。
- C. Vue/React:违背"无构建、CDN/vendor"底线。**不选**。
- 拖拽用原生 HTML5 drag(桌面)+ 点选切换(移动兜底);**移动端**:旭日限 2 环(第三层改重定心)、透视表 `overflow-x` + sticky 首列、看板 chips 横滑 —— 手机 pill/入口按 [[feedback_verify_user_path]] 教训双端都挂。

### 决策 7 · AI 推荐打标:复用 LLM 接入 + 白名单校验 + 显式接受
- 入口在打标管理页(`/lens/tags` 或账户页扩展):收集**未打标**账户名/持仓名 → prompt 要求输出严格 JSON `{name → {platform, industry, assetClass}}`,SYSTEM 注明只做分类、industry/assetClass 必须取白名单枚举值(**枚举外值直接丢弃**,OutputValidator 同风格校验)。
- 结果 = 待确认清单(逐条 接受/改/忽略 + 全部接受),接受才写库(承贷款预填"显式接受"模式);LLM 不可用 → 入口隐藏,手动打标不受影响。**不涉数学**(承 [[feedback_llm_no_math]],分类是允许域)。

## 3. 落库迁移 `V45__asset_lens.sql`(草案 · 向后兼容)
```sql
ALTER TABLE account
    ADD COLUMN asset_class  VARCHAR(20) NULL COMMENT 'AssetClass.name() · NULL=按类型派生默认(v1.1)',
    ADD COLUMN platform_tag VARCHAR(40) NULL COMMENT '平台/机构 · 自由文本(v1.1)',
    ADD COLUMN industry_tag VARCHAR(20) NULL COMMENT 'IndustryTag.name() · 账户级粗标(v1.1)';
ALTER TABLE stock_holding
    ADD COLUMN industry_tag VARCHAR(20) NULL COMMENT 'IndustryTag.name() · 个股行业(v1.1)';
CREATE TABLE lens_board (
    id BIGINT NOT NULL AUTO_INCREMENT,
    family_id BIGINT NOT NULL,
    name VARCHAR(40) NOT NULL,
    spec_json TEXT NOT NULL COMMENT 'LensQuery spec(rows/cols/measures/filters)',
    display_order INT NOT NULL DEFAULT 100,
    PRIMARY KEY (id), KEY idx_board_family (family_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户自存透视看板 · v1.1(预设看板为代码常量不落库)';
```
纯加可空列 + 新表,未打标 = 未分类,线上零影响(承 [[feedback_prod_backward_compat]])。

## 7. 旭日环级配色与信息可见性(v1.1.x 追加 · 2026-07-16 两轮评审)

**配色架构**(备选 → 取舍):
- **A. 前端内置方案表 + 后端只存方案 key(选定)**:lens.js `PALETTE_PLANS` 内置五套(A 飞书 VChart 官方 / B 外环原版内环压墨 / C 色相错位 / D 莫兰迪=默认 / E 国风),`FamilyConfigService.K_LENS_PALETTE` 只存一个字母,`LensMetaService.palette()` 白名单校验(脏值回落 D)注入 `LENS_META.palette`。管理页 `/admin/calc-tweaks` ②.5 区块 radio+色卡(色值与 lens.js 同源硬编码,改需两处同步——qa 守护 v11-SUN-RINGCOLOR 盯住)。
- B. 色板存 DB JSON(用户自定义任意色):灵活但要做色板编辑器 + 校验对比度,家庭场景过度设计,**不选**。
- C. CSS variables 注入:canvas(ECharts)读不到 CSS 变量,需 JS 桥接,绕一圈没收益,**不选**。

**环内分配**:`colorMapFor(values, ring)` —— 字典序去重排序后 哈希定起点 + 线性探测避让已用色;值 ≤ 色数(10)保证环内互不同色;字典序使分配与遍历序无关 → 旭日外环与排行条对同一值集必同色。

**信息可见性**(双环金额/占比 · 承 [[feedback_chart_datalabels]]):
- 扇区 label 常显「名称+占总比」(sunburst 按值分角,角度=share×360°);≥28° 且非隐私再加 `fmtShort` 短金额(¥98万/¥1.02亿)。
- **中心信息盘 `#sunCenter`**(内洞 18%→26%,DOM 绝对居中,pointer-events:none):默认显当前范围合计;`chart.on('mouseover')` 联动显示 hover 块的 名称/金额/占比 —— 内环扇区放不下金额,由中心盘补齐(双环信息密度难点的解法);金额 span 带 `data-priv`(CSS blur 照常)。
- **隐私模式与 canvas**:CSS blur 管不到 canvas 内文本 → `privacyOn()` 时 label/tooltip 不出金额;`html.privacy` class 切换经 MutationObserver 触发 `renderSunburst()` 重绘。
