# Tech Design · v0.13 · 新账户「开账基线」不计入当期收益

> 状态:**待评审(TDD 阶段)** · 对应 `prd/v0.13.md` · 预览 `preview/v0.13/opening-baseline.html`
> 本文是实施权威源。每个关键决策列备选 + 取舍 + 为什么不选。红线:不改净资产资产口径、只改收益归因;纯读侧派生、不改写库;币种不变性([[feedback_currency_invariance]]);prod backward-compat。

## 0. 现状触碰面(实施前必读)

| 组件 | 现状 | 本迭代关系 |
|---|---|---|
| `FactViewServiceImpl.netWorth(slice, P)` | Σ 各账户当期 `endBalanceBase`(本位币) | 不改(净资产照常含新账户) |
| `钱赚` = `CashflowSplitView.qian` | `qian = ΔNW − ren(人赚)` | 改:`qian = ΔNW − ren − 开账基线`;加第三项字段 |
| `本月资产收益` = `InvestmentReturnCalculator.monthly(期初,期末,净流入)` | `pnl = 期末 − 净流入 − 期初` | 改:再减开账基线 |
| `netInflowForPeriod` = `pmcFirstNetInflow` | income − expense(is_adjustment=0) | 不改(人赚口径不动);开账基线是**独立第三项** |
| 家庭 XIRR / TWR 外部流入 | 取 `periodIncome − periodExpense`(cash_flow) | 改:每期外部流入 += 开账基线(当外部资本注入)· FR-173 |
| `period_snapshot` | 每账户每期期末余额 | 只读(检测"账户首期");不写不改 schema |

**根因回顾**:新账户上一期无快照 → `期初`不含它、`净流入`不含它 → 其期末余额全落进 `钱赚 = ΔNW − 人赚` / `本月资产收益`。是 [[feedback_currency_invariance]] 之外、v0.12「外部流入不进 PnL」同类的归因漏洞。

---

## 决策 1 · 「开账基线」怎么定义与检测

- **背景**:需要认定"哪些账户在本期是**首次纳入**、其期末净值算存量基线"。
- **选定 · 派生检测(derived · 从 `period_snapshot` 历史算)**:账户在期 P **有快照、且 P 之前任何一期都无快照** ⇒ 本期首次出现;其 P 期末净值(本位币,按 account_class 带符号)= 开账基线;全期合计 = `openingBaseline(P)`。
  - 新增只读查询 `SnapshotMapper.firstAppearingAccountIds(familyId, periodId)`(见数据模型),fact 层据此从 slice 汇总 `endBalanceBase`。
  - **理由**:①零 schema ②**能追溯修复已存在的账户**(如已建的币安钱包,无需用户重录)③**零用户操作**(新建账户即自动)④账户"归档后恢复"按"曾出现过即非新"天然处理(查的是任意历史快照)。
- **备选(否)· 建账时显式记一条"开账基线"事件(新表/新流水)**:更可审计,但要 ①改 schema ②在所有"首次写余额"入口(submitBalance / 估值写回 / 加持仓)都埋记录点 ③**修不了已存在账户**、要用户重录。收益不抵成本。
- **备选(否)· 新建账户时弹窗问"是否存量"**:增加 10 分钟预算的摩擦、非技术家人易困惑;派生+卡片透明展示已足够。首期一律基线(FR-170),后续如确有"首期就想计收益"的需求再加开关。

## 决策 2 · 剔除口径统一(单一真源)

- **选定**:fact 层新增 `openingBaseline(slice, periodId)`(本位币),**所有收益类指标从同一处减它**:
  - 钱赚:`qian = ΔNW − ren − openingBaseline`
  - 本月资产收益:`monthly(期初, 期末 − openingBaseline, 净流入)` 等价 `(期末 − 净流入 − openingBaseline − 期初)/期初`(把开账基线视作已在期初的资本)
  - XIRR/TWR:把 `openingBaseline(P)` 作为该期**外部资本流入**注入(决策 4)
- **理由**:单一派生量 + 单点扣减,避免多处口径漂移(踩过:v0.8 币种、v0.12 收入双计)。
- **备选(否)** 把开账基线塞进 `netInflow`:会同时抬高"人赚"(它也读 netInflow)→ 变成"收入虚高";开账基线**既非人赚也非钱赚**,必须独立第三项。

## 决策 3 · 「本期怎么变的」卡加第三项(FR-171)

- `CashflowSplitView` 加字段 `openingBaseline`;`of(...)` 传入;`qian = ΔNW − ren − openingBaseline`。
- 恒等式 `ren + qian + openingBaseline == ΔNW` 卡内自洽(与现状"ren+qian==ΔNW"兼容:无新账户时 openingBaseline=0)。
- 模板 `dashboard/_region.html`:在 `openingBaseline != 0` 时插一行「新纳入本金(开账)」+ 双向条(复用现有 `signedBar`/`width` 画法,`maxAbs` 纳入 openingBaseline)。一句话说明。
- 空态/首期:openingBaseline=0 → 不显该行,卡片与现状一致。

## 决策 4 · 家庭全收益指标统一剔除 + 账户级净投入计入(全范围)

用户拍板:**全部收益指标都要修**。构造投资现金流/损益时,把 `openingBaseline(P)` 作为**该期外部资本流入**(与 income/transfer-in 同侧)统一剔除:
- 家庭 XIRR(`familyXirr`)/ 资产 TWR(`familyTwr`)/ 年化(`annualizedInvestReturnPct`=TWR):每期外部流入 `external(P) += openingBaseline(P)` → 补录存量账户不抬高年化。
- 家庭累计投资 PnL(reports「钱赚的·投资PnL」= `cumulativePnl` 分解)/ `ytdInvestPnl`:窗口内累计减去 `Σ openingBaseline`。
- **账户级「累计净投入 net_principal」**:新账户**首期开账余额本就是"带入的本金"**,当前 `netPrincipal = Σ(income−expense+transferIn−transferOut)` 不含它 → 偏低、与 cumPnl 语义不自洽。改:首次出现账户的 net_principal **+= 该账户首期 endBalanceBase**(见决策 5 矩阵)。

## 决策 5 · 全指标审计矩阵(逐个判定 · 权威清单)

原则:**"赚了多少"(收益/回报/损益)→ 剔除开账基线;"现在有多少"(存量/占比/比率)→ 照常含;账户级损益列用 `previousEndBalance`/≥2 期门槛 → 新账户首期天然 null,已正确、只需加测试验证。**

| 指标 | 位置 | 现状对开账 | 判定 | 动作 |
|---|---|---|---|---|
| 钱赚(本期怎么变) | `CashflowSplitView.qian`=ΔNW−人赚 | 漏(全落钱赚) | **必改** | 减 openingBaseline + 卡片第三项(决策 2/3) |
| 本月资产收益 % | `InvestmentReturnCalculator.monthly` | 漏 | **必改** | 期末 − openingBaseline(决策 2) |
| 钱赚的·投资PnL(累计) | reports `cumulativePnl` 分解 | 漏(窗口内) | **必改** | 累计减 Σ openingBaseline |
| YTD 投资 PnL | `ytdInvestPnl` | 漏 | **必改** | 同上(自然年内) |
| 家庭 XIRR · 含收入 | `familyXirr` | 漏(NW 跳增无对应流) | **必改** | external(P) += openingBaseline |
| 资产 TWR / 年化 | `familyTwr`/`annualizedInvestReturnPct` | 漏 | **必改** | 同上 |
| vs 基准(pp) | `familyXirr − benchmark` | 随 XIRR | **自动修** | 无需单独改(基准本身不变) |
| **账户级 累计净投入 net_principal** | `buildAccountPerformance` | 偏低(不含带入本金) | **必改** | 首次出现账户 += 首期 endBalanceBase |
| 账户级 收益率 xirr / 本位币年化 | `xirr(Base)ForAccountRows` | `<2 期→null` | ✅ 已正确 | 仅加测试 |
| 账户级 累计损益 cumPnl | `Σ periodPnlBase`(首期 null 跳过) | 首期已跳过 | ✅ 已正确 | 仅加测试 |
| 账户级 本期损益 / 本期Δ / 最大回撤 / 预实 | 均依赖 previousEndBalance / ≥2 期 | 首期 null | ✅ 已正确 | 仅加测试 |
| 净资产 / 总资产 / 总负债 / 紧急储备 / 负债率 | KpiSnapshot 存量 | 含新账户 | ✅ 不改(正确) | — |
| 占比 share_pct / 配置环 / 持有期数 | 点位/计数 | 含 | ✅ 不改(正确) | — |
| **净资产环比 Δ / Δ%(dashboard 顶部)** | `delta`/`deltaPct` | 含开账(coverage 跳增) | **判断** | **建议不改**:ΔNW 数值保持真实,透明化交给「本期怎么变」卡的第三项;它是"净资产变化"非"收益" |

## 数据模型变更

**无 schema 变更。** 新增只读查询(`SnapshotMapper`):
```sql
-- firstAppearingAccountIds(familyId, periodId):有本期快照、且此前任何一期都无快照的账户
SELECT DISTINCT ps.account_id
  FROM period_snapshot ps
  JOIN period p ON p.id = ps.period_id
 WHERE p.family_id = #{familyId} AND ps.period_id = #{periodId}
   AND ps.account_id NOT IN (
     SELECT ps2.account_id
       FROM period_snapshot ps2
       JOIN period p2 ON p2.id = ps2.period_id
      WHERE p2.family_id = #{familyId}
        AND p2.period_start < (SELECT period_start FROM period WHERE id = #{periodId}))
```
- 纯查询,对 prod 老数据零影响;老账户(早有快照)永远不入结果集。

## 关键流程(伪代码)
```
openingBaseline(slice, P):                      # 本位币
  ids = snapshotMapper.firstAppearingAccountIds(familyId, P)
  Σ = 0
  for row in slice.rows where row.periodId==P and row.accountId in ids:
      Σ += row.endBalanceBase        # ASSET 正 / LIABILITY 负,与 netWorth 同符号口径
  return Σ

# KpiSnapshot 装配(FactViewServiceImpl)
ob        = openingBaseline(slice, last)
qian(钱赚) = ΔNW − ren − ob
monthly   = InvestmentReturnCalculator.monthly(期初, 期末 − ob, 净流入)   # 开账基线并入期初资本
# 家庭 XIRR / TWR:每期外部流入注入 ob(与 income 同侧)
familyXirr/familyTwr: external(P) = periodIncome(P) − periodExpense(P) + openingBaseline(P)
# 家庭累计投资 PnL(reports) / YTD:窗口累计减 Σ ob
cumulativePnl(window) −= Σ_{P in window} openingBaseline(P)

# 卡片
CashflowSplitView.of(ΔNW, breakdown, filled, total, ob):
   ren=breakdown.netInflow; qian=ΔNW − ren − ob;  三行:ren / qian / ob;  和 == ΔNW

# 账户级 net_principal(buildAccountPerformance)· 传入 firstAppearing 集合
firstIds = snapshotMapper.firstAppearingAccountIds(familyId, <各期>)   # 或按账户首期判定
netPrincipal = Σ(income−expense+transferIn−transferOut)
             + (该账户首期在窗口内 ? 该账户首期 endBalanceBase : 0)     # 带入本金

# 财富水位(WaterLevelCalculator 输入)· 期末用剔除累计开账的真实净值
nominalGrowth = (期末 − Σ_{window} openingBaseline) / 期初 − 1
```

## 护栏 / 测试
- `OpeningBaselineTest`:①新账户首期 → ob=其期末净值、钱赚剔除、`ren+qian+ob==ΔNW` ②无新账户期 → ob=0、全指标与现状一致(不回归)③负债新账户 → ob 为负 ④曾归档后恢复 → 不算新。
- `FamilyReturnOpeningTest`:家庭 XIRR / TWR / 本月资产收益 / 投资PnL / YTD —— 补录一个大额存量账户后,**这些收益指标不跳升**(与"该账户从第二期起才产生收益"等价)。
- `AccountMetricsOpeningTest`:①`net_principal` 含首期开账(带入本金)②账户级 `cumPnl / xirr / 本期损益 / momΔ / 回撤` 新账户首期为 null/跳过(**验证"已正确"这批不被误改**)。
- `WaterLevelOpeningTest`:补录存量账户不虚增名义增长/realReturn。
- 纳入 `CurrencyInvarianceTest`(ob 本位币,三视图比值不变);`CashflowSplitEmptyTest` 不回归。
- e2e 主线:新建账户 + 录余额/持仓 → 净资产照常 +N、**钱赚/本月资产收益/家庭XIRR 不含 N**、卡三行自洽、账户表 net_principal 含 N、其它列不变。
- qa-run 静态守护:`CashflowSplitView` 含 `openingBaseline` 且 `qian` 减去它;`familyXirr/familyTwr` 外部流入含 openingBaseline;`buildAccountPerformance` net_principal 含首期。

## 风险与红线
- **只影响"新纳入当期"**:老账户/历史关账期不追溯(FR-175);实现为读侧派生,天然不动历史。
- **XIRR/TWR 改动面**(决策 4):逐期注入外部流入,口径要与钱赚一致;建议评审拍板是否本版做。
- **检测边界**:账户"同期内余额又变动"整块算基线(首期不拆真 PnL,简化);"归档→恢复"按曾出现即非新。都在测试里钉住。
- **backward-compat**:无 schema、无写库、无迁移 → prod 零风险;发布走 [[feedback_tag_must_verify]]。
- **10 分钟**:零新增录入步骤(自动识别),不增负担。

## 非目标(承 PRD)
不改净资产/总资产资产口径;不做逐笔"算不算收益"人工开关;不改 v0.12 收入侧/持仓估值;不处理罕见断档账户的精细拆分。
