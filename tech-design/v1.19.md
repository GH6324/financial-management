## 0 · 一句话概括

**我们只做一件事:一份只读的 OpenAPI。** 其余全部从它派生。

```
                    ┌── stdio MCP ──────▶ 程序员自己的 agent(Claude Code / Cursor / OpenClaw)
只读 OpenAPI ───────┤                     零公网暴露
(唯一要我们写的)   │
                    └── HTTP MCP ───────▶ 百炼(Managed Agents / Responses API)
                                          ├─ 产品内的「问一问」(给非技术用户)
                                          └─ 用户自己在百炼里搭的任何 agent
```

**agent loop 我们不写** —— 编排在百炼那边。我们负责的是「开放什么」和「怎么保证数字是对的」。

自由度的来源仍然是 §3:把已有的 `LensQuery` + `PivotEngine` 语义层开放出去 ——
11 维 × 6 度量 × 任意筛选 × 行列交叉,而口径零新增。

## 1 · 一次提问的完整链路

```
用户            我们(Spring Boot)              百炼 runtime            我们的 MCP
 ├─ 提问 ─────▶ │                                  │                       │
 │              ├─ 建 session / 发事件 ──────────▶ │                       │
 │  ◀─ SSE ─────┤ ◀────────── 事件流 ─────────────┤                       │
 │              │                                  ├─ mcp_call: pivot ───▶ │
 │              │                                  │                       ├─ PivotEngine
 │              │                                  │ ◀── 结果 + 引用元数据 ─┤   (透视页同一份)
 │  ◀─ SSE ─────┤ ◀── 正文(数字位置是引用标记)──┤                       │
 │              ├─ 渲染:标记 → 数值 + 账期 + 跳转 │                       │
 │              ├─ 落库(会话/消息/引用/调用摘要)  │                       │
```

**注意倒数第三段**:模型正文里**不写数字**,写引用标记 —— 见 §4,这仍然是本版最关键的一条。

## 2 · 架构选型

### 2.0 · 先说我上一版错在哪(三处实错)

| 我写过 | 实际 | 后果 |
|---|---|---|
| 「Responses API **vs** Managed Agents」二选一 | **不是二选一**。Responses API 的 `tools` 里**可以直接挂 MCP server**(`server_protocol` / `server_label` / `server_url`);Managed Agents 也挂 MCP。**MCP 是两者共同的底座** | 我把决策问错了 —— 真正要决的是「我们开放什么」,不是「用哪个 runtime」 |
| 「选 Responses API 就得**自己写 agent loop**」 | 只在**函数工具**那个变体下成立。挂 remote MCP 的话**编排在百炼那边,我们一行 loop 都不写** | 我用一个不必要的代价把方案劝偏了。维护者那句「我们哪有能力做这个」是对的 |
| 把「要开公网口」当成**纯代价** | 对一个**开源自建**项目,一份文档化的只读 API **本身就是产品能力** —— 程序员用户能拿它接自己的 agent。这是**收益**,不是负债 | 我用它否决了正确的方案 |

**修正后的判断:走 MCP。** 而且 MCP 不只是「喂百炼的管道」,它是**这一版真正的交付物**。

### 2.1 · 核心资产:一份只读 OpenAPI

我们唯一必须自己写的东西。内容就是 §3 那套查询能力,以 HTTP 接口表达:

```
GET  /api/v1/ask/capabilities          自省:维度 / 度量 / 账期 / 账户
POST /api/v1/ask/pivot                 主力查询(rows/cols/measures/filters/period/currency)
GET  /api/v1/ask/period/{p}/summary    一期全貌
GET  /api/v1/ask/period/{p}/accounts   账户级收益表
GET  /api/v1/ask/period/{p}/attribution
GET  /api/v1/ask/checkup
GET  /api/v1/ask/goals
GET  /api/v1/ask/metric/{key}/explain  这个指标怎么算的(与页面 tooltip 同一份文案)
GET  /api/v1/ask/entity?q=             名字 → id
GET  /api/v1/ask/account/{id}/ledger
POST /api/v1/ask/unmet                 「我够不着」的反馈回收
```

**全部只读。没有任何写接口** —— 这是**物理保证**,不是 prompt 约束。

规格用 springdoc 从代码生成(`openapi.json`),**不手写、不会漂**。

### 2.2 · 从 OpenAPI 派生三种消费方式

| 形态 | 谁用 | 要公网吗 | 怎么接 |
|---|---|---|---|
| **stdio MCP** | 程序员用自己的 agent | **不要** | 我们发一个小的 MCP 进程(读 OpenAPI → 暴露 tools),用户在 Claude Code / Cursor 的配置里加一行 |
| **HTTP MCP**(Streamable HTTP) | 百炼 | 要 | 百炼控制台「自定义 MCP → 安装方式 http」,填 `{"type":"streamableHttp","url":"https://你的域名/mcp"}` |
| **本地函数工具** | 产品内对话的**无公网降级** | 不要 | Responses API + function tools,工具在我们进程里执行 |

**三者共用同一份工具实现** —— 只有传输不同。这正是 §5 那层 `AgentRuntime` 抽象要承载的。

### 2.3 · 产品内的「问一问」用哪个 runtime

| 环境 | runtime | 理由 |
|---|---|---|
| **有公网(默认)** | **Managed Agents** + 我们的 HTTP MCP | 维护者要的就是它「智能度和灵活程度极高的 agent runtime」:session 服务端持久化、中断续接、多步工具编排、skill 生态。**我们不写 loop** |
| 有公网 · 想轻 | Responses API + `tools:[{type:"mcp"}]` | 更薄;而且 Responses 的 mcp tool 支持**传鉴权头**(见 §2.4 的坑) |
| **无公网** | Responses API + **本地函数工具** | 自建用户在 NAT 后面照样能用产品内对话,只是接不了外部 agent |

> 我上一版否决 Managed Agents 的理由是「工具执行在平台侧,数据只能靠公网 MCP 或沙箱文件进去」。
> **在 MCP 就是我们想要的交付物之后,这条理由不成立了** —— 它执行的正是我们的 MCP。

### 2.4 · 一个必须先解决的坑:百炼控制台的自定义 MCP **没有 Header 鉴权字段**

官方文档里远程 MCP 的模板只有 `type` 和 `url` 两项,**没有 Authorization header 的位置**。
(stdio 形态有 `env` 可注环境变量,但那不是 HTTP 头。)

可行的三条,我倾向第一条:

| 做法 | 取舍 |
|---|---|
| **① token 放在 URL 路径里**<br>`https://域名/mcp/{token}` | 现在就能用,不依赖别的产品。**代价**:token 会进访问日志 / Referer / 浏览器历史。**所以必须**:长随机(≥32 字节)、**可一键轮换**、**我们自己的日志里脱敏**、只读、限流、每次调用审计 |
| ② 走**阿里云 AI 网关**,由网关承担鉴权与注头 | 更正规。**代价**:多依赖一个云产品,自建用户的部署成本上升 —— 与「开源好部署」冲突 |
| ③ Responses API 的 mcp tool 传 headers | 如果确认支持,这条最干净。**但它只解决产品内对话,解决不了「用户自己在百炼控制台搭 agent」** |

**结论**:① 作为基线(所有场景可用),③ 作为产品内对话的增强。② 不做。

> 这条要写进 PRD 的风险段:**我们会在用户域名上开一个「拿到 URL 就能读全部家底」的只读端点。**
> 所以它**默认关闭**,开启时页面要把这句话原样说给用户听,并给一键吊销。

## 3 · 开放什么 —— 自由度的来源

### 3.1 三种做法,先说为什么不选另外两种

| 做法 | 自由度 | 口径风险 | 结论 |
|---|---|---|---|
| **A · 罐头接口**<br>`getAllocation()` `getTopLosers()` … 一问一函数 | **低**。我们想到什么它才能问什么;用户一问「按平台看、只看老婆名下的、近三个月」就抓瞎 | 零 | ✗ 这是把「固定卡片」换了个壳,没解决 v1.19 要解决的问题 |
| **B · 裸 SQL / 原始表** | **最高** | **最高**。agent 自己 group-by、自己算占比 → **凭空造出第三份口径**,说的数和页面对不上,而用户没法判断谁对(v1.18 整个 bug 家族就是「同一件事两份判据」,已归档 6 次) | ✗ |
| **C · 把语义层开放出去**(选定)<br>`LensQuery` + `PivotEngine` | **接近 B**:11 维 × 6 度量 × 任意筛选 × 行列交叉 | **零**。算的是透视页**同一份代码** | ✓ |

**C 的关键性质:聚合权在我们手里。** agent 说「按平台分组」,是 `PivotEngine` 去分组;
它拿到的已经是分好组、算好占比、带小计的结果 —— **没有算术可做**。
「禁数学」于是不再是限制,而是**不必要**。

### 3.2 主力接口:`POST /api/v1/ask/pivot`

```jsonc
{
  "rows":     ["platform"],            // 行维度,可多个(嵌套)
  "cols":     ["risk"],                // 列维度,可空
  "measures": ["value", "share"],      // 度量白名单
  "filters":  { "owner": ["成员A"] },   // 维度 → 取值
  "period":   "2026-08",               // 缺省 = 当前上下文账期
  "currency": "CNY"
}
```

**维度白名单(11)** —— 前 10 个是 `LensRegistry` 现有的,第 11 个是本版新增派生视图(§8):
`type` · `risk` · `liquidity` · `currency` · `owner` · `assetClass`(穿透后) · `platform` ·
`industry`(穿透后) · `region` · `purpose` · **`custody` 托管形式**

**度量白名单(6)**:`value` · `share` · `latestPnl` · `cumPnl` · `netPrincipal` · `openValue`

> `PivotEngine.Result` 已带 `rowTotals` / `colTotals` / `grand` / `holdingLevelSplit`,**直接透传**。
> `holdingLevelSplit` 尤其重要:它标记「本次查询含持仓级维度,收益按持有口径、**不可归因**」——
> 必须**原样交给 agent**,否则它会拿一个不可归因的数去下结论。

### 3.3 三个专为「自由度」设计的东西

**① `/capabilities` 自省接口 —— 不让它猜。**
agent 最大的浪费是猜参数:猜维度叫什么、猜账期格式、猜账户名。
所以第一等公民是自省:维度、每维的取值、可用账期、账户列表,**一次问清**。
MCP 的 tool description 里明写:**拿不准就先调它,不要猜。**

**② 参数填错不报错,把校验信息回给它让它改。**
返回 `422` + 结构化的「你可以用的取值是这些」。允许试错,这本身就是自由度。

**③ `/unmet` —— 够不着时诚实说 + 记下来。**
agent 发现「用户问的我没有对应能力」时调它,然后**如实告诉用户拿不到**。
我们把它记进 `ask_unmet_need` —— **agent 的「够不着」变成下一版加接口的产品输入**,
比我们坐着猜用户要什么准得多。

> 这也是对「自由度」的诚实回答:**边界总会有**,重要的是它**可见、可反馈、会移动**,
> 而不是让 agent 在边界上编一个答案。

### 3.4 接口层不许做什么

```
web/ask/api/     只做三件:参数校验 → 调现有 service → 包上口径元数据
                 一行计算都不写
```

每个响应**必须**带 `periodId` · `metricKey` · `inProgress` · `currency` ——
这四样是 §4 引用块的原料,也是「数字说得清自己是哪一期」的载体。

## 4 · 数字保真:**模型不写数字,只写引用标记**

### 4.1 问题

FR-427 要求每个数字挂账期、点得回原页、与页面**逐字一致**。
如果让模型把 `+¥204,522` 打进正文,有三种翻车方式:少一位、改成「约 20 万」、把 7 月说成 8 月。
**靠 prompt 约束这件事我们已经证明过不可靠** —— 那条「禁止四则运算」的铁律是拿生产事故换来的。

### 4.2 做法

工具结果落进**本轮引用表**,每个可引用数字有一个 id;模型正文写标记:

```
你 8 月净资产涨了 {{cite:c1}},其中投资那份 {{cite:c3}} 占了大头。
```

渲染时替换成引用块组件,数值**直接取自工具结果**:

```
净资产变化 ΔNW      +¥222,522
2026-08 · 进行中   → 仪表盘 · 本期怎么变的
```

### 4.3 为什么这是结构性的,而不是约定性的

- 模型**没有机会**打错数字 —— 它手里根本没有数字字符串,只有 id
- 账期 / 口径名 / 跳转目标由**工具结果**决定,不由模型决定
- 渲染时口径文案与页面**共用一份**(`MetricExplainService`);页面改口径,历史对话跟着改

**兜底**:模型仍可能在正文里手打数字(比如复述)。所以加一道**输出校验** ——
扫正文里的金额 / 百分比形态,**凡不在本轮引用表里的,标灰并加一句「这个数我没核对过」**。
不删(删了句子会断),但**明确降级**。

> 复用现有 `OutputValidator` 的思路:v0.4 起我们就在扫 LLM 输出(那时扫「有没有泄露真名 / 荐产品」),
> 现在多扫一类「有没有凭空出现的数字」。

## 5 · 分层:哪一层允许知道「我们在用百炼」

```
web/ask/api/AskApiController      只读 OpenAPI(springdoc 生成规格)  ← 对外的唯一真相
web/ask/mcp/McpEndpoint           把 OpenAPI 包成 MCP(HTTP + stdio 共用一份工具定义)
   ↕ 共用
service/ask/AskToolRegistry       工具注册表 · 参数校验 · 口径元数据
   ↑
service/ask/AskConversation       产品内对话编排 · 引用表 · 本地存储   ← 不知道百炼存在
   ↓
service/ask/AgentRuntime          接口:send(消息, 事件回调)
   ├ ManagedAgentRuntime          默认 · 百炼 Managed Agents + 我们的 HTTP MCP
   ├ ResponsesMcpRuntime          轻量 · Responses API + tools:[{type:"mcp"}]
   └ ResponsesLocalToolsRuntime   无公网降级 · Responses API + 本地函数工具
```

**两条线**:

- **对外线**(OpenAPI → MCP):给百炼、给程序员自己的 agent。**这是本版的主交付物**
- **对内线**(AskConversation → AgentRuntime):产品内的「问一问」,给非技术用户

两条线**共用 `AskToolRegistry`** —— 工具只实现一次。

**为什么 `AgentRuntime` 要抽象成三个实现**:不是为了炫技,是因为
① Assistant API 三个月前还是官方推荐、现在「下线中」——**这一领域的接口寿命短于我们的版本节奏**;
② 自建用户的环境有没有公网**由不得我们**,降级路径必须真实存在,不能只写在文档里。

## 6 · 多轮上下文:主用云端,自己留一份

| 方案 | 取舍 |
|---|---|
| **A · 全靠 `previous_response_id`** | 最省。但有已知时序坑;云端过期 / 换账号后**无法续接** |
| **B · 每轮自拼完整 `input`** | 最可控,但 token 随轮次线性涨,且放弃服务端上下文缓存 |
| **C · 主用 A + 本地全量 + 失败退 B**(选定) | 正常走 `previous_response_id`;一旦报 `No tool output found` 或 id 失效,**用本地历史重拼 input 重试一次** |

**选 C**,理由不是折中:PRD FR-431 本来就要求**本地存全量**,所以「重拼所需的历史」是**免费**的。
既然有,就不该在云端失效时干瞪眼。另开 `x-dashscope-session-cache: enable` 降低多轮延迟与成本。

**新对话**(FR-431b)= 新的 `previous_response_id` 链;旧链自然失效,不用清理。

## 7 · 系统提示词的结构

放仓库 `resources/prompts/ask-system.md`,**随版本走**,不进控制台。五段:

1. **角色与边界** —— 家庭资产顾问;不预测涨跌、不荐具体产品、不做担保性话术(**与现有六处 AI 共用这一段**,避免边界在两处漂移)
2. **数字纪律** —— 你**不写数字**,只写 `{{cite:id}}`(§4)
3. **怎么用工具** —— 拿不准先 `describeCapabilities`;一轮最多 8 次;够不着就 `reportUnmetNeed` 并如实说
4. **什么时候先反问**(FR-425)—— 凡结论会因一个未知条件**翻转**的问题,先问再答。给正反例:
   「该不该提前还贷」要问现金用途;「我房产占比多少」不需要问
5. **答完给 2–3 条追问**(FR-424b)—— 贴着刚才那段答案,不是一屏

## 8 ·「托管形式」:派生维度

| 方案 | 取舍 |
|---|---|
| **A · 新增维度(需打标)** | 与现有维度一致。但要用户**逐个账户打标** —— 违背 10 分钟硬约束 |
| **B · 派生**(选定) | 由已有字段推导,**零新增录入**。代价:规则由我们定 |

| 托管形式 | 规则(全部来自已有字段) |
|---|---|
| **自己盯** | `STOCK` / `CRYPTO` / `METAL`,你自己建的标的 |
| **交给产品** | `WEALTH` / 基金类;有穿透结果的走**穿透后成分** |
| **不动** | `PROPERTY` / `INSURANCE` |
| **随时可取** | `CASH` + 标了 `LIQUID` 的货基类 |

**落点**:在 `LensQueryService.positions()` 组装 `Position` 时**多填一个 `custody` 标签**,
其余完全复用 —— 于是它自动获得透视引擎的全部能力(能当行、能当列、能筛选、能交叉),
**而且透视页也白捡一个新维度**。

> 配**结构性单测**遍历 `AccountType`,要求每个类型落进四类之一或显式列入 `NEITHER` ——
> 照抄 `AccountTypeSemanticsTest`,那条正是为「v0.14 加 METAL 漏了投资类判据」立的。

## 9 · 外壳与 SSE

### 9.1 两种壳,一个流

| | PC(≥1024) | 移动 |
|---|---|---|
| 入口 | 右下角**常驻悬浮按钮** | 导航**顶级入口** |
| 壳 | **可拉宽侧边抽屉** | **全屏页** +「← 回到刚才那页」 |
| 实现 | 同一个 `ask/_stream` 片段,两个外层模板 | 同上 |

**PC 必须是侧栏**:本版最重的承诺是「数字点得回原页」,侧栏能左边看数右边问话;
独立页每点一次引用块都要跳走再跳回。

### 9.2 跨页面保持

| 方案 | 取舍 |
|---|---|
| **A · 整页刷新重建** | 简单,但**对话会断** —— 直接违背要求 |
| **B · 导航改 HTMX 局部替换**(选定) | 与项目现有做法一致(趋势 / 支出构成早就是局部替换)。抽屉挂 layout 上,主体换它不换 |
| **C · 引入 SPA 路由** | 能做到,但给 Thymeleaf 项目引前端路由,收益与成本不成比例 |

> **风险**:B 触到**每一个页面**。所以单列为第二刀,第一刀先做「当前页可用」。

### 9.3 SSE

Spring MVC 原生 `SseEmitter` + **独立线程池**(不引 WebFlux —— 只有一个流式端点,
引一套新范式不划算)。池子有上限,满了直接拒绝并给人话提示,**不排队、不拖垮主池**。
移动端全屏页跳走时**必须主动关 emitter**,否则线程挂到超时。

### 9.4 滚动(FR-431d)

流式时滚动停在**新消息顶部**,不追最后一个字。实现用
「stick to bottom only if already at bottom」:用户已在底部才跟随。

理由:追着滚会让人**读不了正在生成的内容**;而我们的答案里有引用块,滚到底会让最重要的数字一闪而过。

## 10 · 存储

```
ask_conversation    id · family_id · title · provider_ref · ctx_period · ctx_currency · created_at · archived_at
ask_message         id · conversation_id · role · content_text(含 {{cite:id}})· seq · created_at
ask_citation        id · message_id · cite_key · metric_key · period_id · in_progress · value_text · currency · target_href
ask_tool_call       id · message_id · tool_name · args_json · duration_ms · ok      ← 只存摘要,不存返回体
ask_unmet_need      id · family_id · question · needed · created_at                 ← §3.4 ③
ask_suggestion_skip id · family_id · suggestion_key · shown_count                   ← FR-424b「不重复推」
```

**为什么引用块单独存,而不是把渲染好的 Markdown 塞进 `content_text`**:
存 Markdown 等于把口径**冻结成一段文字**。页面口径改了(这一年改过三次),
历史对话里的说法就和现在的页面对不上,**而且没人会发现**。
结构化存之后,口径文案在**渲染时**生成,与页面共用一份。

**`ask_tool_call` 只存摘要**:返回体就是家底数据,存两份没有意义,只增加泄漏面。

> 隐私:对话正文含真实金额 —— 那本来就在用户自己库里,不是新增暴露面。
> 但**不进 `audit_log`**(会被导出)、**不进任何日志**。这条进护栏。

## 15 · 开源用户怎么接上(维护者点名要「简简单单一个 mcp 就搞定」)

### 15.1 目标

一个陌生程序员 `docker compose up` 之后,**三步内**让自己的 agent 读到自己的资产:

```
① 管理页 →「AI 接入」→ 点「启用只读接口」   (默认关闭)
② 页面直接给出两段配置,复制走
③ 粘进百炼控制台 / 或粘进 Claude Code 的 mcp 配置
```

**没有第四步。** 不用建 Agent 资源、不用填 workspace_id、不用装 SDK。

### 15.2 页面直接给出的两段配置

**给百炼(云端 agent)** —— 控制台「自定义 MCP → 安装方式 http」:

```json
{ "type": "streamableHttp",
  "url": "https://你的域名/mcp/{一键生成的 token}" }
```

**给本地 agent(Claude Code / Cursor / OpenClaw)** —— 零公网暴露:

```json
{ "mcpServers": {
    "my-finance": { "command": "docker", "args": ["exec","-i","finance","ask-mcp"] } } }
```

> 第二段是这个项目**开源属性的关键**:程序员用户根本不必把服务暴露到公网,
> 直接用容器里的 stdio MCP 接自己的 agent。而这条路**同时也是我们自己的降级路径**(§2.3)。

### 15.3 管理页要说的话(不能只给按钮)

启用时把风险**原样说出来**,不做美化:

> 打开之后,**任何拿到这个链接的人都能读到你的全部资产数据**(只读,改不了)。
> 链接里带着一串随机口令 —— 别发到群里、别贴进公开仓库。
> 怀疑泄露就点「重新生成」,旧链接立刻失效。

配套:**一键轮换** · **最近调用记录**(谁、什么时候、调了哪个接口)· **随时关闭**。

### 15.4 为什么 token 放在 URL 里(而不是 Header)

不是我们想这么干 —— 是**百炼控制台的自定义 MCP 没有 Header 鉴权字段**(§2.4)。
所以必须补齐这些:

| 要求 | 做法 |
|---|---|
| 长度 | ≥ 32 字节随机,不可猜 |
| 可吊销 | 管理页一键轮换,旧的立刻失效 |
| 不进日志 | nginx 与我们自己的 access log **都要脱敏**(路径里的 token 段替换成 `***`)· 进护栏 |
| 限流 | 按 token 限流,超了返回 429 而不是继续吐数据 |
| 审计 | 每次调用记一条(接口名 / 时间 / 来源 UA),但**不记返回体** |
| 只读 | 这条不是「配置」,是**这批接口物理上没有写方法** |
| 默认关 | 不启用就 404,不是「启用了但没人知道」 |

### 15.5 README 要加的一段

```markdown
## 让 AI 读你的账本(可选)

1. 管理页 →「AI 接入」→ 启用只读接口
2. 复制页面给出的配置:
   · 用阿里云百炼 → 粘进「自定义 MCP 服务」
   · 用 Claude Code / Cursor → 粘进本地 mcp 配置(不用公网)
3. 问它:「我的钱都放在哪些平台?」

接口是【只读】的,AI 改不了你的任何数据。
```
