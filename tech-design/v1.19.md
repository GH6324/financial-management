## 已核实的平台事实(写 TDD 时直接用,不必重查)

- **Agent 资源** = 模型 + 系统提示词 + 工具 + MCP 服务 + 技能 的组合配置,创建后按 ID 复用
- **系统提示词可由 API 传入**:REST 字段 `system`,Java SDK `.instructions(...)`
- **创建端点**:`POST https://{workspace_id}.cn-beijing.maas.aliyuncs.com/api/v1/agentstudio/agents`,
  鉴权 `Authorization: Bearer $DASHSCOPE_API_KEY` —— 与我们「数据源接入」页里通义那把**同一把 key**
- **版本语义**:保存即递增 `version`;**会话创建时锁定版本**,之后改 template 不影响已有会话;
  更新是**全量替换 + 乐观锁**(要带当前 version,未提供的字段会被清空);智能体**只能归档不能删除**
- **运行时**:独立沙箱容器,agent 可执行 shell、读写文件、安装依赖;Session 级 **SSE 事件流**,事件历史服务端持久化,支持中断与续接
- **我们现有的三家 LLM** 走的都是 OpenAI 兼容的 `/chat/completions`
  (通义 `dashscope.aliyuncs.com/compatible-mode/v1`),**与 agentstudio 不是同一个 API 家族** ——
  key 能复用,客户端代码不能复用

## 阻塞 TDD 的分水岭(必须先有答案)

**Managed Agents 的 `tools` 支不支持「自定义工具由应用侧执行」?**
(即模型发结构化调用请求 → 我们的服务执行 → 回传结果,类似 `tool_use` / `tool_result`)

阿里云官方文档里我**只确认到 `builtin_toolkit`**(沙箱内 bash / read / write 那一组)。
「应用侧执行」的描述我只在 **Anthropic 的 Managed Agents 资料**里见到,
**没有从阿里云官方页面确认百炼是否同样支持** —— 所以不写进设计,先标成未知。

三条路,TDD 阶段按答案二选一:

| 路 | 前提 | 优点 | 代价 |
|---|---|---|---|
| **A** 应用侧执行工具 | 百炼支持回调 | 不开公网口;NAT 后的自建用户也能用 | **待确认** |
| **B** MCP 服务 | 我们暴露公网 MCP endpoint | 已确认可行(百炼支持自定义 MCP + Bearer) | 自建用户要有公网域名;百炼**无固定出口 IP → 做不了 IP 白名单** |
| **C** 文件挂沙箱 | 把指标快照挂进沙箱 | 不开公网口;沙箱里是 **pandas 在算,不是模型在算** | 快照是**时点**的,对话中途不更新;必须是**算好的指标**而非原始表,否则口径分裂 |

**无论走哪条,工具/数据的定义只写一份**(见 PRD FR-428),换的只是传输方式 ——
所以 PRD 不锁死这一条,TDD 才锁。

## TDD 阶段要给出的选型(现在只列题目,不给答案)

1. **传输方式**:A / B / C 三选一,含未选的「为什么不」
2. **工具层放哪**:新建 `service/ask/` 还是复用 `factview` + `checkup` 的现有服务(倾向后者,但要论证不会引入第三份口径)
3. **SSE 怎么落到 Spring MVC**:`SseEmitter` vs `WebFlux`(本项目是 Spring MVC + Thymeleaf + HTMX,不引入 WebFlux 的理由要写清)
4. **对话存储 schema**:会话表 + 消息表 + 引用块(账期/口径/跳转目标)怎么存,以及**为什么引用块要结构化存而不是存 Markdown**
5. **agent template 的 upsert 时机**:启动时?管理页手动?版本变更时?(百炼是全量替换 + 乐观锁,要处理并发与失败回滚)
6. **失败面**:key 失效 / workspace 取不到 / 沙箱冷启动超时 / session 过期 —— 各自的用户可见行为
7. **护栏怎么设**:至少要有「工具层不提供写操作」「工具层不提供原始表」两条**静态可校验**的判据,
   不能只靠 prompt 和自觉
