## 0 · 一句话概括

**我们只做一件事:一份只读的 OpenAPI。** 其余全部从它派生。

```
只读工具层 ──▶ HTTP MCP ──▶ 百炼 Managed Agents ──▶ 产品内的「问一问」
(唯一要我们写的)              (agent loop 在它那边)      + 用户自己搭的任何 agent
```

**维护者 2026-08-26 定:直接选 B(Managed Agents),没有 A 方案。**

这意味着 **公网 MCP 从「可选」变成「必需」** —— 三个后果,写在前面别让人漏看:

1. **没有公网域名 / HTTPS 的自建用户,用不了「问一问」**(见 §2.3)
2. **安全那一层现在是唯一防线** —— 没有「默认零暴露」这个兜底了(§15)
3. `AgentRuntime` 只剩一个实现;抽象保留,但**理由从「降级路径」变成「接口寿命短于版本节奏」**

**agent loop 我们不写** —— 编排在百炼那边。我们负责的是「开放什么」和「怎么保证数字是对的」。

自由度的来源仍然是 §3:把已有的 `LensQuery` + `PivotEngine` 语义层开放出去 ——
11 维 × 6 度量 × 任意筛选 × 行列交叉,而口径零新增。

## 1 · 一次提问的完整链路

```
用户            我们(Spring Boot)              百炼 runtime            我们的 MCP
 ├─ 提问 ─────▶ │                                  │                       │
 │              ├─ 建 session / 发事件 ──────────▶ │                       │
 │  ◀─ SSE ─────┤ ◀────────── 事件流 ─────────────┤                       │
 │              │                                  ├─ mcp_call: pivot ───▶ │
 │              │                                  │                       ├─ PivotEngine
 │              │                                  │ ◀── 结果 + 引用元数据 ─┤   (透视页同一份)
 │  ◀─ SSE ─────┤ ◀── 正文(数字位置是引用标记)──┤                       │
 │              ├─ 渲染:标记 → 数值 + 账期 + 跳转 │                       │
 │              ├─ 落库(会话/消息/引用/调用摘要)  │                       │
```

**注意倒数第三段**:模型正文里**不写数字**,写引用标记 —— 见 §4,这仍然是本版最关键的一条。

## 2 · 架构选型

### 2.0 · 先说我上一版错在哪(三处实错)

| 我写过 | 实际 | 后果 |
|---|---|---|
| 「Responses API **vs** Managed Agents」二选一 | **不是二选一**。Responses API 的 `tools` 里**可以直接挂 MCP server**(`server_protocol` / `server_label` / `server_url`);Managed Agents 也挂 MCP。**MCP 是两者共同的底座** | 我把决策问错了 —— 真正要决的是「我们开放什么」,不是「用哪个 runtime」 |
| 「选 Responses API 就得**自己写 agent loop**」 | 只在**函数工具**那个变体下成立。挂 remote MCP 的话**编排在百炼那边,我们一行 loop 都不写** | 我用一个不必要的代价把方案劝偏了。维护者那句「我们哪有能力做这个」是对的 |
| 把「要开公网口」当成**纯代价** | 对一个**开源自建**项目,一份文档化的只读 API **本身就是产品能力** —— 程序员用户能拿它接自己的 agent。这是**收益**,不是负债 | 我用它否决了正确的方案 |

**修正后的判断:走 MCP。** 而且 MCP 不只是「喂百炼的管道」,它是**这一版真正的交付物**。

### 2.1 · 核心资产:一份只读 OpenAPI

我们唯一必须自己写的东西。内容就是 §3 那套查询能力,以 HTTP 接口表达:

```
GET  /api/v1/ask/capabilities          自省:维度 / 度量 / 账期 / 账户
POST /api/v1/ask/pivot                 主力查询(rows/cols/measures/filters/period/currency)
GET  /api/v1/ask/period/{p}/summary    一期全貌
GET  /api/v1/ask/period/{p}/accounts   账户级收益表
GET  /api/v1/ask/period/{p}/attribution
GET  /api/v1/ask/checkup
GET  /api/v1/ask/goals
GET  /api/v1/ask/metric/{key}/explain  这个指标怎么算的(与页面 tooltip 同一份文案)
GET  /api/v1/ask/entity?q=             名字 → id
GET  /api/v1/ask/account/{id}/ledger
POST /api/v1/ask/unmet                 「我够不着」的反馈回收
```

**全部只读。没有任何写接口** —— 这是**物理保证**,不是 prompt 约束。

规格用 springdoc 从代码生成(`openapi.json`),**不手写、不会漂**。

### 2.2 · 只有一种消费方式:HTTP MCP

| 形态 | 谁用 | 公网 | 怎么接 |
|---|---|---|---|
| **HTTP MCP**(Streamable HTTP) | 百炼 Managed Agents(产品内对话)· 用户自己搭的 agent | **必需** | 控制台「自定义 MCP → http」,填 url + `Authorization` 头 |

> 上一稿列过的另外两种 —— 「stdio MCP」和「本地函数工具」—— **维护者都砍了**。
> 收敛的好处是**只有一条路要测、要守、要维护**;代价是**没有降级路径**,见 §2.3。

### 2.3 · 选定 Managed Agents,以及它意味着什么

**选它的理由(维护者的)**:要的就是「智能度和灵活程度极高的 agent runtime」——
session 服务端持久化、中断续接、多步工具编排、skill 生态。**agent loop 我们一行不写。**

**它要求的**:百炼要能**回调**我们的 MCP,所以用户的实例必须**公网可达 + HTTPS**。

#### 这条要写进产品文档,不能只写在 TDD 里

| 谁 | 能不能用「问一问」 |
|---|---|
| 有域名 + HTTPS(维护者本人、多数自建 NAS 玩家) | 能 |
| **在 NAT 后面 / 没有域名 / 只在内网跑** | **不能** —— 而且要在页面上**明说是这个原因**,不能只说「去配 key」 |

> 我上一稿留过一条「本地函数工具」的降级路径正是为了这类用户。**维护者砍掉了** ——
> 这是明确的取舍:**换来只维护一条路,代价是一部分自建用户用不了这个功能**。
> 我把它记在这里,是因为将来有人问「为什么内网用不了」时,应当能查到这是**当时的选择**,
> 而不是漏掉的需求。

#### 两个凭据,方向相反,别搞混

```
我们的实例  ──[DashScope API Key]──▶  百炼(建 session / 发事件)      出站
百炼        ──[MCP Bearer Token]──▶  我们的 /mcp                      入站 ← 唯一暴露面
```

出站那把是现成的(数据源接入页里通义那把)。**入站那把是本版新增的,也是全部安全设计的对象**(§15)。

### 2.4 · 两条被查证推翻的假设

| 我上一稿写过 | 实际 |
|---|---|
| 「百炼自定义 MCP 只有 `type` + `url`,**没有 Header 鉴权字段**,所以 token 只能放 URL」 | **支持自定义 Header**(`"headers":{"Authorization":"Bearer ..."}`)。而且 **MCP 规范硬性禁止**在 URI query string 里传 bearer token —— 我上一稿那个方案**违规** |
| (未考虑)OAuth | MCP 规范的标准做法是 **OAuth 2.1 资源服务器**(401 + `WWW-Authenticate` → `/.well-known/oauth-protected-resource` → PKCE + resource indicator)。**但百炼客户端不支持交互式授权流程** —— Claude / ChatGPT 的 remote connector 支持,百炼今天不支持 |

**结论**:走**静态 Bearer(放 Header)**。维护者提的「AK/SK 换短期 token」思路是对的方向,
但**百炼 MCP 客户端做不到那个换取动作** —— 它只会带一个固定头,不会先去换。
所以短期 token 那套只能用在**我们自己是客户端**的地方(即路径 A),对百炼无效。

> `Authorization` header 字段名与写法**需要在控制台实测确认**(文档模板里没写全)。
> 这是第一刀的第一个验证点 —— 如果实测不支持,**退回 §2.3 的 A 方案**,不做公网口。

## 3 · 开放什么 —— 自由度的来源

### 3.1 三种做法,先说为什么不选另外两种

| 做法 | 自由度 | 口径风险 | 结论 |
|---|---|---|---|
| **A · 罐头接口**<br>`getAllocation()` `getTopLosers()` … 一问一函数 | **低**。我们想到什么它才能问什么;用户一问「按平台看、只看老婆名下的、近三个月」就抓瞎 | 零 | ✗ 这是把「固定卡片」换了个壳,没解决 v1.19 要解决的问题 |
| **B · 裸 SQL / 原始表** | **最高** | **最高**。agent 自己 group-by、自己算占比 → **凭空造出第三份口径**,说的数和页面对不上,而用户没法判断谁对(v1.18 整个 bug 家族就是「同一件事两份判据」,已归档 6 次) | ✗ |
| **C · 把语义层开放出去**(选定)<br>`LensQuery` + `PivotEngine` | **接近 B**:11 维 × 6 度量 × 任意筛选 × 行列交叉 | **零**。算的是透视页**同一份代码** | ✓ |

**C 的关键性质:聚合权在我们手里。** agent 说「按平台分组」,是 `PivotEngine` 去分组;
它拿到的已经是分好组、算好占比、带小计的结果 —— **没有算术可做**。
「禁数学」于是不再是限制,而是**不必要**。

### 3.2 主力接口:`POST /api/v1/ask/pivot`

```jsonc
{
  "rows":     ["platform"],            // 行维度,可多个(嵌套)
  "cols":     ["risk"],                // 列维度,可空
  "measures": ["value", "share"],      // 度量白名单
  "filters":  { "owner": ["成员A"] },   // 维度 → 取值
  "period":   "2026-08",               // 缺省 = 当前上下文账期
  "currency": "CNY"
}
```

**维度白名单(11)** —— 前 10 个是 `LensRegistry` 现有的,第 11 个是本版新增派生视图(§8):
`type` · `risk` · `liquidity` · `currency` · `owner` · `assetClass`(穿透后) · `platform` ·
`industry`(穿透后) · `region` · `purpose` · **`custody` 托管形式**

**度量白名单(6)**:`value` · `share` · `latestPnl` · `cumPnl` · `netPrincipal` · `openValue`

> `PivotEngine.Result` 已带 `rowTotals` / `colTotals` / `grand` / `holdingLevelSplit`,**直接透传**。
> `holdingLevelSplit` 尤其重要:它标记「本次查询含持仓级维度,收益按持有口径、**不可归因**」——
> 必须**原样交给 agent**,否则它会拿一个不可归因的数去下结论。

### 3.3 三个专为「自由度」设计的东西

**① `/capabilities` 自省接口 —— 不让它猜。**
agent 最大的浪费是猜参数:猜维度叫什么、猜账期格式、猜账户名。
所以第一等公民是自省:维度、每维的取值、可用账期、账户列表,**一次问清**。
MCP 的 tool description 里明写:**拿不准就先调它,不要猜。**

**② 参数填错不报错,把校验信息回给它让它改。**
返回 `422` + 结构化的「你可以用的取值是这些」。允许试错,这本身就是自由度。

**③ `/unmet` —— 够不着时诚实说 + 记下来。**
agent 发现「用户问的我没有对应能力」时调它,然后**如实告诉用户拿不到**。
我们把它记进 `ask_unmet_need` —— **agent 的「够不着」变成下一版加接口的产品输入**,
比我们坐着猜用户要什么准得多。

> 这也是对「自由度」的诚实回答:**边界总会有**,重要的是它**可见、可反馈、会移动**,
> 而不是让 agent 在边界上编一个答案。

### 3.4 接口层不许做什么

```
web/ask/api/     只做三件:参数校验 → 调现有 service → 包上口径元数据
                 一行计算都不写
```

每个响应**必须**带 `periodId` · `metricKey` · `inProgress` · `currency` ——
这四样是 §4 引用块的原料,也是「数字说得清自己是哪一期」的载体。

## 4 · 数字保真:**模型不写数字,只写引用标记**

### 4.1 问题

FR-427 要求每个数字挂账期、点得回原页、与页面**逐字一致**。
如果让模型把 `+¥204,522` 打进正文,有三种翻车方式:少一位、改成「约 20 万」、把 7 月说成 8 月。
**靠 prompt 约束这件事我们已经证明过不可靠** —— 那条「禁止四则运算」的铁律是拿生产事故换来的。

### 4.2 做法

工具结果落进**本轮引用表**,每个可引用数字有一个 id;模型正文写标记:

```
你 8 月净资产涨了 {{cite:c1}},其中投资那份 {{cite:c3}} 占了大头。
```

渲染时替换成引用块组件,数值**直接取自工具结果**:

```
净资产变化 ΔNW      +¥222,522
2026-08 · 进行中   → 仪表盘 · 本期怎么变的
```

### 4.3 为什么这是结构性的,而不是约定性的

- 模型**没有机会**打错数字 —— 它手里根本没有数字字符串,只有 id
- 账期 / 口径名 / 跳转目标由**工具结果**决定,不由模型决定
- 渲染时口径文案与页面**共用一份**(`MetricExplainService`);页面改口径,历史对话跟着改

**兜底**:模型仍可能在正文里手打数字(比如复述)。所以加一道**输出校验** ——
扫正文里的金额 / 百分比形态,**凡不在本轮引用表里的,标灰并加一句「这个数我没核对过」**。
不删(删了句子会断),但**明确降级**。

> 复用现有 `OutputValidator` 的思路:v0.4 起我们就在扫 LLM 输出(那时扫「有没有泄露真名 / 荐产品」),
> 现在多扫一类「有没有凭空出现的数字」。

## 5 · 分层:哪一层允许知道「我们在用百炼」

```
web/ask/api/AskApiController      只读 OpenAPI(springdoc 生成规格)  ← 对外的唯一真相
web/ask/mcp/McpEndpoint           把 OpenAPI 包成 Streamable HTTP MCP(仅在显式开启时挂载)
   ↕ 共用
service/ask/AskToolRegistry       工具注册表 · 参数校验 · 口径元数据
   ↑
service/ask/AskConversation       产品内对话编排 · 引用表 · 本地存储   ← 不知道百炼存在
   ↓
service/ask/AgentRuntime          接口:send(消息, 事件回调)
   └ ManagedAgentRuntime          唯一实现 · 百炼 Managed Agents + 我们的 HTTP MCP
```

**两条线**:

- **对外线**(OpenAPI → MCP):给百炼、给程序员自己的 agent。**这是本版的主交付物**
- **对内线**(AskConversation → AgentRuntime):产品内的「问一问」,给非技术用户

两条线**共用 `AskToolRegistry`** —— 工具只实现一次。

**只有一个实现,为什么还要这层接口**:诚实说,**它现在是投机性的**。
留着的唯一理由是 Assistant API 三个月前还是官方推荐、现在已「下线中」——
**这一领域的接口寿命明显短于我们的版本节奏**,而业务层里有工具分发与口径引用,
那是最不该被供应商变更牵动的部分。
如果评审觉得这属于过度设计,**可以拿掉**,代价是将来换接口要动 `AskConversation`。

## 6 · 多轮上下文:主用云端,自己留一份

| 方案 | 取舍 |
|---|---|
| **A · 全靠 `previous_response_id`** | 最省。但有已知时序坑;云端过期 / 换账号后**无法续接** |
| **B · 每轮自拼完整 `input`** | 最可控,但 token 随轮次线性涨,且放弃服务端上下文缓存 |
| **C · 主用 A + 本地全量 + 失败退 B**(选定) | 正常走 `previous_response_id`;一旦报 `No tool output found` 或 id 失效,**用本地历史重拼 input 重试一次** |

**选 C**,理由不是折中:PRD FR-431 本来就要求**本地存全量**,所以「重拼所需的历史」是**免费**的。
既然有,就不该在云端失效时干瞪眼。另开 `x-dashscope-session-cache: enable` 降低多轮延迟与成本。

**新对话**(FR-431b)= 新的 `previous_response_id` 链;旧链自然失效,不用清理。

## 7 · 系统提示词的结构

放仓库 `resources/prompts/ask-system.md`,**随版本走**,不进控制台。五段:

1. **角色与边界** —— 家庭资产顾问;不预测涨跌、不荐具体产品、不做担保性话术(**与现有六处 AI 共用这一段**,避免边界在两处漂移)
2. **数字纪律** —— 你**不写数字**,只写 `{{cite:id}}`(§4)
3. **怎么用工具** —— 拿不准先 `describeCapabilities`;一轮最多 8 次;够不着就 `reportUnmetNeed` 并如实说
4. **什么时候先反问**(FR-425)—— 凡结论会因一个未知条件**翻转**的问题,先问再答。给正反例:
   「该不该提前还贷」要问现金用途;「我房产占比多少」不需要问
5. **答完给 2–3 条追问**(FR-424b)—— 贴着刚才那段答案,不是一屏

## 8 ·「托管形式」:派生维度

| 方案 | 取舍 |
|---|---|
| **A · 新增维度(需打标)** | 与现有维度一致。但要用户**逐个账户打标** —— 违背 10 分钟硬约束 |
| **B · 派生**(选定) | 由已有字段推导,**零新增录入**。代价:规则由我们定 |

| 托管形式 | 规则(全部来自已有字段) |
|---|---|
| **自己盯** | `STOCK` / `CRYPTO` / `METAL`,你自己建的标的 |
| **交给产品** | `WEALTH` / 基金类;有穿透结果的走**穿透后成分** |
| **不动** | `PROPERTY` / `INSURANCE` |
| **随时可取** | `CASH` + 标了 `LIQUID` 的货基类 |

**落点**:在 `LensQueryService.positions()` 组装 `Position` 时**多填一个 `custody` 标签**,
其余完全复用 —— 于是它自动获得透视引擎的全部能力(能当行、能当列、能筛选、能交叉),
**而且透视页也白捡一个新维度**。

> 配**结构性单测**遍历 `AccountType`,要求每个类型落进四类之一或显式列入 `NEITHER` ——
> 照抄 `AccountTypeSemanticsTest`,那条正是为「v0.14 加 METAL 漏了投资类判据」立的。

## 9 · 外壳与 SSE

### 9.1 两种壳,一个流

| | PC(≥1024) | 移动 |
|---|---|---|
| 入口 | 右下角**常驻悬浮按钮** | 导航**顶级入口** |
| 壳 | **可拉宽侧边抽屉** | **全屏页** +「← 回到刚才那页」 |
| 实现 | 同一个 `ask/_stream` 片段,两个外层模板 | 同上 |

**PC 必须是侧栏**:本版最重的承诺是「数字点得回原页」,侧栏能左边看数右边问话;
独立页每点一次引用块都要跳走再跳回。

### 9.2 跨页面保持

| 方案 | 取舍 |
|---|---|
| **A · 整页刷新重建** | 简单,但**对话会断** —— 直接违背要求 |
| **B · 导航改 HTMX 局部替换**(选定) | 与项目现有做法一致(趋势 / 支出构成早就是局部替换)。抽屉挂 layout 上,主体换它不换 |
| **C · 引入 SPA 路由** | 能做到,但给 Thymeleaf 项目引前端路由,收益与成本不成比例 |

> **风险**:B 触到**每一个页面**。所以单列为第二刀,第一刀先做「当前页可用」。

### 9.3 SSE

Spring MVC 原生 `SseEmitter` + **独立线程池**(不引 WebFlux —— 只有一个流式端点,
引一套新范式不划算)。池子有上限,满了直接拒绝并给人话提示,**不排队、不拖垮主池**。
移动端全屏页跳走时**必须主动关 emitter**,否则线程挂到超时。

### 9.4 滚动(FR-431d)

流式时滚动停在**新消息顶部**,不追最后一个字。实现用
「stick to bottom only if already at bottom」:用户已在底部才跟随。

理由:追着滚会让人**读不了正在生成的内容**;而我们的答案里有引用块,滚到底会让最重要的数字一闪而过。

## 15 · 安全设计(公网 MCP 开启后)

> 维护者 2026-08-26:「我没有看到安全相关的设计?**你认真点,这可是用户资产数据**」。
> 上一稿我只写了七条要求就交差了 —— 那不是设计。这一节重写。

### 15.1 威胁模型:到底在防谁

| 资产 | 家庭全部资产数据(余额 / 持仓 / 净资产 / 收支)· **只读,改不了** |
|---|---|
| **攻击面** | 一个挂在用户自己域名上的 HTTPS 端点 |
| **攻击者能力** | ① 全网扫描找端点 ② 从日志 / 截图 / 聊天记录里捡到凭据 ③ 重放 ④ 猜路径探测 |
| **我们拿不到的防御** | **IP 白名单** —— 百炼的 MCP 跑在函数计算上,**没有固定出口 IP** |
| **必须承认的信任** | 凭据一旦贴进百炼,就是**信任阿里云**保管它。这一点没法回避,只能让用户知情 |

### 15.2 第一道:没有有效凭据,一律 404

选了 B 之后,**「默认零暴露」这个兜底没有了** —— 想用「问一问」,这个口就必须开。
所以第一道防线从「默认不开」变成**「开着也让扫描者看不出来」**:

| 情形 | 返回 |
|---|---|
| 用户没启用 AI 接入 | **404** |
| 启用了,但请求没带凭据 / 凭据错 / 已过期 / 已吊销 | **404**(不是 401) |
| 凭据有效但 scope 不够 | **403** + 说明缺哪个 scope |

**为什么错凭据也返 404**:`401` 等于告诉扫描者「这里有东西,只是你没凭据」,
而这个端点背后是一个家庭的全部资产。MCP 客户端本该靠 `401` + `WWW-Authenticate` 发现鉴权 ——
但**百炼本来就不走那个流程**(§2.4),所以我们不损失任何东西。

配套:**认证失败计数** —— 同一来源 IP 连续失败 N 次 → 临时封禁 + 记审计。
暴露到公网就一定会被扫,这条不是可选项。

### 15.3 凭据:为什么不是 AK/SK 换短期 token

维护者问的方向是对的 —— 那是标准做法(AK/SK → 换 access_token → 短 TTL → refresh)。
**但百炼的 MCP 客户端做不到那个换取动作**:它只会带一个**固定的 header**,不会先去调换取接口,
也不支持 MCP 规范里的 OAuth 交互式流程(401 → 元数据发现 → PKCE 授权)。

所以只能是**静态 Bearer**。既然静态,就必须靠**其它维度**把风险压下来:

| 维度 | 做法 | 防的是什么 |
|---|---|---|
| **不放 URL** | 走 `Authorization: Bearer`(**MCP 规范硬性禁止**放 query string) | token 进访问日志 / Referer / 浏览器历史 |
| **一接入点一把** | 每加一个接入方(「百炼-我的智能体」)发一把独立 token | 泄露一把 ≠ 全线失守;能定位是哪一把出的事 |
| **只存 hash** | 库里存 `argon2(token)`,**明文只在生成那一刻显示一次** | 拖库 → 拿不到可用凭据 |
| **有效期** | 默认 **90 天**,到期自动失效,页面提前提醒 | 遗忘的长期凭据 |
| **scope 两档** | `aggregate`(只给聚合与占比,**默认**)/ `detail`(含账户名与流水) | 数据最小化 —— 大多数问题聚合就够答 |
| **限流** | 每 token:60 次/分、2000 次/天,超了 `429` | 拖库式批量抓取 |
| **异常熔断** | 调用量突增 / 大量 404 路径探测 / 非常规 UA → **自动禁用该 token + 通知** | 凭据已泄露但用户不知道 |
| **审计** | 每次调用记 接口 / 时间 / 来源 IP / UA / 耗时 / 结果,**不记返回体** | 事后能查「谁在什么时候读了什么」 |
| **通知** | token **首次被使用**、被吊销、被熔断 → 站内 +(可选)微信 | 第一次异常使用就能被发现 |
| **一键吊销** | 管理页点一下,旧 token 立刻失效 | 怀疑泄露时的止血 |
| **日志脱敏** | `Authorization` 头**不进任何日志**(nginx + 应用)· 进护栏 | 日志变成凭据仓库 |
| **真名脱敏** | **复用现有机制**:成员真名 → 代号(与现有六处 AI 一致) | 即使数据被读走,**读不到「谁」** |
| **只读是物理的** | 这批接口**没有写方法**;护栏 `v119-API-READONLY` 静态扫 | prompt 注入也改不了数据 |
| **可选 IP 白名单** | 百炼没有固定出口 IP,但**用户自己的 agent 有** —— 给用得上的人 | 有条件时的额外一层 |

### 15.4 凭据生命周期

```
生成   管理页「AI 接入」→ 新增接入点(填名字 / 选 scope / 选有效期)
       → 服务端生成 32 字节随机 → 明文【只显示这一次】 → 库里只留 argon2 hash

使用   Authorization: Bearer <token>
       → 查 hash → 校验 未过期 / 未吊销 / scope 够 → 限流 → 记审计

吊销   一键删除接入点 → 立刻 404

过期   到期自动失效 · 到期前 7 天页面提醒 · 过期后调用返回 401 且审计记一笔
```

## 16 · 端到端:凭据怎么生成、用户到底要点几下

> 维护者 2026-08-27:「**还是没看懂你的设计**」。前面几节都在写取舍,没写**流程**。这一节补。

### 17.1 决定性的两条查证结果

| | **Managed Agents** | **Responses API** |
|---|---|---|
| 怎么挂 MCP | `mcp_servers: [{type, name}]` —— **只是对「已注册服务」的引用**,不含 url / headers | `tools: [{type:"mcp", server_url, headers:{...}}]` —— **内联** |
| 注册自定义 MCP | **没有公开 API**。三条路都是人工:控制台 / AI 网关 / 函数计算 | **不用注册** |
| 鉴权头 | 注册那一刻填(**支持性待实测**) | **明确在 `headers` 里传** |
| **能不能一键** | **不能** —— 用户必须去百炼控制台**手动注册一次 MCP**,拿到服务 ID 回填我们这边 | **能** —— 我们代码里直接传,用户零操作 |

**这直接撞上维护者的诉求**:「我们能一键自己完成?比如用户点击一键部署 MA,我们自动导出 skill/token?」
—— **走 MA 做不到一键**,卡在「注册自定义 MCP 服务没有 API」这一步。

### 17.2 Token:生成 / 存储 / 校验 / 时效(完整逻辑)

#### 生成

```
触发   管理页「AI 接入」→ 新增接入点
输入   名字(如「百炼-家庭助手」)· scope(aggregate | detail)· 有效期(30 / 90 / 365 天)

生成   raw = SecureRandom(32 字节)
       token = "fmk_" + base64url(raw)            ← 43 字符 + 4 前缀
       
存库   token_hash   = argon2id(token)             ← 只存这个
       token_prefix = token 前 12 字符             ← 明文,仅用于定位与展示
       scope · expires_at · created_at · last_used_at · revoked_at · name

返回   明文【只在这一次响应里出现】
页面   显示 + 复制按钮 + 必须勾「我已保存」才能关闭;此后任何地方都取不回
```

**为什么带 `fmk_` 前缀**:① 万一被贴进公开仓库,GitHub 的 secret scanning 能按前缀识别;
② 审计页显示 `fmk_a1b2c3d4…` 就能定位是哪一把出的事,**而不必存明文**。

#### 校验(每次请求)

```
Authorization: Bearer fmk_xxx
  → 按 token_prefix 命中候选行(有索引,不必全表 argon2)
  → argon2 verify —— 不匹配:404
  → revoked_at 非空:404      expires_at 已过:404
  → scope 不足:403 + 说明缺哪个
  → 限流(60/分 · 2000/天)—— 超:429
  → 记审计 · 异步更新 last_used_at(节流 60 秒,不每次写库)
```

> 「不匹配 / 已吊销 / 已过期」全部返 **404 而不是 401** —— 理由见 §15.2。

#### 时效与轮换

| | |
|---|---|
| 到期 | `expires_at = now + 选定天数`。**到期前 7 天**管理页出黄条 +(可选)微信提醒 |
| 到期后 | 调用返 404,审计记 `EXPIRED`(区别于 `INVALID`,便于用户看懂是「过期了」不是「填错了」) |
| **轮换** | 生成新的 → 旧的进入 **24 小时 grace**(仍可用,但每次调用在审计里标 `USING_ROTATED`,管理页红条催)→ 24 小时后自动失效 |
| 为什么要 grace | 轮换那一刻百炼那边配置还是旧的。**没有 grace 就是每次轮换必然断一次服务** —— 那会让人干脆不轮换 |
| 立即吊销 | 「立刻失效」按钮跳过 grace(怀疑泄露时用) |

### 17.3 用户完整步骤 —— 走 Managed Agents(**6 步,含一次控制台操作**)

```
① 我们这边   管理页「AI 接入」→ 新增接入点 → 复制【口令】与【配置 JSON】
                ↓
② 百炼控制台  MCP 管理 → 创建自定义 MCP → 安装方式 http → 粘 JSON → 保存
                ↓                                    ← 【这一步没有 API,必须人工】
③ 百炼控制台  在服务卡片上复制【服务 ID】
                ↓
④ 我们这边   把服务 ID 粘回管理页 → 点「完成接入」
                ↓
⑤ 我们自动   POST /agents(system 提示词 + mcp_servers:[{type:"customer", name:服务ID}]
              + tools:[{type:"mcp_toolkit", mcp_server_name:服务ID}])→ 存下 agent_id
                ↓
⑥ 用户提问   我们 POST /sessions → POST /sessions/{id}/events(Accept: text/event-stream)
              → 百炼回调我们的 /mcp 取数 → SSE 事件流回来 → 渲染
```

**用户真正要动手的是 ②③④** —— 两次复制粘贴,一次去百炼控制台。
⑤⑥ 全自动。**这已经是 MA 路线能做到的最简了**,再简化不了(卡在注册没 API)。

### 17.4 用户完整步骤 —— 走 Responses API 内联 MCP(**2 步,全自动**)

```
① 我们这边   管理页「AI 接入」→ 点「启用」→ 我们自己生成口令,【不显示给用户】
                ↓                              (因为没人需要手动粘它)
② 用户提问   我们 POST /compatible-mode/v1/responses
              tools:[{ type:"mcp",
                       server_url:"https://用户域名/mcp",
                       headers:{ Authorization:"Bearer <我们刚生成的口令>" } }]
              → 百炼回调我们的 /mcp 取数 → SSE 流回来 → 渲染
```

**用户点一下「启用」,完。** 没有控制台、没有复制粘贴、没有服务 ID。

> 口令仍然生成、仍然入库、仍然可轮换可吊销可审计 —— 只是**不需要人去搬运它**,
> 所以泄露面小一截(不会经过剪贴板、截图、聊天记录)。
