选 deepseek 就会去 api.deepseek.com, 拿的是 DeepSeek 官方的 key,不是方舟的。

旧配置怎么搬过来
issue #14 第 3 问 · 硬要求:一把 key 都不用重填
升级前升级后你会看到

llm_model = auto		 → 阿里云百炼 · 通义千问 · 自动(仍是多型号轮询)

llm_vision_model = off → 截图导入开关 = 关
llm_temperature / max_tokens / timeout → 不变,仍是全局调用参数
线上红线
prod 已经在跑,所以迁移只能是「补写新键」:旧键不删、不改写语义,迁移可重入(跑两次结果一样), 并且 降级回上一版 jar 仍然能正常工作。这三条会做成机器可验的用例,不靠肉眼。

顺手收掉的旧账:模型清单散在四处
加一个平台要同时改四处,漏一处就出诡异行为
现在
QwenLlmClient.DEFAULT_MODELS
IntegrationsController.normalizeLlmModel
integrations.html · JS LLM_MODELS
同页视觉下拉的三个 <option>
这四处已经事实上不一致:前端清单里有 auto,DEFAULT_MODELS 里没有; 视觉那三项谁都不知道该归谁管。
这一版之后
收敛成一份目录:平台 → 系列 → 推荐型号。
前端级联、服务端校验、客户端默认值都从它读。
加平台 = 改一处。
再加一条 qa-run 护栏:前端能选到的型号 ⊆ 服务端白名单,四处清单再分叉就红。
5
这几件我没替你定
都是产品决定,不是技术难点
① failover 的单位是什么?
现在是「哪家挂了切另一家」。三级之后我建议改成主/备各是一个完整三元组 —— 因为「主选火山方舟」在方舟挂着好几个系列时说不清。代价:配置页多一组字段。
② 同一系列出现在多个平台,都允许吗?
DeepSeek 官方 vs 方舟上的 DeepSeek。我认为要允许,这正是拆三级换来的东西。 代价:UI 上会有两个看着一样的「DeepSeek」,靠平台名区分。
③ 百炼那套「轮询摊免费额度」留不留?
我倾向留(实实在在省钱),代价是百炼比另外两家多一块专属配置,三个平台不齐整。 也可以借这版砍掉、统一成「选定一个型号」。
④ 型号手填,放开给所有平台?
我倾向放开(上面已按放开画)。反面是填错一个字符串,失败信息来自对方接口、不那么好懂。
另外一件值得先知道的事:方舟申请 key 要实名认证。对「自部署给家里人用」的读者,这是一道真实的坎, 会写进 docs/llm-api-keys-setup.md。
