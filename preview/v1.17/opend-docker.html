它是一个可选组件:只有用富途的人才需要。你的这套部署现在没有它 —— 没有多占磁盘、没有多跑进程。 要用富途,请先看清下面三段,再决定要不要启用。

02 / 镜像里没有富途文件
我们不转发别人的软件
镜像里只有三个 shell 脚本(下载校验 / 启动 / 控制循环),你可以逐行读完。 OpenD 是容器第一次启动时从富途官网下载的, 我们既不打包也不转存。构建流水线里有一道检查,一旦镜像里出现富途文件就直接构建失败。
构建期已校验 · 层内无富途制品
03 / 官方安装包的哈希
下载完先验,再启动
富途官方不公布任何校验和。下面这两个值是我们下载后自己算的, 钉在公开仓库里(有 git 历史可查)。装的时候现算一次,不一致就拒绝启动。
OpenD 10.10.7008 · 445,000,000 字节 sha256 1b0e…9f42 md5 4297cdec5653565556802fcd1b148f05
请你自己也验一遍 —— 这是一个能操作你券商账户的组件,值得多花两分钟。 三条命令,任何一条对不上就不要继续,来仓库开个 issue:
# 1) 我们的镜像:按 digest 拉(不认 tag),并验签与构建来源 docker pull ghcr.io/…/futu-opend-launcher@sha256:3f9c…a71d gh attestation verify --repo … oci://ghcr.io/…@sha256:3f9c…a71d # 2) 镜像里确实没有富途文件 docker run --rm --entrypoint ls ghcr.io/…@sha256:3f9c…a71d /opt # 3) 官方包的 MD5:CDN 响应头里的 etag 就是文件 MD5(实测) curl -sI "https://softwaredownload.futunn.com/Futu_OpenD_10.10.7008_Ubuntu18.04.tar.gz" | grep -i etag etag: "4297cdec5653565556802fcd1b148f05" # ← 和上面第 03 段对上
要说清这条的极限:etag 和安装包走的是同一条连接、同一个 CDN, 它证明的是"传输没坏",不是独立第三方担保。真正有意义的是三方对上:你自己算的、我们仓库里钉的、CDN 给的。
看完了,启用它
复制这条命令在服务器上跑一次(镜像很小,里面只有三个 shell 脚本):
docker compose --profile futu up -d
用 docker-up.sh 起的:改成 ./docker-up.sh --with-futu 即可,profile 不用自己记。
不想启用?两条别的路
换成自己的镜像 不信我们构建的,.env 里设 FUTU_OPEND_IMAGE 指向你自己的,其余流程不变
OpenD 在别处 家里 NAS / 另一台机器上已经跑着 OpenD,直接填地址(见第 5 区)

坏在哪现在的行为改成
下载域名过期 写死 softwarefile.futunn.com,该域名 443 已经连不上(实测超时) 改用官方现行下载域名;白名单同步放开,否则用户手填官方地址会被我们自己拒

依赖提示是错的 教用户 apt install libgtk-3-0 fuse —— 这俩是桌面版的依赖,且在 Ubuntu 24.04+ 已改名,命令必然失败 不再无条件教装;真缺库时按实际缺的那个提示
启动参数已废弃 用命令行传密码(-login_pwd_md5)和 telnet 端口 —— 10.10 都不再支持,改成了交互式登录 按 10.10 的方式:起进程 + 交互喂凭据 + 读它自己的日志判断状态

对照:老虎为什么没有这个问题
你问的那条 —— 「部署方式不同导致体验不一致」是不是也发生在老虎身上
项富途(今天)老虎
怎么连券商本地常驻一个网关进程 OpenD,应用连它的 11111 官方 SDK 直连 HTTPS(TigerHttpClient),没有任何本地进程
要装东西吗要:445MB 安装包 + 家目录 + 端口不要
凭据在哪Docker 下今天在 .env 明文(这一版改到管理页) 管理页填、存库(tiger_id / RSA 私钥 / 账户号)
按部署方式分叉有:FutuOpendManager 7 处 + 向导页 10 处 channel != 'DOCKER' 零处。broker/link.html 里一处都没有
结论Docker 与原生今天是两套体验 —— 这一版要收敛掉 Docker 与原生完全一致,结构上也不会出现这个问题
换句话说:这个毛病的根源是「富途要一个本地网关」,不是「我们的 Docker 支持不好」。 全仓库按部署方式分叉的地方只有 OpenD 这一处,收拾完就没有第二处了。

项问题我的建议
最新版 「自动装最新版」和「哈希已被我们核对过」是冲突的:富途发了新版、我们还没核对时怎么办 默认只装已核对版本;想尝鲜要用户显式勾一下,页面把实算的 sha256/md5 摆出来由他判断。 代价:富途发新版后到我们跟上之间,默认路径装的是旧版(能用,但不是最新)
凭据加密 富途密码这一版存库但不加密(和老虎的 RSA 私钥今天一样是明文存库) 建议这一版不做:只给富途加密会造成「看起来加密了」的错觉,账户风险面没变。 凭据加密单独一版、两家一起做、连 audit_log 一起过。这一版只保证:不落 .env · 不进日志 · 不进 AI prompt。
(原来这一格问的「无鉴权控制口怎么办」已在 TDD 里定了:telnet 只绑容器内 127.0.0.1、根本不出容器,11111 上 RSA)
