这一版顺手修掉的「现状即坏」
下面四条今天在 原生 路径上也是坏的 —— 不修,原生的一键也按不动
坏在哪现在的行为改成
下载域名过期 写死 softwarefile.futunn.com,该域名 443 已经连不上(实测超时) 改用官方现行下载域名;白名单同步放开,否则用户手填官方地址会被我们自己拒
文件名 / 系统标识过期 拼 FutuOpenD_<版本>_Ubuntu16.04.tar.gz,官方现在只发 Ubuntu18.04 / Centos7 按官方现行命名;并向官方端点问最新版,用户不再手填版本号(现在的输入框默认写着 9.3.5308)
依赖提示是错的 教用户 apt install libgtk-3-0 fuse —— 这俩是桌面版的依赖,且在 Ubuntu 24.04+ 已改名,命令必然失败 不再无条件教装;真缺库时按实际缺的那个提示
启动参数已废弃 用命令行传密码(-login_pwd_md5)和 telnet 端口 —— 10.10 都不再支持,改成了交互式登录 按 10.10 的方式:起进程 + 交互喂凭据 + 读它自己的日志判断状态

项问题我的建议
A/B/C Docker 下 OpenD 谁来跑:A 应用容器自己跑(本页画的)· B 我们自己发一个 launcher 镜像到 GHCR · C 默认指向社区镜像 A。它就是把原生那条路直接给 Docker 用,零新构件、零端口暴露;B 要长期维护一个镜像并在内网开一个无鉴权控制口,C 等于把券商账户交给陌生镜像
凭据 .env 里的 FUTU_ACCOUNT / FUTU_PWD_MD5 怎么处置 降级为可选、文档删掉 md5sum 教程;已经写了的人升级后不报错。理由是项目既有原则:运营参数走管理页
问卷 富途首次问卷 / 协议到底在哪做 —— 向导页说牛牛 App,sidecar 教程说必须桌面版 OpenD 登录一次,两句话冲突,我目前没有确凿答案 TDD 前用真实账号走一遍,把结论写死进文档;这条不问清,第 1 步的文案就还是会骗人
