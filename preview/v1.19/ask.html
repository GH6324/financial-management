分 水 岭 已 查 清 · 选 型 改 了

原来挂着的问题是「百炼 Managed Agents 支不支持应用侧执行工具」。查完三个接口,答案是 不支持,而且我们本来就不该用它。

候选工具在哪执行结论
Managed Agents 平台侧沙箱。客户端只能写 message 事件 数据要进去只有两条:开公网 MCP 口,或把家底写进云端沙箱文件。 而它的强项(代码执行 / 文件处理 / 长时任务)我们一个都用不上
Assistant API 客户端 官方标注「下线中」,全站提示迁移。不能往上建
Responses API ✓ 客户端:模型返回 tool_call → 我们执行 → 回传 function_call_output 官方推荐方向。端点 /compatible-mode/v1/responses —— 与我们现有通义客户端同一个 base、同一把 key

选它的三条理由:① 工具在我们进程里跑,暴露面和现在六个 AI 调用点完全一样,不新增; ② 不开公网口 —— 这个产品发 Docker 给陌生人自建,很多人在 NAT 后面没有域名, 而百炼的 MCP 没有固定出口 IP、做不了白名单; ③ 没有云端资源要管 —— instructions + tools 随请求发, 原方案里「建 Agent / 全量替换 + 乐观锁 / 只能归档不能删」整块消失。

代价照实说:多轮交给 previous_response_id,社区反馈它与 function_call_output 配合有时序问题 → 我们本地始终存全量(PRD 本来就要求), 云端失效时用本地历史重拼重试一次。

5b自由度从哪来 —— 把透视引擎整个交给它 TDD §3
「更高自由度」的答案不是让它碰原始数据,是复用我们已经有的语义层。

资产透视页背后是 LensQuery(rows, cols, measures, filters) + PivotEngine —— 这本来就是一个语义层。把它当成 agent 的主查询接口,一步到位: 11 个维度 × 6 个度量 × 任意筛选 × 行列交叉,而算的是透视页同一份代码。
关键性质:聚合权在我们手里 —— agent 说「按平台分组」,是 PivotEngine 去分组; 它拿到的已经是分好组、算好占比、带小计的结果,一次加法都不用做。 「禁数学」于是不再是限制,而是不必要。

用户随口问的落成一次 pivot 调用
我的钱都放在哪些平台?rows=[platform] measures=[value,share]
老婆名下的钱,按风险分一下rows=[risk] filters={owner:[成员B]}
穿透之后我到底有多少股票?rows=[assetClass] measures=[value,share]
各平台里各类风险各占多少?rows=[platform] cols=[risk](行列交叉)
哪些是我自己盯,哪些交给产品了?rows=[custody](本版新增的派生维度)
我外币敞口在哪几个账户?rows=[currency,platform] filters={currency:[USD,HKD]}

这六条是随手举的 —— 组合空间远不止。而罐头接口(getAllocation() 这种) 只能答我们提前想到的那几条,用户一问「按平台看、只看老婆名下的」就抓瞎。

还给了三件事,专为自由度
  • 自省接口 describeCapabilities —— 维度、取值、账期、账户全告诉它, 不让它猜参数(猜参数是 agent 最大的浪费)
  • 参数填错不报错,把校验信息回给它让它改 —— 允许它试错
  • 够不着时 reportUnmetNeed —— 如实告诉用户拿不到, 同时记一笔;agent 的「够不着」变成下一版加工具的输入
仍然不给的

任意 SQL / 原始表行 / 任何写操作。

不是保守 —— 是 agent 自己 group-by、自己算占比就等于凭空造出第三份口径, 它说的数会和页面对不上,而用户没法判断谁对。 v1.18 整个 bug 家族就是「同一件事两份判据」,已归档 6 次。

边界总会有 —— 重要的是它可见、可反馈、会移动, 而不是让 agent 在边界上编一个答案。

另 一 条 · 模 型 不 写 数 字

我认为这是本版最重要的设计:模型正文里写引用标记不写数字 ——

你 8 月净资产涨了 {{cite:c1}},其中投资那份 {{cite:c3}} 占了大头。

兜底:它仍可能手打一个数字复述 —— 那就扫正文,不在引用表里的标灰 并注「这个数我没核对过」。不删句子,但明确降级。

生成  SecureRandom(32B) → "fmk_" + base64url → 明文只出现这一次
存库  argon2id(token)  +  token_prefix(前 12 位明文,仅用于定位)  +  scope · expires_at
校验  前缀命中候选行 → argon2 verify → 未吊销 / 未过期 → scope 够 → 限流 → 记审计
过期  到期前 7 天提醒;到期后返回 404,审计记 EXPIRED(区别于 INVALID)
轮换  新口令生效,旧的进入 24 小时 grace → 期间可用但审计标 USING_ROTATED + 页面红条催
吊销 「立刻失效」跳过 grace(怀疑泄露时用)
为 什 么 带 fmk_ 前 缀

① 万一被贴进公开仓库,GitHub 的 secret scanning 能按前缀识别并告警
② 审计页显示 fmk_a1b2c3d4… 就能定位是哪一把出的事, 而不必在库里存明文

为 什 么 轮 换 要 留 2 4 小 时

轮换那一刻,百炼那边的配置还是旧的。没有 grace 就是每次轮换必然断一次服务 —— 那会让人干脆不轮换,反而更不安全。
怀疑泄露时另有「立刻失效」,跳过 grace。
